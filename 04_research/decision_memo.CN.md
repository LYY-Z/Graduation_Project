# 选题决策备忘（第 2 版）

日期：2026-11-25。状态：**已经过三份 Opus 审核修订，待用户与老师确认**。审核原文：[PACE 原文核对](review_opus/pace_audit.CN.md) · [最接近工作全文核对](review_opus/closest_works_audit.CN.md) · [最终查重与审稿意见](review_opus/final_review.CN.md)。实机条件见 [实机实验条件](../05_experiments/lab_requirements.CN.md)。

## 1. 结论

**题目方向**：轮足机器人 Go2-W 的仿真—真机差距归因与分阶段对齐。

**基础论文**：PACE（Bjelonic 等，IJRR 2026 在线发表）。在 Go2-W 上复现它的"悬空执行器辨识"（12 个腿电机 + 4 个轮电机）。

**研究问题**：PACE 作者主张"悬空数据足以用于有接触的任务"（论文 p20 §5）。这个主张在**轮子**上是否成立？如果不成立，着地后还剩哪些差距、怎样用少量物理参数补上？

**创新点**：
1. **差距归因**：按通道（12 腿 / 4 轮）、按状态（悬空 / 着地）量化 Go2-W 的仿真—真机差距，回答"差距在哪里"。
2. **分阶段对齐**：悬空辨识电机参数；着地后只用 4–8 个有物理含义的轮—地接触参数补剩余差距（滚动阻力、与负载有关的阻力、有效轮半径或滑移）。训练端不需要动捕。
3. **受控比较**：同一平台、同一数据预算下，比较默认、只辨识、只补接触、两步结合，以及调过的域随机化等强基线。

**审核结论**：有条件批准（[终审 §2.6](review_opus/final_review.CN.md)）。作为本科毕设方向真实、平台可得、有完整退路；作为顶会论文当前新意不足。

## 2. 为什么是这个问题

- Go2-W 是常见的商用轮足平台，社区有实机抖动（rl_sar#178）、发热（rl_sar#70）、模型文件不一致（unitree_ros#157）等报告（[可行性](../05_experiments/go2w_feasibility.CN.md) §6）。"差距在哪里、怎么补"有实际价值。
- Go2-W 用 7 英寸**充气轮胎**（官网），仿真里通常是刚性圆柱，轮地接触可能存在明显差异。
- **但目前没有证据证明差距主要在轮子上**。现有线索也指向配置错误（仿真腿刚度 25、部署 20）、模型文件错误和腿部发热（[终审 §2.1](review_opus/final_review.CN.md)）。所以**第一步就是测量**，测量结果本身就是研究成果。

## 3. 基础论文：PACE

| 项目 | 内容（已经 Opus 逐页核对） |
|---|---|
| 发表 | IJRR 2026，在线优先发表，尚无卷期号 |
| 方法 | 机器人悬空，关节按 chirp 信号运动；用 CMA-ES 拟合每个电机的电枢惯量、阻尼、摩擦、偏置，加一个整机延迟（4n+1 个参数）；只需关节编码器，不需要机身状态 |
| 数据量 | 一条 20–40 s 拟合序列，另加 1–2 条验证序列 |
| 代码 | 开源，Isaac Lab，依赖少；声明支持 Isaac Sim 5.0，与服务器 5.1 同代，需实测 |
| 已公开 | ANYmal 悬空数据。**未公开**：运动训练环境、奖励和权重；论文的运动实验用的是 LeggedGym / Isaac Gym |
| 轮足 | 论文 p12 已列出轮式平台 LEVA；issue #36 作者说同事在轮足上用过，并建议轮子用速度指令辨识，同时指出它"不会辨识滚动阻力和打滑" |
| 风险 | Unitree 用户在 issue 中的反馈不理想（#11 结果比普通 PD 差，#18 振动，#22 运动指标"not consistently better"）；维护者在 #22 最新回复中指出差距可能来自执行器以外（观测顺序、坐标系、状态估计延迟、机载滤波） |

**复现目标**：不复现 ANYmal 的原始数字，而是复现"辨识能否改善迁移"这一核心主张在 Go2-W 上的结果。

## 4. 方法

### 4.1 第 0 步：配置统一

把 robot_lab（训练）、rl_sar（部署）、URDF/MJCF（模型文件）中的 kp/kd、力矩和速度限幅、质量和轮惯量统一成一张参数表。之后所有比较都以这个修正后的配置作为"默认"。

### 4.2 第 1 步：悬空辨识（复现 PACE）

- 搭**刚性**悬吊架。PACE 的 ANYmal 用绳子吊，只能激励到 2 Hz（issue #4）。
- 腿用位置 chirp、轮用速度 chirp，用 CMA-ES 拟合 16 个电机。轮子需改成速度损失，并考虑轮速环的固件滤波（issue #36）。

### 4.3 第 2 步：着地接触补偿（创新）

| 设计 | 内容 | 理由 |
|---|---|---|
| 补在哪里 | 轮—地接触侧（轮的滚动阻力矩、接触参数），**不是**轮速指令 | 轮是速度伺服，打滑时轮编码器读数正常，变的是机身速度；改指令的残差表示不了打滑（[终审 §2.1](review_opus/final_review.CN.md)） |
| 形式 | 4–8 个物理参数：c₀·sign(ω) + c₁·ω 的滚动阻力、与法向负载有关的项、有效轮半径或纵向滑移 | Dao & Fern 显示约 1000 维的 MLP 残差用 CMA-ES 学不动（Fig.1）；低维参数可解释，和 PACE 的叙事一致，复用同一套 CMA-ES |
| 匹配目标 | ① 本体感觉：轮速、轮速跟踪误差、轮电机估计力矩、IMU 偏航角速度与轮速推算偏航角速度之差，按指令分组；② **机身平面运动**：相机 + 机身贴 AprilTag（几十元）测得 | 只用本体感觉看不到打滑；"不用动捕"保留，但不坚持"零外部参考" |
| 腿 | 默认不加补偿，交给 PACE；"腿也补偿"只作消融 | 控制工作量、分工清楚 |

### 4.4 可辨识性检查（先做，1–2 周）

用 **unitree_mujoco 的 Go2-W 模型当"假真机"**（与 Isaac Sim 接触模型不同）。在其中改滚动阻力、轮电机增益、轮地摩擦，检查第 2 步能否把它们辨识出来。如果打滑辨识不出来，就如实把目标限定为"负载下的轮执行器与滚动阻力"。

## 5. 实验设计

### 5.1 对比组

| 组 | 作用 |
|---|---|
| 配置修正后的默认仿真 | 基础基线（否则"辨识"的提升里混着配置修正） |
| 调过的域随机化（延迟、轮摩擦、滚动阻力、轮半径），调参投入与本文方法相当 | **最重要的强基线**：最便宜、最常用；不赢它，方法就没有意义 |
| 只辨识（PACE） | 复现 |
| 着地数据直接做 PACE 式辨识 | 回答"是否只需要在着地数据上辨识" |
| Dao & Fern 的残差执行器 | 最接近方法 |
| 只补接触 / 两步结合（本文） | 与只辨识组成 2×2：{无辨识, PACE} × {无补偿, 接触补偿} |
| 经典控制基线：站姿锁定 + 轮速 PD + 偏航 PI | 同一套对齐后的仿真调参再上真机，说明对齐对经典控制也有用 |
| 出厂控制器 | 只作产品参照线，不称"传统控制基线"（黑盒） |

### 5.2 评估协议（事先写死）

- **主指标**：固定指令下的机身速度跟踪误差（相机 + AprilTag 测量）。
- **次要指标**：轮速与关节跟踪误差、留出数据上的本体感觉分布距离、10 m 横向偏移、转弯误差。
- **真机重复性下限**：同一策略、同一指令、不同时段的两次真机之间的差距。方法要接近这个下限才算有效。
- **统计**：每条件 3 个训练种子 × 每种子 ≥ 5 次；配对、随机顺序；报告均值、标准差、置信区间；留出指令和地面。
- **工作量**：约 270 次真机运行，6–8 个实验日（[终审 §2.2](review_opus/final_review.CN.md)）。

## 7. 预期贡献（措辞已按审核收紧）

1. 轮足机器人（腿位置 + 轮速度）仿真—真机差距的**通道级归因**：悬空与着地、腿与轮各占多少。
2. 检验 PACE"悬空数据足够"的主张在轮子上是否成立；若不成立，给出低维、可解释的着地接触补偿。
3. 与强基线（调过的域随机化、着地直接辨识、残差执行器）的受控比较。

不使用"首个"的说法：PACE 已有轮式平台应用（LEVA），也已有发表的扩展（Kang 等，Machines 2026）。

## 8. 查重结论

- **已有**：电机辨识（PACE、SPI-Active）；只用本体感觉做分布匹配、CMA-ES、无动捕（Dao & Fern，Miller 等）；先标定再残差（QuadVerse，依赖 LiDAR 机身位姿）。
- **检索范围内未发现**：轮足上的仿真—真机对齐；轮—地接触的低维补偿；四种做法的受控比较。
- **检索空白**：知网未覆盖；ICRA/IROS 2026 未逐条翻官方列表。开工后第 1 周补做。
- **抢先风险**：PACE 作者把"有力传感时的接触参数细化"列为未来工作，同事已在轮足上使用。应对：尽早做，并把重点放在差距归因和受控比较。

## 9. 如何回答传统控制方向的质疑

1. **"这不就是系统辨识吗？"** 是的，第一步就是经典系统辨识，并单独作为一组。本题研究的是"经典辨识之后还剩什么、怎么补"。补偿项也是物理参数，不是黑盒。
2. **"为什么不用 MPC？"** 本题的对象是"让仿真更像真机"，这对任何依赖模型的控制器都有用，包括 MPC。实验中用经典的轮速 PD + 偏航 PI 控制器在对齐后的仿真里调参再上真机，直接展示这一点。学习策略本身的优势有同平台证据（Hwangbo 2019、Lee 2020，见[对比资料](learning_vs_model_based.CN.md)），但本文不声称"学习优于传统控制"。
3. **"黑盒怎么保证安全？"** 不声称有形式化保证；部署有关节限位、力矩限幅、急停，先悬空试运行，再低速着地，多次重复。

## 10. 为什么不选其他候选

| 候选 | 原因 |
|---|---|
| ASAP（RSS 2025） | 训练需机身全局状态（原作者用动捕）；真机数据难采；数据转换脚本未公开 |
| SimDist（RSS 2026） | 实机需外接 RTX 4090 级笔记本做实时规划；JAX 与旧栈；底座 6–8 周 |
| 具身尺度律（CoRL 2025） | 算力不可及；核心目标已被 LocoFormer 覆盖 |
| MoE-CTS（RSS 2026） | 单次训练约 7 天；创新点偏评估工具 |
| Multi-Loco（CoRL 2025） | 论文证据偏薄；Isaac Gym 移植 |
| TEMPO（NeurIPS 2026） | 无代码；可作后续参考 |
| 感知方向（Omni-Perception 等） | 价值高，但感知链工作量大；"实机走得准"是更前置的问题 |
| CaT + 电机热约束 | 技术最简单，但基础论文级别较低；**保留为备选路线** |
