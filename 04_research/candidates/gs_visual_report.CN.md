## 3. 查重（检索范围：arXiv API 多组关键词、网页检索、VR-Robo 施引文献，截至 2026-11-25；未查 IEEE Xplore 和 Google Scholar）

| 工作 | 状态 | 与本题的差别 |
|---|---|---|
| [WAVE-Go](https://arxiv.org/abs/2609.18193)（2026-09） | 预印本 | **最接近**。轮足机器人上的图像目标导航，模态与姿态切换要先通过间隙、稳定性等检查。未提及 3DGS。传感器类型与切换是学习还是规则，摘要页**未核实**，需读全文 |
| [MUJICA](https://arxiv.org/abs/2605.13058)（2026-05） | 预印本 | Go2-W 实机，有学习式技能选择器，**纯本体感觉，无视觉** |
| [AWARE](https://arxiv.org/abs/2604.23761) | 子代理称 RA-L 2026，**未亲自核实** | 轮足机器人 M20，高层策略协调滚动、迈步、混合三类专家，任务是躲避障碍，输入未核实 |
| [ReaDy-Go](https://arxiv.org/abs/2602.11575) | RA-L 2026 | 3DGS + 纯 RGB 导航，但平台是轮式小车，没有腿 |
| [QuadVerse](https://arxiv.org/abs/2606.07118) / [GaussGym](https://arxiv.org/abs/2510.15352) | 预印本 | 3DGS 视觉运动或导航，平台是腿足，无轮 |

另外，VR-Robo 的施引文献（Semantic Scholar 42 篇，OpenAlex 50 篇）按标题看，没有一篇面向轮足。

**结论：部分覆盖。** 以下组合已有人做过：
- 3DGS × 腿足视觉策略；
- 3DGS × 轮式导航；
- 轮足 × 学习式模态选择（本体感觉）；
- 轮足 × 视觉导航 × 模态切换（WAVE-Go）。

"3DGS 数字孪生 × 轮足 × RGB 策略学出模态"三者同时出现的组合，在检索范围内未见。不能声称"无人做过"。

## 4. "轮/腿模态"能否成为问题核心

【评价】**能，但有条件。** 理由有三：
- 两种模态的能力差别是量级上的：轮足 ANYmal 混合运动相对纯腿式约 3 倍速度、运输成本低 53%（Lee 2024，见 [证据整理](../learning_vs_model_based.CN.md)）。
- 路线和模态是耦合决策：可以滚着绕坡，也可以迈步抄近路上台阶。
- 视觉可以在接触障碍前就提前切换。

要成为核心，需要同时满足三条：
1. 场地设计成必须权衡（绕远平地 vs 近路台阶）；
2. 奖励里的能耗项用真机实测标定（`LowState_` 有 `power_v`/`power_a` 字段，是否有效未核实）；
3. 与三类基线正面比较：robot_lab 盲混合策略、本体感觉被动切换、雷达高程阈值切换。

否则就退化成"VR-Robo 换个机器人"。

**主要隐患**：台阶是几何问题，正是雷达的强项，RGB 学到的模态选择**可能赢不了雷达阈值规则**。

## 5. 致命风险与判断

| 风险 | 级别 |
|---|---|
| Go2-W 不开放 lowcmd（底层控制） | 致命；第 0 周确认 |
| 前置相机取流方式和视场未核实；扩展计算模块型号未核实 | 高；可改用外接相机或外接笔记本 |
| 模态条件底层策略需自己训练（robot_lab 默认策略不区分模态），社区报告过 Go2-W 策略抖动、发热（rl_sar #178、#70） | 高 |
| 重建、对齐、部署三段都没有代码，工程链最长 | 高；挤压实机时间 |
| WAVE-Go 已占"Go2-W 视觉导航 + 模态切换" | 高；创新点只剩 3DGS 训练 + 学习式模态 + 能耗权衡 |
| 结果可能输给雷达规则 | 中；可作为负结果报告 |
| 每个场地需重建并训练约 3 天，泛化未验证 | 中；属于原文局限 |

**判断：有条件可行。** 前提有四：
1. 第 0 周确认 lowcmd、相机、计算模块；
2. 先读 WAVE-Go 全文，确认它的模态切换是规则而不是学习、且未用 3DGS；
3. 第 4 周模态底层策略在真机达标；
4. 接受"可能输给雷达规则"的负结果风险。

【评价】与 PACE 方案（7/10）相比，本方向题目更新、演示更直观；但工程链长，查重压力更大，回应传统控制较弱。**总体 5.5/10**，建议作为备选。
