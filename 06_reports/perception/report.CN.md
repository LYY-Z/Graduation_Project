## 0. 一页总览

| 项目 | 内容 |
|---|---|
| 课题方向 | 轮足机器人 Go2-W 用机身自带激光雷达的原始点云做端到端避障，重点研究轮式高速行驶时避障还能否成立、怎样提高安全速度上限 |
| 基础论文 | **Omni-Perception**：*Omnidirectional Collision Avoidance for Legged Locomotion in Dynamic Environments*（Wang 等，港科大（广州）），**CoRL 2025**，PMLR v305 wang25b，pp. 670–685 |
| 基础论文做了什么 | 机器狗把激光雷达原始点云（不建地图）和本体感觉一起输入一个强化学习策略，策略直接输出关节目标，实现全方位避障，包括悬空障碍和移动的人 |
| 我们的研究问题 | ① 这种端到端避障迁到 Go2-W（12 腿位置 + 4 轮速度）后，在什么速度范围内成立？② 用 Go2-W 自带的稀疏雷达（L1 或 L2）时，速度升高后失败的主要原因是点太稀、扫描延迟，还是运动畸变？③ 针对这些原因做设计，能把"安全速度上限"提高多少？ |

| 退路 | 高速目标做不成时，论文改为：Omni-Perception 在轮足和稀疏雷达上的复现，加上"速度–成功率"的系统评测和与分层方案的对比 |
| 关卡 | 第 0 周确认雷达型号（L1/L2）、Jetson 型号、能否读到点云；第 5 周仿真复刻必须达标；第 9 周第一次实机低速避障 |
| 总体评价 | **5.5/10（作为备选）**。演示效果好、方向热门，但基础论文的训练代码未公开（发表一年仍未放出），同期竞争很多，而且 Go2-W 自带雷达偏稀疏是硬件层面的风险（见第 12 节和文末对比） |

### 0.1 为什么选 Omni-Perception 作基础论文

用户给的方向是"基于激光雷达感知的 Go2-W 运动（避障/复杂地形）"。候选比较如下：

| 候选 | 发表 | 代码 | 平台 / 传感器 | 与方向的契合 | 结论 |
|---|---|---|---|---|---|
| **Omni-Perception** | CoRL 2025（PMLR 已收录） | 只开源了雷达仿真；训练和部署代码"In Progress / Planned"（README 第 36–38 行），至今未放出（issue #36、#37） | Go2（实机雷达不是 L1，见 issue #23）+ G1 Mid-360 | **原始点云端到端避障**，与"雷达 + 避障"完全对口；是该方向被引最多的工作（OpenAlex 记 28 次，2026-11-25） | **选为基础论文** |
| REASAN（arXiv 2512.09537） | **预印本**，未查到录用信息 | **训练和部署代码齐全**，带预训练权重，GPLv3 | Go2 + Mid-360 + Jetson AGX Orin 64 GB | 模块化：Transformer 把点云转成射线距离，再接 3 个 RL 策略 | 作为**工程脚手架和主要学习基线**，不作基础论文（未正式发表） |
| PGTT（arXiv 2510.18348） | arXiv 页写 IROS 2026 录用 | 有，含 Go2 实机脚本 | Go2 + **L1** + Point-LIO 高度图；MuJoCo MJX（JAX） | 复杂地形（台阶），不是避障；技术栈是 JAX | 不选。但它给出了 **L1 稀疏导致只能 0.4 m/s** 的关键证据（第 8 页结论段） |
| Hiking in the Wild（arXiv 2601.07718） | 项目页称 CoRL 2026；非官方 CoRL 2026 论文列表中有此题 | 项目页称有代码（本次未核实仓库内容） | **人形 G1 + 深度相机** | 感知方式是深度相机，不是雷达 | 不选 |
| PointWalker（arXiv 2610.15548） | 预印本，投 RA-L | 未见代码 | 深之源 X30，**4 个 Mid-360** | 原始点云地形行走，与 Omni 同类 | 作为查重对象，不选 |

【评价】选 Omni-Perception 的理由：
1. 正式发表在 CoRL；
2. 问题定义最贴近"雷达 + 避障"；
3. 它自己承认的局限（远场平均后小障碍消失、草地误判，p9 §6）和别人对它的批评（速度约 1 m/s、启发式避让速度在密集场景下过于保守，REASAN §II、表 II）正好留出创新空间。

代价是要自己补齐训练代码。因此复现时借用 REASAN 的开源工程（同为 Isaac Lab、同为 Go2）。

## 第一部分：基础论文 Omni-Perception 精读

### 1. 论文的价值与权威性

| 团队 | 港科大（广州）梁俊卫组，合作方有清华和北京人形机器人创新中心（p1） |
| 影响 | OpenAlex 被引 28 次；GitHub 542 星、46 个 fork、20 个未关闭 issue（2026-11-25 通过 GitHub API 读取） |
| 开放程度 | 开源的只有雷达仿真模块 LidarSensor，作者自评 "Released[Half]"。**训练代码、PD-RiskNet 网络定义、部署代码都没有公开**（README 第 36–38 行）。2025-11-05 只补了一份点云预处理参考文件 `Train/reference/observations.py`（issue #26、#28）。README 徽章写 MIT，但仓库中**没有 LICENSE 文件**，GitHub API 的 license 字段为空 |
| 【评价】 | 会议级别高，方向热门，问题有吸引力。但论文本身偏系统演示，方法和实验都较薄（见第 7 节）。它的价值更多在于证明"原始点云直接进 RL 策略在实机上可行"，并提供了一个快速雷达仿真器 |

### 2. 论文要解决的问题

**背景**：多数足式机器人控制器只用本体感觉（"盲走"），看不见障碍。用深度相机的方法受光照影响，视野窄。用高程图的方法要维护中间地图，而且表达不了悬空障碍（p2 引言）。

**【作者】问题定义**：给定速度指令，让机器人在有静态、悬空、移动障碍的三维环境里一边跟踪速度、一边全方位避障。只用机载雷达点云和本体感觉，用 RL 端到端训练（p4 §3.1）。

**【评价】为什么重要**：雷达不受光照影响，视野可达 360°，而且 Go2/Go2-W 出厂就带雷达。如果"点云直接进策略"可行，就能省掉建图、定位、规划这条长链路，反应也更快。

### 3. 现有方法及其局限（论文想法的来源）

| 现有方法 | 【作者】指出的局限（p2–3 §1、§2） |
|---|---|
| 纯本体感觉策略 | 看不见障碍和复杂地形 |
| 深度相机端到端策略、深度转射线距离（如 ABS） | 受光照影响，视野和量程有限，sim-to-real 需要大量深度噪声随机化 |
| 2.5D 高程图 | 表达不了悬空和非平面障碍，对噪声敏感，维护地图有计算开销 |
| 导航规划与运动控制解耦 | 行为保守，发挥不出机器人的敏捷性 |
| MPC 带碰撞约束 | 依赖准确模型、计算量大、动作偏慢（p3 §2.3，**只是引文论述，论文没有做 MPC 对比实验**） |
| 雷达在足式机器人上的已有用法 | 多用于 SLAM 和路径规划这类传统流水线，没有直接进入 RL 策略 |

**论文的想法**：把原始点云当作策略的直接输入。为了解决点数太多和远近密度差异大的问题，近场和远场分两路处理。再写一个足够快、能模拟真实扫描方式的雷达仿真器，支撑 4096 个环境并行训练。

### 4. 论文面对的挑战

【作者】（p2 引言、p3 §2.2）：
1. 点云维度高、无结构，难以在高频控制回路中实时处理；
2. 雷达物理特性难以准确仿真，影响 sim-to-real；
3. 现有仿真器对非重复扫描雷达（如 Livox）支持差，或者无法大规模并行（p4 §3.2）；
4. 动态障碍需要每步更新网格，大规模并行时开销很大（p4 §3.2）。

### 5. 方法：流程与细节

**流程**：

```text
① 仿真中按真实扫描方式发射射线（Warp/Taichi 实现，含机身自遮挡）→ ② 点云按俯仰角分成近场 / 远场
→ ③ 近场：最远点采样（FPS）→ GRU（训练时用特权高度做监督）；远场：降采样 → GRU
→ ④ 两路特征 + 本体感觉历史 + 速度指令 → MLP → 12 个关节位置目标
→ ⑤ PPO 训练，奖励 = 带避让的速度跟踪 + 远离障碍 + 常规正则项 → ⑥ 零样本部署
```

**关键细节**：

| 环节 | 内容（页码 / 代码行） |
|---|---|
| 观测 | 本体感觉历史：关节位置和速度、**机身线速度与角速度**、重力投影；点云历史；速度指令（p4 §3.1）。【评价】**Go2-W 在底层模式下没有官方机身线速度**（[可行性核查 §1.5](../../05_experiments/go2w_feasibility.CN.md)），robot_lab 的 Go2-W 任务也删掉了这一项，迁移时要去掉或另行估计 |
| 雷达仿真 | Warp 做 GPU 光线投射，Taichi 支持跨平台。每个环境的静态网格只建一次 BVH；所有环境的动态物体合并成一个全局网格，每步只更新顶点（p4–5 §3.2）。支持 Livox 非重复扫描（用真机数据确定每一时刻的扫描角）和 Velodyne/Ouster 旋转雷达（p5）。**不含 Unitree L1/L2 的扫描模式**（README 硬件列表；issue #3） |
| 近 / 远场划分 | 按俯仰角阈值划分（p6 §3.3.1），论文**没有给出阈值数值**。参考代码按俯仰角 φ ≤ 阈值算近场、> 阈值算远场，阈值默认 0.0（`observations.py` 第 203、291、372 行） |
| 近场 | FPS 采样后按球坐标排序，送入 GRU；GRU 的训练目标是特权高度（p6）。作者在 issue #18 说明是 "MSE(height, gru(point cloud))"。近场输出 187 维（p14 B.1）。【评价】187 = 17 × 11，正好是 legged_gym 常用高度扫描网格的点数，近场分支实际上是在"从点云重建高度图"。参考代码默认采 256 个点（第 262 行） |
| 远场 | 论文写"平均降采样"（p6），输出 64 维（p14）。**参考代码其实是按角度排序后等间隔取 128 个点，没有求平均**（`distal_points_average`，第 343–426 行），与论文描述不一致 |
| 时间历史 | N_hist = 10 帧（p14 B.1） |
| 策略网络 | MLP [1024, 512, 256, 128]，ELU，输出 12 维关节位置（p15 B.2） |
| 核心奖励 | ① 带避让的速度跟踪：把 360° 分成 36 个扇区，扇区内最近距离小于阈值（文中举例 1 m）时，生成一个指向远离障碍方向的避让速度 V_avoid = Σ exp(−d·α)，奖励 exp(−β‖v − (v_cmd + V_avoid)‖²)，权重 2；② 距离最大化：远场射线截断距离的平均，权重 1.5（p6–7，表 5） |
| 碰撞 | 只有很小的连杆碰撞惩罚（−0.02）和绊脚惩罚（−2×10⁻²）（表 5），文中**没写碰撞是否终止回合** |
| PPO | 4096 个环境，每批 24 步，学习率 1e-3（自适应），5 个 epoch，4 个 mini-batch（表 6） |
| 随机化 | 10% 的点被遮挡（距离改为 [0, 0.3] m），10% 距离噪声；质量 −1～5 kg，负载 −1～3 kg，摩擦 0.4–1.0，电机强度 0.8–1.2，本体感觉延迟 5–45 ms 等（表 7，以第 15 页 PDF 图像为准） |
| 部署 | 图 2 的流程图中有 "Actuator Net"（p5），但正文没有解释。实机用的计算平台、控制频率、雷达帧率，**论文都没有写** |

### 6. 针对性设计：每个机制对应哪个挑战

| 挑战 | 设计 | 【评价】是否成立 |
|---|---|---|
| 点云维度高 | 近场 FPS、远场降采样、GRU 处理时间序列 | 有一个仿真消融支持（表 3），但只在单一场景跑了 30 次 |
| 远近密度差异大 | 近 / 远场分开处理 | 合理。代价是作者自己承认的：远场处理会抹掉细小障碍（p9 §6.1，图 8 细杆） |
| 仿真速度 | 共享动态网格 + Warp | 有定量数据（表 1）：4096 个环境、32k 线时约 273 ms，Isaac Sim 内存溢出 |
| 雷达逼真度 | 真实扫描方式 + 自遮挡 | **只有定性的点云对比图**（图 4，"appeared similar"），没有定量指标 |
| 避障行为学习 | 启发式避让速度 + 距离最大化奖励 | 有效，但偏保守。REASAN 复刻了这个启发式奖励（REA-heu）：稀疏场景成功率 99.0%，密集场景只有 31.1%，超时 62.3%（REASAN 表 II）。这是第三方复刻的结果，不是原作者的数据 |

### 7. 实验：平台、任务、基线、指标、结果

| 项目 | 内容 |
|---|---|
| 平台 | 实机：Unitree Go2（图 1、图 2）。作者在 issue #23 说明实机**没有用 Go2 自带的 L1**，理由是 "L1 pc density too low"（点云太稀）。具体用了哪款雷达，论文没写（issue #31 也在问，未回复）。仿真逼真度验证用的是 G1 + Mid-360（p7 图 4） |
| 任务 | ① 雷达渲染速度（表 1）；② 仿真消融：12 m × 4 m 场地，6 个以 1.5 m/s 运动的障碍，到达终点即成功（p8 表 3）；③ 实机：静态、悬空、细小障碍和移动的人四类场景，各 30 次（表 4） |
| 基线 | 消融：Direct MLP、FPS+MLP、FPS+GRU；实机：**只比较了 Unitree 出厂系统** |
| 指标 | 成功率、碰撞率、渲染时间 |
| 结果 | 消融（表 3）：本文方法成功率 76.7%、碰撞率 56.7%；FPS+MLP 33.3% / 93.3%；FPS+GRU 30.0% / 70.0%；Direct MLP 显存溢出（24 GB）。实机（表 4）：本文 / 出厂系统：静态 30/30 对 30/30；悬空 21/30 对 0/30；**细小障碍 25/30 对 30/30**；移动的人 27/30 对 0/30 |

**【评价】证据强度：偏弱。**

1. **实机只和出厂系统比**。没有和 ABS、高程图类学习方法或"建图 + 规划"方案比较，却在摘要中称比依赖中间地图的方法更鲁棒（p1）。这个说法**没有实验支撑**。
2. **出厂系统在细小障碍上反而更好**（30/30 对 25/30）。论文在正文中没有讨论这一点。
3. **消融很薄**：只有一个场景、30 次、没有随机种子和置信区间。表 3 中成功率加碰撞率超过 100%，说明碰撞不终止回合，但文中没有说明碰撞率的定义。
4. **关键条件没报告**：实机速度、雷达型号、计算平台、控制频率都没写。REASAN 称其速度约 1 m/s，并且是线缆连接而非完全机载（REASAN §II）。这是第三方的说法，原文中未能核实。
5. 雷达逼真度只有定性对比；附录中有一处断开的引用（p7 "Appendix.??"）。

### 8. 与传统控制（建图 + 规划 + MPC 分层方案）相比

| 对比对象 | Omni-Perception 多了什么 | 它的不足 / 未证明的部分 |
|---|---|---|
| 分层方案：雷达惯性里程计（LIO）+ 局部代价地图 + DWA/MPC → 速度指令 → 运动控制器 | 不需要定位和建图；悬空障碍和移动的人直接在点云中体现；从感知到动作只经过一个网络，链路短 | **论文没有做这个对比**。分层方案可解释、可调参、能显式写约束（见[学习与传统控制证据 §1.2](../../04_research/learning_vs_model_based.CN.md)）。Go2-W 上已有分层方案跑通长距离任务的先例：FAST-LIO2 + 占据栅格 A* + Mid-360 + Orin NX，约 2.8 km（arXiv 2606.21387 §5，预印本），但该文没有报告避障的定量指标 |
| 出厂系统（Unitree 自带避障） | 在悬空障碍和移动的人两类场景中占优（表 4） | 静态障碍持平，细小障碍落后 |
| 带碰撞约束的 MPC | 论文只在相关工作中称 MPC 偏慢、计算量大（p3 §2.3） | 无实验。另一篇 Go2 端到端避障工作 E2DRL（arXiv 2610.19627，预印本）在仿真中与 DCBF-NMPC 做了比较，可作参考 |

【评价】在"学习 vs 传统"问题上，这篇论文提供的证据很少。我们的课题如果做这个方向，**必须自己补上与分层方案的同条件对比**。这既是答辩时最容易被质疑的地方，也是可以写进论文的贡献。

### 9. 作者承认的假设、局限与未来工作

- **局限**（p9 §6）：
  - 密集植被（草地）中雷达提不出可靠的几何特征，会把草误判为障碍（图 7）；
  - 远场降采样会丢失细小障碍（图 8 细杆）；
  - 采样策略降低了感知的细节。
- **作者提出的解决方向**：
  - 引入语义分割；
  - 提高仿真逼真度；
  - 更强的域随机化或域适应；
  - 部署时在线微调感知。
- **隐含假设**（【评价】，从方法中推断）：
  - 雷达点密度足够（作者因此弃用了 L1，issue #23）；
  - 实机可以获得机身线速度；
  - 机器人运动速度不高，可以忽略扫描期间的运动畸变（论文没有提及畸变）。

### 10. 复现难度（含服务器兼容性）

| 层次 | 内容 | 难度 |
|---|---|---|
| 雷达仿真能跑 | LidarSensor 有 IsaacGym、Isaac Lab、Genesis 示例。README 要求 Isaac Sim **≤ 4.5**，并写明 "Isaac Sim 5.0 don't supported"（README 第 125 行）。issue #29：在 Isaac Sim 5.0 中无法通过 xform view 读取运动物体的状态，**动态障碍的射线检测失效**，官方 RayCaster 也有同样问题，至今未解决。issue #22：作者在 Isaac Sim 4.2/4.5 + Isaac Lab 2.1/2.2 上测试过；有用户在 Isaac Lab 2.3.0 下出现 NaN（0×inf），已给出补丁 | 中。**我们服务器的 Isaac Sim 5.1 是否可用未核实**，动态障碍风险高 |
| 复刻训练 | 训练代码、网络定义、近 / 远场阈值都没有公开（#20 作者 2025-09 说"两周内"放出，至今没有；#36、#37 仍未关闭）。现有信息：论文附录的维度、奖励和超参数，`observations.py` 的点云预处理（Isaac Lab 接口，第 8–17 行），以及 #18 中的高度监督方式 | **高**：要自己写环境、网络和奖励，并调到能用 |
| 迁到 Go2-W | 动作改为 16 维（12 腿位置 + 4 轮速度），去掉机身线速度，加入 L1/L2 扫描模式（作者在 #3 建议采 1–2 秒真机数据记录发射角）、Go2-W 机身和轮子的自遮挡网格 | 中高 |

**可复用资源与服务器兼容性**：
- REASAN 仓库提供完整的训练、部署代码和预训练权重：PyTorch 2.7.0 cu128 + Isaac Sim 4.5 + 自带 Isaac Lab + rsl_rl（README）。论文写明全部训练在单张 **RTX 5090** 上完成（REASAN §III，表 I：运动策略 4 h / 15 GB，安全策略 15 h / 12 GB，导航策略 7 h / 15 GB）。RTX 5090 与我们服务器的 RTX PRO 5000 同为 Blackwell 架构（sm_120），所以"torch 2.7 cu128 + Isaac Sim 4.5 能在 sm_120 上跑"有间接证据。但在 RTX PRO 5000 上**未核实**。
- robot_lab v2.3.2 的 Go2-W 任务兼容 Isaac Sim 4.5/5.0/5.1（[可行性核查 §1.3](../../05_experiments/go2w_feasibility.CN.md)）。
- 【设想】可行的组合是：robot_lab v2.3.2（Go2-W 资产与动作接口）+ 独立的 Isaac Sim 4.5 Conda 环境（与 REASAN 一致）+ Omni 的 Warp 光线投射（自己管理动态网格，绕开 Isaac Sim 5.x 的 xform 问题）。第 1 周就要验证。

**社区反馈的风险**：
- 训练代码一年多未发布，多人在问（#20、#26、#28、#36、#37）；
- 有用户报告动态网格在 prim path 相同时失效（#33，未解决）；
- 有用户的雷达射线在动态物体上失效（#24，作者已补示例）。

### 11. 这篇论文对我们的贡献

1. **问题框架和方法原型**：PD-RiskNet 结构简单（FPS + GRU + MLP），附录给出了各部分维度、奖励权重和超参数，可以照着复刻。
2. **雷达仿真工具**：Warp 光线投射、非重复扫描模式、自遮挡，大规模并行训练可以直接借用。
3. **明确的缺口**：作者因 L1 太稀而弃用（#23）；远场处理会丢失小障碍（p9）；只和出厂系统比（表 4）；没有报告速度。这几点都直接对应 Go2-W 的问题。
4. **对照的抓手**：它的启发式避让速度奖励已被 REASAN 证明在密集场景中保守，可以作为我们改进设计的对照组。

### 12. 后续创新研究价值与抢先风险

| 方向 | 依据 | 【评价】 |
|---|---|---|
| **轮足高速 + 稀疏雷达下的端到端避障**（我们选的方向） | Omni 没有报告速度，弃用了 L1；PGTT 因 L1 只有 21,600 点/秒（"higher-end sensors" 为 200,000 点/秒），实验限速 0.4 m/s（PGTT 第 8 页结论）；Go2-W 官方最高速度 2.5 m/s（[实验条件 §1](../../05_experiments/lab_requirements.CN.md)） | 问题真实、有动机。但风险也来自同一个原因：**如果用户的雷达是 L1，高速目标可能做不到**，需要换雷达或降低目标 |
| 扫描期内运动畸变与延迟建模 | 高速时一帧扫描期间机身移动明显；检索范围内未见足式机器人在 RL 训练中对扫描期间的运动畸变建模（PointWalker 只注入 40–60 ms 延迟） | 有新意，工作量可控，可单独做消融 |
| 远场保留小障碍 | Omni 自承的局限（p9） | 改动小，适合作为消融项 |
| 语义分割识别草地 | 作者列出的未来工作 | 需要相机，偏离雷达方向，不建议 |
| 轮腿混合避障（滚行绕开 vs 抬腿跨过） | Go2-W 特有 | 价值高但训练难，作为扩展目标 |

**抢先风险：高。** 这个方向在 2025–2026 很拥挤（详见"查重"）：
- REASAN（Go2 + Mid-360，代码已开源）；
- SEA-Nav（Go2，用到 L1）；
- PointWalker（4 个 Mid-360）；
- AWARE（轮足反射式躲避，RA-L 2026）；
- FutureRay（制动约束，预印本）。

原作者组也在扩展到更多机器人（#20）。应对办法：抓住"轮足 + 自带稀疏雷达 + 速度上限"这个交叉点，不在网络结构上和别人拼。

## 第二部分：我们的课题方案

### 13. 研究问题与挑战

**问题**：Go2-W 用机身自带雷达（L1 或 L2）的原始点云做端到端避障时，速度从 0.5 m/s 提高到 2 m/s，成功率怎样变化？主要瓶颈是什么？针对性设计能把安全速度上限提高多少？与传统分层方案相比，各自在哪些速度和场景下更好？

**挑战**：

1. **点稀**：
   - L1 官方为 21,600 点/秒、360° × 90° 视场、30 m 量程，水平扫描 11 Hz；L2 为 64,000 点/秒，水平扫描 5.55 Hz（Unitree 官方页与手册的检索摘要，**未逐份打开 PDF 核对**）。
   - SEA-Nav 附录称 Go2 自带 L1 每帧约 1,000 个三维点。
   - Omni 作者因此弃用了 L1（#23）。
2. **速度带来的时间压力**：
   - 制动距离随速度平方增长；
   - L1 一圈约 1/11 s，L2 约 1/5.55 s。【评价】按这个周期估算，以 2 m/s 行驶时，一帧扫描期间机身移动约 0.18 m（L1）或 0.36 m（L2），点云会产生畸变。这是按周期推算的值，未实测。
3. **轮足动作空间**：
   - 轮子是速度伺服，转向方式与腿式不同（滑移转向）；
   - 机身没有官方线速度（底层模式下）；
   - 轮子和腿会遮挡雷达视野。
4. **公平比较**：分层方案也要调好，才能回答"为什么不用传统方法"。
5. **实机安全**：高速避障实验存在撞击风险。

### 14. 针对性设计

| 挑战 | 设计 |
|---|---|
| 点稀、扫描方式不同 | **D1 真实雷达模型**：采 1–2 秒真机 L1/L2 数据，提取每一时刻的发射角，生成扫描模式文件（作者在 #3 中给出的方法）。射线按发射时刻对应的机身位姿投射，模拟**扫描期内的运动畸变**。另外随机化延迟和丢帧 |
| 小障碍丢失 | **D2 远场保留最近点**：远场降采样时，每个角度格保留最近的点，而不是平均或等间隔取点，避免把细杆抹掉 |
| 高速时间压力 | **D3 制动距离安全项**：用仿真中的特权信息算出当前航向上的净空距离 c，以及制动距离 s = v·t_r + v²/(2a_max)。s > c 时给予惩罚或提前终止回合。这一项替换 Omni 的启发式避让速度（后者在密集场景中保守，见 REASAN 表 II） |
| 速度条件化 | **D4（可选）**：近 / 远场的俯仰角阈值和远场点数随指令速度调整，速度越快看得越远 |
| 轮足动作 | 沿用 robot_lab Go2-W 的 16 维动作（腿位置 + 轮速度）和 57 维本体观测（不含机身线速度），把点云分支接在前面 |
| 方法是否可靠 | 先在仿真中用"完美点云"训练上限策略，再逐项加入 D1 的各种误差，测量每一项造成的性能下降，作为瓶颈归因 |

### 15. 任务、Benchmark、基线、指标与统计

**任务**：给定前进速度指令，穿过布有障碍的走廊（静态箱子、悬空横杆、细杆、移动障碍），障碍密度分稀疏和密集两档；速度档 0.5 / 1.0 / 1.5 / 2.0 m/s。

**Benchmark 说明**：轮足雷达避障目前没有公认的测试集。仿真场景参照 REASAN 的 ScaSparse/ScaDense 和 Omni 表 4 的四类障碍自建，实机场景完整公开。

**基线**：

| 基线 | 选择理由 |
|---|---|
| B0 出厂避障系统 | 产品参照线（黑盒） |
| B1 盲策略（robot_lab Go2-W） | 下限，说明感知确实起作用 |
| B2 Omni-Perception 复刻（PD-RiskNet + 启发式奖励） | 基础论文复现 |
| B3 射线距离表示（ABS/REASAN 式，同一策略结构，把点云换成射线距离） | 检验"原始点云"本身有没有价值 |
| B4 传统分层：Point-LIO（官方适配 L1/L2）+ 局部代价地图 + Nav2 的 MPPI（采样式 MPC）或 DWB 控制器 → 速度指令 → 盲运动策略 | 回答"为什么不用传统方法"的核心对照 |
| 消融 | 去掉 D1 / D2 / D3 的任一项；完美点云上限 |

**指标（事先确定）**：
- **主指标**："安全速度上限"，即成功率 ≥ 90% 的最高速度档；
- 次要指标：成功率、碰撞率、超时率、最小净空距离、平均速度、端到端延迟（雷达到动作）、Jetson 推理耗时。

**统计**：
- 仿真：每个条件 3 个训练种子 × 200 回合；
- 实机：每个条件、每个速度档 ≥ 10 次，按随机顺序执行；
- 成功率报告 Wilson 置信区间。

### 16. 与传统控制相比的优势（答辩口径）

1. **不预设学习方法更好**。本课题的核心实验就是把分层方案（B4）和学习方案放在同一台机器、同一套场景、多个速度档下比较，结果画成"速度–成功率曲线"。
2. **预期【设想】**：
   - 低速、静态障碍下，分层方案可能持平甚至更好（参考 Omni 表 4 中出厂系统在细小障碍上的表现）；
   - 学习方案的优势预计出现在悬空障碍、移动障碍和高速场景（链路短、无需定位）；
   - 这些都需要实验证实。
3. **安全措施**不靠形式化保证，而靠工程手段：限速、软质障碍物、急停、先仿真后实机、逐档提速。

### 17. 预期贡献

1. 首个面向轮足 Go2-W、使用机身自带稀疏雷达的端到端点云避障系统，以及"速度–成功率"的系统评测。（"首个"仅限于"查重"一节的检索范围，不声称无人做过。）
2. 稀疏雷达下高速避障的瓶颈归因：点密度、延迟、运动畸变各自影响多大。
3. 与传统分层方案的同条件对比，以及公开的测试协议。

## 查重：设想创新点在 2025–2026 是否已被覆盖

**检索范围**（2026-11-25）：
- WebSearch 约 9 轮，关键词包括 wheel-legged / wheeled-legged、LiDAR、point cloud、collision avoidance、high-speed、motion distortion、Unitree L1、Go2-W；
- arXiv API 核对元数据；
- 非官方 CoRL 2026 论文列表（本地抓取，按标题检索）。

| 工作 | 状态 | 与我们设想的重合 | 链接 |
|---|---|---|---|
| AWARE：轮足反射式躲避（DEEP Robotics M20） | **RA-L 2026**（arXiv journal_ref） | 轮足 + 学习避障，**高度重合于"轮足躲避"**；但障碍状态来自**动捕**，只躲飞来的或捅过来的物体，不涉及雷达，也不涉及高速滚行中的静态避障（§VI、§V） | [arXiv 2604.23761](https://arxiv.org/abs/2604.23761) |

| StratMamba | IROS 2026 录用（arXiv 页） | 雷达避障，双时间尺度记忆，Go1 | [arXiv 2607.12370](https://arxiv.org/abs/2607.12370) |

**结论**：
- "轮足 + 学习避障"已被 AWARE 部分覆盖（动捕、动态物体）；
- "雷达点云 + 学习避障"已被 Omni、REASAN、SEA-Nav 覆盖（腿式）；
- "制动距离约束速度"已被 FutureRay 部分覆盖（深度、分层）。
- 在检索范围内，**没有找到同时满足"轮足 + 机身自带稀疏雷达原始点云 + 端到端策略 + 速度上限评测与分层方案对比"的工作**；也没有找到足式机器人在 RL 训练中建模扫描期运动畸变的工作。
- 本方向的创新属于"有明确动机的组合与轮足适配"，符合 STATUS 中 2026-11-25 的决定，但新颖性有限，主要靠实验的扎实程度取胜。
