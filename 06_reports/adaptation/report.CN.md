## 0. 一页总览

| 项目 | 内容 |
|---|---|
| 课题方向 | 轮足机器人 Go2-W 部署后遇到**换地面、加负载**时，在机载电脑上在线小幅调整策略；不需要奖励，也不需要外部定位 |
| 基础论文 | TEMPO：*Efficient Test-Time Adaptation For Robot Policies*（Alfarra、Mazzaglia、Peschl、Dijkman、Louizos，Qualcomm AI Research），NeurIPS 2026 poster |
| 基础论文做了什么 | 部署时冻结训练好的评价网络（critic），把它的打分当作自监督信号，每隔一段时间对策略网络做一步梯度更新。另外加了熵正则和"难样本优先"的记忆库，让更新更稳。全程只用机载传感器，不用奖励 |
| 我们的研究问题 | 策略已经用域随机化加历史编码器（RMA/HIM 类）训练过，相当强。在这个基础上，"无奖励在线更新"在**轮足实机**上还能不能带来额外收益？会不会把机器人越调越差？怎样保证"不变坏"？ |
| 我们的做法【设想】 | ① 在 Go2-W 仿真中复现 TEMPO 的结论；② 为 Go2-W 设计"可部署的 critic"：加入轮速推算速度等机载信号，弥补 Go2-W 拿不到机身速度的问题；③ 不再更新全部策略参数，改为只训练有界、从恒等开始、腿和轮分开的小适配器；④ 加一个不依赖 critic 的"不变坏"守护，发现变差就退回原策略；⑤ 与强基线、经典自适应控制做受控对比 |

**选择理由【评价】**：

1. **本科生能不能做出来**：TEMPO 的核心只有三个公式（p4 式 1–2，p5 式 3–4）和两段很短的算法（p13 算法 1–2），可以在现有训练链上自己实现。难点在于它需要一个"给动作打分"的 Q 型 critic，而 robot_lab 用的是 PPO，只有状态价值 V。所以要换成 off-policy 训练，或者另补一个 Q 型 critic（见第 10 节），这是主要工作量。
2. **机载算力**：每 128 步对一个小 MLP 做一次反向传播（p6），作者在 Go2 的 4 个 CPU 核上完成（p17）。不需要外接 GPU，这一点明显好于 SimDist 和 SHOES。
3. **真机在线更新的安全性**：TEMPO **没有任何显式的安全机制**，只靠很小的学习率（5×10⁻⁶，p6）和"仿真中没观察到遗忘"（p15–16 B.4）。这是它最大的短板，也正好是我们可以做文章的地方（第 14 节）。

## 第一部分：基础论文 TEMPO 精读

### 1. 论文的价值与权威性

| 维度 | 情况 |
|---|---|
| 发表 | NeurIPS 2026 poster（会议页和 PDF 页脚，见上表）。NeurIPS 是机器学习顶会，但**不是机器人领域的专门会议**。这篇论文的贡献以算法为主，实机部分很轻 |
| 团队 | Qualcomm AI Research（阿姆斯特丹）。第一作者此前做测试时适应（TTA）的方法和评测（论文自引 Alfarra 等 2024、2025，p3、p5）。【评价】团队的强项是 TTA 和端侧部署，不是足式机器人 |
| 版本 | arXiv v1，2026-10-14，目前只有这一个版本 |
| 影响 | 发布约 6 周，被引次数本次没查（未核实） |
| 开放程度 | **没有代码，也没有权重**。仿真基于 MuJoCo Playground，策略用 FastTD3、SimBaV2、RMA 训练（p6），这些框架都开源，但 TEMPO 本身要自己写 |
| 【评价】 | 价值在于**把视觉领域已经成熟的"测试时适应"系统地搬到机器人控制上**，并给出一个机载 CPU 能跑的简单方案。发表级别高，但实验以仿真为主，实机只有一个场景 |

### 2. 论文要解决的问题

**背景**：用强化学习训练的运动策略，部署时一旦遇到训练没见过的情况（地面变滑、加了负载、传感器退化），性能会明显下降（p1 摘要、图 1 左）。

**【作者】问题定义**（p3 §2.1）：机器人执行时收到一串**没有标签、没有奖励**的观测。要设计一个更新规则，只用推理时拿得到的量，在线更新策略参数，让性能恢复。评估用的奖励只用来报告结果，不参与更新。

**【作者】为什么难**（p3 §2.2）：
1. 部署时只有一个环境、时间很短，相邻观测高度相关，能看到的变化很片面；
2. 变化可能很突然，而算力和延迟的预算都很小。

**【评价】为什么重要**：现实中机器人不可能每遇到一种新地面就回实验室重训。如果能"边走边调"，又不需要外部测量和奖励，部署成本会低很多。

### 3. 现有方法及其局限（论文想法的来源）

| 现有方法 | 做法 | 【作者】指出的局限 |
|---|---|---|
| 域随机化 | 训练时随机改变摩擦、质量等参数 | 只能覆盖事先想到、也能建模的变化；遇到真正的新情况，只能停机离线重训（p1） |
| 适应模块 / 历史编码器（RMA 等） | 加一个网络，从历史观测推断隐变量 | 系统更复杂，跨任务、跨机器人不好移植（p2）；超出训练分布时仍可能失效（p5 相关工作） |
| 视觉领域的 TTA（Tent 等） | 最小化预测熵，或更新 BN 统计量 | 为分类任务设计，在机器人闭环控制中无效（p3，图 1 中） |
| 测试时的 RL 改进（OPEX，Park 2024） | 离线 RL 的测试时策略改进 | 同样在这个设定下无效（p3，图 1 中） |
| 测试时训练（TTT） | 在 QMAX 上加 KL 约束，不让策略偏离原策略 | 作者实验中 KL 权重越大效果越差，最好的配置就是不加约束（p17 B.9） |

**论文的想法**：训练时得到的 critic 通常部署时就扔掉了。其实它学会了"在这个观测下，这个动作有多好"，**可以拿来当部署时的性能替身**：让策略在最近的观测上，朝 critic 打分更高的方向走一小步（p2）。

### 4. 论文面对的挑战

【作者】（p2、p4 §3）：

1. **critic 本身也受分布偏移影响**。在没见过的状态上，它可能"盲目自信"地打高分，把策略带偏；
2. 简单地最大化 critic 打分（QMAX）在严重偏移下会**更新过猛、动作覆盖变窄**，闭环变脆弱；
3. 内存和算力有限，**存哪些样本、用哪些样本更新**需要取舍；
4. 观测流高度相关，多样性低。

### 5. 方法：流程与细节

**流程**（p5、p13 算法 1）：

```text
① 训练阶段（仿真）：用 actor-critic 训练策略 π 和"分布式" critic Z（critic 与策略输入相同，不用特权信息）
② 部署：每个控制步执行 a = π(o)，并算出这个观测的"难度分" S(o) = 1/(Q(o, π(o)) + ε)
③ 记忆库：没满就存；满了就把分数最低（最容易）的样本换掉 → 库里留下的是"最难"的观测
④ 每 K = 128 步：按分数比例无放回抽 B 个样本，最小化 L = −平均[Q(o, π(o)) + α·H(Z(o, π(o)))]，做一步梯度更新（critic 保持冻结）
```

**关键细节**：

| 环节 | 内容（页码） |
|---|---|
| 基线 QMAX | 只最大化 critic 的 Q 值，记忆库为先进先出（FIFO）（p4 式 1） |
| 熵正则 | critic 输出的是价值的离散分布（沿用 FastTD3 的分布式 critic）。损失中加入这个分布的熵，权重 α = 0.5。作用是不去挑 critic "很确定"的区域，鼓励在"价值高且 critic 不太确定"的区域更新（p4 式 2，p6） |
| 难样本记忆 | 难度分与 critic 预测值成反比（p5 式 3）；抽样概率按"分数减去最小值"后归一化（p5 式 4） |
| 超参数 | Adam，学习率 5×10⁻⁶；记忆库 16k；批量 2k；K = 128；**更新策略的全部参数**（p6） |
| 资源 | 49 维观测、16k 记忆库约占 3 MiB（p6）；实机用 Go2 的 4 个 CPU 核：2 个做推理、1 个做适应、1 个做里程计（p17 附录 C） |
| 观测 | 角速度、重力方向、**机身线速度**、关节角、关节速度、上一步动作、速度指令；critic 与策略输入相同（p13 B.1） |
| 机身速度 | Go2 自带的速度估计不可用，作者用足底力传感器加扩展卡尔曼滤波（引 Hartley 2018）在线估计（p13 B.1） |
| 被适应的策略 | 默认用 FastTD3 训练，**在平地、不加域随机化**（p6）；另外也测了 SimBaV2 和 RMA |

### 6. 针对性设计：每个机制对应哪个挑战

| 挑战 | 设计 | 【评价】是否成立 |
|---|---|---|
| 没有奖励 | 冻结 critic 当性能替身 | 成立，但前提是 critic 在偏移下"排序大致正确"。作者只给了经验证据，并在局限中承认：critic 严重失准时效果会变差（p17） |
| critic 盲目自信 | 熵正则 | 消融显示有用（p9 表 3，+0.5 到 +1.6）；附录 B.6 显示熵的变化与回报差距同步（p16–17）。这只是相关性证据 |
| 存什么、用什么 | 难样本记忆加重要性抽样 | 消融中贡献比熵正则大（+1.0 到 +2.3，p9 表 3） |
| 算力受限 | 每 128 步做一次小批量更新 | 成立。超参数扫描显示对记忆库大小、批量、K 都比较稳健（p14–15 B.3，图 7，只有图没有数字） |
| 遗忘 | 没有专门设计 | 仿真中回到原环境后"立即恢复、没有遗忘"（p8 §5.4，p15–16 B.4），但**实机没测** |
| 安全 | **没有专门设计** | 不成立。实机更新只做了一次、持续 4 分钟（p7），没有讨论失败时怎么保护 |

### 7. 实验：平台、任务、基线、指标、结果

| 项目 | 内容 |
|---|---|
| 平台 | 仿真：MuJoCo Playground 的 Go1、Go2、G1 摇杆任务（p6）。真机：Unitree Go2 |
| 偏移类型 | 四类：粗糙地形（高度变化）、小腿加质量、机身加质量、地面摩擦降低。每个测试回合只有一种（p6）。另有组合偏移（p7–8 §5.3）和逐步加重（p8 §5.4） |
| 基线 | 不适应；QMAX；Tent 和 OPEX（只在图 1 中出现）；TTT（p17 B.9）；RMA 自带的适应（p9 图 5） |
| 指标 | 回合回报、平均前进速度（p6 图 2）；角速度跟踪（p16 B.5）；实机用线速度跟踪奖励的累加 |
| 统计 | 仿真 6 个种子（p7）；表 2 给出均值±标准差 |

**主要结果（均为作者数字）**：

- **组合偏移**（p8 表 2，8 种组合）：平均回报不适应 11.18、QMAX 12.48、TEMPO 14.09。最难的"机身 5 kg + 碎石"一档：7.8（不适应）→ 10.5（QMAX）→ 14.6（TEMPO）。
- **消融**（p9 表 3）：

  | 条件 | 不适应 | QMAX | +熵 | +记忆 | TEMPO |
  |---|---|---|---|---|---|
  | 小腿 4 kg | 15.3 | 16.5 | 17.0 | 17.5 | 17.9 |
  | 碎石 10 cm | 7.0 | 9.0 | 10.6 | 11.3 | 11.5 |

- **Go1 / G1**（p14 表 4）：例如 Go1 机身加 10 kg，6.8 → 6.9（QMAX）→ 11.0（TEMPO）。
- **真机**（p7 表 1）：两条左腿的小腿挂配重，机载适应 4 分钟后评估。5 个速度指令，每个评 5 次，每次 3 秒（150 步，满分 150）：

| 指令 (vx, ωz) | 不适应 | TEMPO |
|---|---|---|
| 0.5, 0.0 | 93.2 ± 1.3 | 95.2 ± 0.6 |
| −0.5, 0.0 | 98.7 ± 1.6 | 113.5 ± 0.7 |
| −0.7, 0.0 | 88.1 ± 1.1 | 96.5 ± 1.0 |
| 0.7, 0.6 | 88.4 ± 3.3 | 101.6 ± 1.4 |
| 0.7, −0.6 | 80.5 ± 1.0 | 86.9 ± 1.2 |
| 平均 | 89.8 | 98.7 |

**【评价】证据强度：仿真中等，实机弱。**

1. **被适应的策略偏弱**：主实验的策略在平地、不加域随机化下训练（p6），这会放大"适应"带来的收益。加了域随机化的 FastTD3 只在碎石地形上用一张图展示（p14 图 6），没有数字。
2. **与强基线的对比不够**：和 RMA 的比较只有图（p9 图 5），没有数字。真机上**只和"不适应"比较**，没有 QMAX，也没有"域随机化 + 历史编码器"策略。
3. **实机证据很薄**：
   - 只有一种偏移（小腿配重）；
   - 适应只做了"一次、4 分钟"（p7），等于只有一次适应过程；
   - 每个指令只评 3 秒；
   - **速度真值从哪来没有说明**。从附录看，机载只有 EKF 速度估计（p13），评估很可能用的就是这个机载估计，而不是外部测量；
   - 没有报告摔倒次数、人工干预次数等安全指标。
4. **收益幅度不大**：真机平均提升约 9.9%（89.8 → 98.7）；仿真回报的绝对差距多在 1–5 分。
5. **文中数字前后不一致**：
   - 最大提升：摘要写"最高 80%"（p1），引言写"最高 50%"（p2），§5.3 写单项 +87.2%（p8）；
   - 配重：引言写"{3, 2} kg"（p2），§5.2 只写左前、左后小腿各挂配重（p7），两处怎么对应没有说明。
6. **"无奖励"的含义要说清楚**：部署时确实不用奖励，但 critic 是用仿真奖励训练出来的，奖励信息被"存"在了 critic 里。

### 8. 与传统控制（自适应控制、鲁棒控制、在线参数估计）相比

| 对比对象 | 传统方法怎么做 | TEMPO 多了什么 | TEMPO 的不足 |
|---|---|---|---|
| **自适应控制**（MRAC、L1 等） | 按已知的模型结构在线调控制器参数，通常有基于李雅普诺夫的稳定性证明 | 不需要事先写出"哪些参数会变、怎样影响动力学"；直接作用在高维神经网络策略上 | **没有任何稳定性或收敛保证**；更新方向完全取决于 critic 是否可信 |
| **鲁棒控制**（H∞、滑模） | 事先给定不确定性范围，设计一个在整个范围内都稳定的控制器 | 学习方法里对应的是域随机化；TEMPO 处理的是"超出范围"的情况 | 超出范围时，传统鲁棒控制同样没有保证，TEMPO 也没有 |
| **在线参数估计**（RLS、EKF 估质量和摩擦） | 估出物理参数，再交给模型控制或增益调度 | 不需要显式参数化；对接触、地形这类难建模的变化也能试 | 调出来的东西不可解释，不知道到底适应了什么 |
| **积分作用 / 增益调度** | 用误差积分消除稳态偏差（如上坡、滚动阻力变大） | — | 【评价】对"负载变重、速度偏慢"这类简单偏差，一个积分项可能就够了。**这是传统控制方向最可能的质疑**，必须用实验正面回答（第 15 节） |

可以借鉴的已有对比做法：
- SARA（arXiv 2603.07775v2，预印本）在仿真中把 MRAC、RLS 与 RMA、DR-SAC 等一起作为基线（见其实验设置段）。
- Zhou 等的在线学习 MPC（arXiv 2510.15626，arXiv 评论写 IEEE RA-L）用最小二乘在线学习残差动力学，并给出动态遗憾界；但只在 Gazebo 和 MuJoCo 中验证过（摘要）。

【评价】准确的说法是：TEMPO 和经典自适应控制目标相同，都是运行中调整参数来应对变化。区别在于学习方法不需要事先写出模型结构，代价是没有理论保证。本课题**不应声称学习方法优于自适应控制**，而是在同一台 Go2-W 上比较，分析各自适用的情形。

### 9. 作者承认的假设、局限与未来工作

- **假设**：
  - critic 在偏移下仍能提供"足够有用"的信号（p4、p17）；
  - 策略是确定性的（p3）；
  - critic 与策略输入相同、不用特权信息（p3）。这意味着训练时就要用"对称 critic"，常见的非对称 PPO 训练不满足这一点；
  - critic 必须是分布式的（p4，沿用 FastTD3）；
  - 观测中包含机身线速度（p13）。
- **局限**（p17 附录 C）：
  - 依赖 critic 的可信度。若 critic 严重失准，或训练域与部署域差距太大，效果会下降；
  - 推理时有额外的内存和计算开销；
  - 长时间运行时，记忆库里的分数会过时。作者试了两种刷新办法都没有提升，归因于仿真多样性不足，并预计在真实长时部署中这个问题会更明显（p17 B.8）。
- **未来工作**：论文没有单独列出。【评价】从局限推断，critic 失准时怎么办、真实长时间部署，是两个开放问题。

## 第二部分：我们的课题方案

### 13. 研究问题与挑战

**问题**：Go2-W 部署时换了地面（瓷砖、地毯、橡胶垫），或加了负载（0、4、8 kg，以及偏在一侧的负载）。在只用机载传感器、不用奖励的条件下，在线小幅调整策略能不能让速度跟踪更好？在"什么都没变"或"适应走错方向"时，能不能保证机器人不变差？

**挑战**：

1. **强基线下收益可能很小**：域随机化加历史编码器本来就能应付一部分负载和地面变化。在线更新的额外收益可能被真机测量噪声淹没。
2. **critic 看不到真实速度**：Go2-W 底层模式下没有官方机身速度。轮速可以推算速度，但一打滑推算值就偏高。偏偏在"地面变滑"这种最需要适应的时候，critic 的输入最不可靠。
3. **真机在线更新的安全**：梯度更新可能把策略带进危险区域。轮足一旦失稳倒地，会损伤腿和轮子。
4. **传统控制的质疑**：负载变重导致速度偏慢，一个积分项也许就能解决。需要证明学习方法在哪些情况下有额外价值。
5. **多种因素混在一起**：电机发热（Go2-W 轮式运动时发热集中在髋关节，arXiv 2606.21387 摘要）、电池电压下降，也会改变表现，必须和"适应"的效果分开。

### 14. 针对性设计【设想】

| 挑战 | 设计 |
|---|---|
| critic 看不到速度 | **可部署的增强 critic**。critic 的输入 = 策略观测 + 机载拿得到、但策略没用的信号：轮速推算的机身速度、IMU 加速度、腿和轮的估计力矩、腿—轮速度一致性等打滑指标。critic 只在部署时用来算梯度，所以输入可以和策略不同，只要都是机载可得的。训练时在仿真中随机化打滑、轮胎半径和滚动阻力，让 critic 学会判断"轮速推算值什么时候不可信" |
| 在线更新不安全 | **有界、恒等初始化、腿/轮分开的适配器**。冻结原策略，只训练两个小模块（借鉴 SHOES 的有界 FiLM 和线性适配器，p5 式 5–6），初始时与原策略完全一致。腿通道和轮通道分开：换地面时主要允许轮通道变化，加负载时主要允许腿通道变化。这种分工是否必要，用消融检验 |
| critic 可能误导 | **不依赖 critic 的"不变坏"守护**。独立监测机身倾角、动作变化率、轮—腿速度不一致、电机温度，以及多个 critic 之间的分歧。任何一项比"原策略的基准窗口"明显变差，就冻结更新，退回上一个安全版本或原策略 |
| 收益难测 | 用外部真值：固定相机加机身 AprilTag（与 PACE 方案共用，见[实验条件清单](../../05_experiments/lab_requirements.CN.md)）；**事先确定**最小可检测效应和试验次数 |
| 传统控制的质疑 | 在同一场地、同一指令序列下加入经典自适应基线（第 15 节） |
| 仿真先行 | 用 unitree_mujoco 的 Go2-W 模型当"假真机"（接触模型与训练用的 Isaac Lab 不同），先在里面完成全部方法开发和安全测试 |

### 15. 任务、Benchmark、基线与指标

**任务**：平地速度跟踪（前进、后退、转弯、加减速），轮足混合运动。

**偏移条件**（真机）：

| 类别 | 条件 | 说明 |
|---|---|---|
| 地面 | 瓷砖、地毯、橡胶垫 | 改变摩擦和滚动阻力 |
| 负载 | 0、4、8 kg 居中；4 kg 偏在一侧 | 官方负载约 8 kg（[实验条件清单 §1](../../05_experiments/lab_requirements.CN.md)） |
| 轮足特有（可选） | 一侧轮胎降低胎压 | 有效轮半径改变，造成偏航漂移。【评价】这种情形经典积分控制很可能占优，用来公平展示传统方法的长处 |
| "什么都没变" | 原地面、无负载 | 检验适应会不会让机器人变差 |

**Benchmark 说明**：轮足的部署期适应目前没有公认的测试集。我们采用自建协议："固定指令序列 × 地面 × 负载 × 偏移前后"。仿真中复用 TEMPO 的四类偏移和组合偏移协议（p6、p7–8），便于和原文对照。协议本身作为贡献公开。

**基线**：

| 基线 | 选择理由 |
|---|---|
| 域随机化 PPO 策略（robot_lab 默认，冻结） | 最常用的做法 |
| **域随机化 + 历史编码器**（RMA 式教师—学生或 HIM 类，冻结） | 题目要求的强基线，也是"扰动适应"方向的标准做法。TEMPO 原文中 RMA 只有仿真图 |
| QMAX | TEMPO 原文的基线（p4 式 1） |
| TEMPO 原版（更新全部策略参数） | 复现结果 |
| 本文方法及其消融（去掉增强 critic / 去掉有界适配器 / 去掉守护 / 腿轮不分开） | 证明每个设计都有用 |
| 有奖励的在线适配器（SHOES 式，奖励来自相机测速） | 只在仿真中做，作为"有奖励时能做到多好"的上限参照 |
| **经典控制**：站姿锁定 + 轮速 PI（带积分抗饱和）+ 偏航 PI；可选再加 RLS 在线估计等效滚阻或质量，用作前馈 | 回答"一个积分项或在线估计够不够"；同时代表"自适应控制"一侧 |
| 出厂控制器 | 只作产品参照线（黑盒） |

**指标（事先确定）**：
- **主指标**：偏移后稳态的机身速度跟踪误差（相机 + AprilTag 测量）。
- **次要指标**：
  - 偏移后的恢复时间；
  - 摔倒和人工干预次数；
  - 守护触发次数；
  - "什么都没变"时，相对原策略的性能变化（不变坏检验）；
  - 回到原条件后的性能（遗忘检验）；
  - 电机温度；
  - 机载单次更新的耗时。
- **统计**：
  - 每个条件 3 个训练种子 × 每个种子至少 5 次评估；
  - 方法顺序随机，做配对比较；报告均值、标准差和 95% 置信区间；
  - 先测"同一策略两次运行之间的差距"，作为真机重复性下限。效应小于这个下限，就不宣称有提升。

### 16. 与传统控制相比的优势（答辩口径）

1. **不声称学习方法优于自适应控制**。实验中直接放入经典 PI 加在线估计的基线，按偏移类型分别报告谁更好。
2. 学习方法的潜在优势：不用事先写出"哪些参数会变、怎么影响动力学"；能同时调整 16 个关节的协调方式（例如偏置负载时腿的姿态和轮速一起调）。经典轮速 PI 只能修正速度偏差。
3. 学习方法的劣势必须如实说明：没有稳定性证明。我们靠有界适配器、守护和急停做工程保护，用统计数据报告安全性，不说"保证安全"。口径与 [学习 vs 传统控制证据整理 §2、§5](../../04_research/learning_vs_model_based.CN.md) 一致。

### 17. 预期贡献

1. 在我们的检索范围内，首次在**轮足实机**上系统评估无奖励测试时适应，并以"域随机化 + 历史编码器"为基线。
2. 一个适合 Go2-W 的可部署增强 critic，以及对"critic 何时失准"的分析（尤其是打滑时）。
3. 有界适配器加不依赖 critic 的守护，在实机上给出"不变坏"的经验证据。
4. 与经典自适应控制的同条件比较，以及公开的测试协议。

【评价】第 1、4 条最稳。第 2、3 条是方法贡献，但各部件都有先例（第 20 节），只能写成"有明确动机的方法结合与轮足适配"。

| 14 | 经典控制基线的实机对比；补实验 | 2 个实验日 |
| 15–16 | 写作（第 13 周前先完成保底版论文） | — |

真机合计约 8–10 个实验日，比 PACE 方案略多。原因是在线适应每次都要"先跑一段适应，再跑一段评估"。

### 19. 风险与应对

| 风险 | 应对 |
|---|---|
| Go2-W 上用 off-policy 方法训练的步态无法部署（FastTD3 已有步态崩坏类 issue） | 改用 PPO 策略加事后拟合的 Q 型 critic；还不行，就只在仿真中对适配器做有奖励的对照，真机只做评估型论文 |
| 在强基线上没有额外收益 | 论文改为"系统评估 + critic 失效分析"。【评价】这类负结果的发表价值，弱于 PACE 方案"差距归因"的负结果 |
| 真机在线更新不安全 | 改成"跑一段 → 停下 → 更新 → 再跑"的少样本模式，仍符合"少样本调整"的题意 |
| 效应小于测量噪声 | 事先算好最小可检测效应；增加重复次数；优先选偏移大的条件（8 kg、地毯） |
| 底层控制权限不可用 | 与 PACE 方案相同的第 0 周关卡；若不可用，两个方案都要调整 |
| 电机发热、电池电压混入结果 | 记录温度和电压；条件顺序随机；单次运行时间要短 |
| 被 TEMPO 或 SHOES 团队抢先 | 尽早开展；突出"轮足 + 强基线 + 不变坏 + 传统控制对比" |

### 20. 查重：设想的创新点是否已被覆盖

**检索时间与范围**：2026-11-25。检索了：
- arXiv 摘要页，部分论文的 PDF 全文；
- NeurIPS 2026 会议页；
- GitHub API（搜索 TEMPO、SHOES 的代码）；
- 网页搜索，多组关键词：test-time adaptation locomotion、wheel-legged online adaptation、reward-free frozen critic adapter、Go2-W adaptation；
- 整理列表 [Awesome-Test-Time-Robot-Learning](https://github.com/Oliverbansk/Awesome-Test-Time-Robot-Learning)（2026-11-23 更新）。

**没有系统翻阅 CoRL / ICRA / RSS / NeurIPS 2026 的全部论文集，也没有检索中文期刊。**所以只能说"检索范围内没看到"，不能说"没人做过"。

**先正面回应仓库已有的结论**：[候选比较 §4](../../04_research/review.CN.md) 已经记录，"历史编码器 + 自适应策略""冻结策略 + 门控/有界残差""变化检测 + 工况召回"这些组合都已被占据。本方案**不把这些组合当作贡献**：历史编码器是基线，有界适配器和守护是借鉴来的部件。我们问的是另一个问题：**策略已经有历史编码器、已经很强时，部署期再更新参数还能不能带来额外收益？在轮足实机上怎样做到"不变坏"？**

| 设想的点 | 最接近的工作 | 状态 | 覆盖程度【评价】 |
|---|---|---|---|
| 冻结 critic 当替身，无奖励更新策略 | [TEMPO](https://arxiv.org/abs/2610.20318) | NeurIPS 2026 poster | **完全覆盖**（就是基础论文） |
| 用预训练 Q 函数约束测试时微调 | [Value Conditioned Policy Fine Tuning](https://icml.cc/virtual/2025/48086)（Pandya 等） | ICML 2025 测试时适应研讨会（PUT）poster；只在 MuJoCo 仿真（会议页摘要） | 思路相近；不是运动控制，也没有实机 |
| 有界、恒等初始化的适配器 | [SHOES](https://arxiv.org/abs/2610.16457) | 自述 CoRL 2026 | 结构已有。但 SHOES 用奖励加 T265，**不是无奖励**；和 TEMPO 目标结合，检索范围内没看到 |
| 低秩适配器 + 安全恢复的真机微调 | [SLowRL](https://arxiv.org/abs/2603.17092) | 预印本 | 需要奖励，是训练式微调 |
| 冻结策略 + 有界残差 + 门控 | [SARA](https://arxiv.org/abs/2603.07775v2) | 预印本（v2） | 门控思想已有。它用在线性能信号和跟踪参考，不是完全无奖励；轮式平台只在 AgileX Scout Mini 上做了**一次**可行性试验（其表 4 注释） |
| "更新可能让机器人变差"，保留"什么都没变"的假设 | [RoboAda](https://arxiv.org/abs/2611.30209) | 预印本（2026-11-23），操作任务 | 动机直接相关；方法不同：不做梯度更新，而是用逆动力学修正指令 |
| RMA 式显式辨识负载和关节受限 | [Rapid Embodiment Adaptation](https://arxiv.org/abs/2608.01506) | 预印本 | 属于历史编码器一类，作基线参考 |
| 轮足上的适应 | [LocoFormer](https://arxiv.org/abs/2509.23745)（CoRL 2025，Go2-W 实机，上下文适应，不更新权重）；[RACER](https://arxiv.org/abs/2610.07409)（预印本，Go2W 实机；低秩适配的是**规划器的残差动力学**，不是策略） | — | 轮足适应已有工作，但没看到"部署期无奖励更新策略" |
| 真机在线 RL 的设计选择 | [What Matters for Simulation to Online RL on Real Robots](https://arxiv.org/abs/2602.20220)（As 等，ETH） | 预印本 | 是有奖励的在线 RL，平台包括 Go1 等；可借鉴其中的稳定化经验 |
| 世界模型的真实世界适应 | SimDist（RSS 2026）、DreamTIP（ICRA 2026）、[Reward-Free Continual Adaptation for Space Robots](https://arxiv.org/abs/2608.23452)（SPAICE 2026） | — | 路线不同：更新的是世界模型，不是策略 |
| 可部署增强 critic（轮速推算速度 + 打滑指标） | 检索范围内没看到 | — | **没看到覆盖**；但属于工程适配，单独作为贡献偏弱 |
| 在轮足实机上以历史编码器为基线评估无奖励 TTA | 检索范围内没看到 | — | **没看到覆盖** |

**结论【评价】**：部分覆盖。核心算法（TEMPO）、有界适配器（SHOES）、门控和回退的思想（SARA、RoboAda）都有先例。**"轮足实机 + 强基线 + 无奖励 + 不变坏"这个组合及其评估，检索范围内没看到。**创新属于"有明确动机的方法结合 + 面向轮足的适配 + 受控实验"，符合 STATUS 中 2026-11-25 用户确认的标准；但创新强度低于 PACE 方案的"检验顶刊主张在轮子上是否成立"。

## 第四部分：老师可能会问的问题

| 问题 | 回答要点 |
|---|---|
| 扰动适应方向不是已经被做烂了吗？ | 是的。历史编码器、门控残差、工况召回都有先例，我们不把它们当贡献：历史编码器是基线，门控是借鉴的部件。我们问的是：在这些方法之上，部署期再更新参数还有没有用？在轮足实机上能不能保证不变坏？这样的评估在轮足实机上检索范围内没看到 |
| 为什么选 TEMPO，而不是 SHOES 或 SimDist？ | SHOES 需要奖励，奖励来自外部 T265 测速，还要 GPU 训练。SimDist 需要外接 RTX 4090 笔记本做实时规划。TEMPO 不用奖励、不用外部测量，在 Go2 的 4 个 CPU 核上就能跑（p17），最贴合"部署时"的设定 |
| 已经有 RMA/HIM 了，为什么还要在线更新？ | 历史编码器只能"认出"训练时见过的变化范围，超出范围也会失效（TEMPO p5 相关工作的论点）。TEMPO 在仿真中显示，叠加在 RMA 之上还有提升（p9 图 5），但只有图没有数字，也没有实机证据。这正是我们要检验的 |
| 真机上边跑边改网络，不危险吗？ | 危险，TEMPO 原文也没有安全设计。我们的做法：只改两个有界的小模块，初始时和原策略完全一样；独立守护一发现变差就退回原策略；先在 MuJoCo 假真机上测试，过了第 9 周关卡才上真机；真机低速、拴安全绳、两人看护、配急停。若仍不安全，改成"停下来再更新"的少样本模式 |
| 加负载后速度变慢，加一个积分项不就行了？ | 对简单的速度偏差，积分项很可能就够了，我们会把它作为基线放进同一个实验。学习方法的潜在价值是能同时调整 16 个关节的协调（例如偏置负载时的姿态），这要靠数据说话，不预设结论 |
| critic 是用仿真奖励训练的，仿真和真机不一样，它的打分可信吗？ | 这是 TEMPO 的核心假设，作者也承认这是主要局限（p17）。我们设计了增强 critic，并专门分析打滑时 critic 失准的情况；守护不依赖 critic，防止被它带偏 |
| 如果实验结果是"没有提升"呢？ | 论文改为"无奖励测试时适应在轮足实机上的系统评估与失效分析"。但要坦白：这种负结果的价值弱于 PACE 方案的"差距归因" |
| 需要什么条件？ | 与 PACE 方案基本相同（底层控制权限、场地、相机 + AprilTag），不需要悬吊架。额外需要 4–8 kg 配重块、2–3 种地面材料，以及更多实机时间（约 8–10 个实验日） |
| 能和 PACE 方案结合吗？ | 可以。PACE 让仿真更准，TEMPO 应对部署后才出现的变化，两者互补。但 3–4 个月内同时做两条线不现实，建议二选一，另一条写进"未来工作" |
