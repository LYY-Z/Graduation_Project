## 2. 基础论文精读：GRAM

*GRAM: Generalization in Deep RL with a Robust Adaptation Module*。Queeney、Cai、Schperberg、Corcodel、Benosman、How（MERL、MIT、Amazon Robotics）。IEEE RA-L 11(2):2218–2225，2026，DOI 10.1109/LRA.2025.3641155。

| 环节 | 内容 |
|---|---|
| 作者的问题 | 【作者】动力学泛化：训练时可获得环境上下文（摩擦、质量等），部署时不可得。希望一个策略既在训练分布内表现好，又能应对分布外情况（p.2，式 1–2） |
| 已有局限与挑战 | 【作者】①情境 RL / 教师—学生（如 RMA）："适应只在训练见过的范围内可靠"（p.1）；②鲁棒 RL / 对抗训练：鲁棒，但"以分布内的保守表现为代价"（p.1）；③难点是"用单个策略同时做到两者"（p.2） |
| 方法设计 | 基础：RMA 式教师—学生 + PPO + 对抗 RL。新增三项：①**鲁棒适应模块**：适应网络换成认知不确定性网络（epinet），用 8 次随机采样得到估计的均值与方差（式 5）；②**按不确定性混合**：最终表示 = (1−α)·鲁棒表示 + α·适应估计，α = exp(−(σ̂² − β)⁺)，鲁棒表示为 0（式 9）。不确定时退向鲁棒；③**联合训练**：并行环境交替做"适应训练"和"带对抗推力的鲁棒训练"，共用一个策略网络（p.4） |
| 回退机制（关键） | **整体回退**：对 8 维隐变量逐维算方差后求和成**一个标量**（式 6–7），α 也是标量，整个隐变量一起缩放（代码已核实）。α 随时间变化，所以同一条轨迹中可以时而适应、时而保守（p.6，图 4） |
| 任务与训练 | Go2 跟踪速度指令。观测为关节角、关节速度、投影重力、基座角速度；动作为 12 维目标关节角，PD 控制 200 Hz，策略 50 Hz；历史 16 步，隐变量 8 维（表 I）。训练上下文 26 维：摩擦、附加质量、12 维电机强度、12 维关节零偏（表 II）。部署只用本体历史，不需特权信息 |
| Benchmark | Isaac Lab 仿真 + Go2 真机。训练在平地上。测试分近分布外与远分布外：6 / 9 kg 负载、5° / 10° 坡、5 / 10 cm 粗糙地、关节冻结（p.5）。运行中变化：仿真中第 10 s 加 9 kg（图 4）；真机走上泡沫和湿滑白板。真机 7 个场景 × 3 种方法 × 每种 5 次，共 105 次（p.7） |
| Baseline | 鲁棒 RL、情境 RL、域随机化（足式泛化的常用方案），以及三个消融（p.5–6） |
| 关键结果 | 归一化回报（分布内 / 近外 / 远外）：GRAM 0.92 / 0.79 / 0.58；鲁棒 RL 0.87 / 0.74 / 0.59；情境 RL 0.94 / 0.75 / 0.42；域随机化 0.93 / 0.74 / 0.43（表 III）。真机困难场景成功次数：GRAM 15/15，鲁棒 RL 12/15，情境 RL 2/15（表 V） |
| 贡献与局限 | 【作者】局限：分布外泛化取决于对抗者对最坏动力学的覆盖，只试了标准对抗者和四足（p.8）。【评价】①**回退是整体的**：只有一个因素异常时，其余可信因素的适应信息也被丢掉，这是本课题的切入点；②鲁棒分支只用"推力"对抗训练，没有针对质量、摩擦、电机的分布外训练；③远分布外上 GRAM（0.58）与鲁棒 RL（0.59）相当；近分布外上一个消融（0.80）略高于 GRAM（0.79）；④未给仿真种子数 |
| 代码与复现 | 有官方训练和评估代码（6 种算法、两种训练范围），**无预训练权重、无真机代码，也没有"运行中加负载"的代码**。基于 Isaac Lab 1.0 / Isaac Sim 4.1 / torch 2.2，要迁移到 Isaac Lab 2.3 / Isaac Sim 5.1 才能在服务器 Blackwell 显卡上运行。估计迁移并跑通约 1–2 周（rsl_rl 接口变化是主要工作），再用 1 周对齐表 III 趋势。另有一处代码与论文不一致：默认用 base 网络输出而非采样均值做缩放 |

## 3. 研究方案

### 3.1 研究问题

运行中发生**局部**动力学变化时，能否**保留仍可信的适应信息，只对不可信的部分保守**，从而比 GRAM 的整体回退表现更好？

**举例**：Go2-W 已经适应了当前地面和负载，途中右前轮驱动突然变弱。GRAM 会把整个适应估计一起弱化，变得保守。可地面和负载的信息大部分仍然有用。更合理的做法是：保留这部分，只对轮驱动采取保守处理，并由同一个全身策略协调腿和轮去补偿。

### 3.2 挑战

1. **因素能否区分**：一个轮子变弱会同时改变机身姿态和接触。仅凭 16 步本体历史，"轮子变弱"和"地面变滑"未必能分开。
2. **部分回退的组合没训练过**：如果训练时没见过"某组置零、某组保留"的输入，推理时直接拼接反而可能更差。
3. **鲁棒训练信号**：GRAM 只用推力对抗训练鲁棒性，没有针对某一组因素的分布外训练。
4. **轮足适配**：16 个关节，轮子是速度控制，奖励与执行器都要重做。

### 3.3 针对性设计【设想】

| 挑战 | 设计 | 代码切入点（据代码审查） |
|---|---|---|
| 因素能否区分 | 先只分 2 组：环境（摩擦、负载）与执行器（轮驱动）；隐变量拆为 4 + 4 维；每组单独算不确定性和回退系数 | 上下文按组排序（`context_env_wrapper.py`）；不确定性按组切片（`gram_actor_critic.py` L688–696）；α 改为向量（L620–628、L720–739） |
| 组合没训练过 | 训练时按组随机置零，让策略见过所有"部分可信"组合 | `robust_masks` 从每环境 1 维改为每组 1 维（runner L198–219） |
| 鲁棒训练信号 | 对被标为不可信的组，把该组上下文采样扩到分布外，其余组保持分布内 | 参考仓库已有的 wide 配置（`unitree_go2_cfg.py`） |
| 运行中变化 | 自写"运行中改质量、改摩擦、改单轮驱动增益"的事件（原仓库没有） | `envs_utils.py` 新增事件 |
| 轮足适配 | 腿用位置动作、轮用速度动作；16 维观测；重写执行器与奖励 | 动作项、执行器配置、奖励配置 |

### 3.4 实验

**变化类型**（均在运行中发生）：单轮驱动增益下降、单轮锁死、负载突变、地面摩擦突变，以及它们的组合。测试时使用训练中没见过的幅度和组合。

**对比**：

| 组 | 作用 |
|---|---|
| 充分随机化训练的历史策略 | 最常用的强基线 |
| 原版 GRAM（整体回退） | 基础论文 |
| 分组但不做选择性回退 | 检验"分组"本身是否就够 |
| 变化检测 + 历史重置 | 简单替代方法 |
| 传统控制：驱动响应估计 + 降速补偿 + 轮速重分配 | 回应传统控制方向 |
| 理想上限：直接告诉策略哪组可信 | 检验机制的上限 |
| 本文方法 + 消融 | — |

**指标**：速度跟踪误差、路线完成率、变化后的恢复时间、摔倒次数，以及**正常情况下的性能代价**（防止"更鲁棒"是靠全程保守换来的）。

**统计**：仿真每条件多个训练种子，并报告种子数（补上 GRAM 原文的不足）；真机每条件 ≥ 5 次，配对、随机顺序。

### 3.5 与传统控制的关系

1. 本方法类似"部分故障下的可重构控制"：已知哪部分可信就用、不可信就保守，这正是容错控制的思路，只是由学习完成判断和协调。
2. 实验中直接放入传统方法：估计驱动响应，再降速并重新分配各轮转速。
3. 不声称"学习优于传统控制"，按变化类型分别报告各自的适用情形。

### 3.7 风险与应对

| 风险 | 应对 |
|---|---|
| 因素不可区分 | 理想上限检验先行；不可区分时如实报告，并转为"可区分程度"的分析 |
| 迁移耗时超出预期 | 第 1 周评估；必要时先在旧环境中用 CPU 小规模验证思路 |
| 原代码无权重、无运行中变化 | 自行训练，自写运行中变化事件，在论文中写明 |
| 被认为只是"把标量改成向量" | 贡献落在"部分可信条件下的鲁棒训练"和系统的消融证据上，而不是回退系数本身 |

**措辞**：不能宣称首次解耦、首次不确定性适应或首次选择性鲁棒化。相关工作有 DMCM（CoRL 2025，多因素上下文解耦）、CERTAIN（ICML 2025，上下文不确定性）、Robust Factored MDPs（AAAI 2026），均已核实存在。贡献限定为：面向运行中的局部变化，把因素可信度与条件鲁棒训练结合起来，用于轮足控制。

## 4. 老师可能问的问题

| 问题 | 回答要点 |
|---|---|
| 创新是不是只把一个系数改成了几个？ | 不是。只改系数，推理时会出现训练没见过的组合，反而可能更差。核心是"部分信息可信条件下的鲁棒训练"，并用"分组不回退""整体回退""理想上限"等消融证明贡献来自哪里 |
| 为什么不用域随机化？ | 它是对照组之一。在相同训练范围和预算下比较，检查改进是否超出充分随机化的收益 |
| 为什么不用传统控制？ | 传统的驱动响应估计 + 降速 + 轮速重分配作为基线放进实验，不预设学习更好 |
| GRAM 代码能直接跑吗？ | 不能。它基于旧版 Isaac Lab，需要迁移，第 1 周评估；它也没有权重和运行中变化的代码，需要自补 |
| 因素分不开怎么办？ | 第 2–4 周的理想上限检验先回答"分开了是否有用"；实际分不开时，如实报告可区分的边界，转为保底 |
| 和老师给的其他论文的关系？ | GRAM 是老师给的论文；RMA 是它的基础；LocoFormer、ESCP、SADL 等是相关工作（见 §1） |
