# Go2-W 与 UR7e 运动控制：阶段文献比较

> 阶段记录（2026-11-22）：以下论文、分类和建议反映当时已查到的资料，不是最终候选或后续检索边界。可随新文献和核验结果替换、修正。

本报告服务于课题选择：先复现可靠的公开方法，再研究运行中扰动后的恢复。检索与源码审查截至 2026-11-22；未进行安装、训练、性能复现或硬件验证。以下“可迁移”是依据方法和接口作出的工程判断，不是已有实验结果。

## 1. 这份比较如何使用

以下材料是截至 2026-11-22 的阶段性调查，按历史策略、通用连续控制与在线动力学三类比较。TAM、GRAM、SADL 等均为当前样本，可继续增加、替换和推翻原有排序；不限定强化学习，不预设最终共享一套权重或分别训练。

现有证据尚不足以确认一篇同时满足“官方完整发布、多类运行中扰动、Go2-W 与独立机械臂直接支持、迁移成本低”的方法。这不等于全网不存在，也不应成为停止调研的理由。评估时应分别判断原任务可运行、论文结果可对齐和目标硬件可部署，不能相互替代。

下文保留各方法的证据和代价，作为继续比较的起点；GPU 兼容性、部署可用观测与控制接口要独立审查。

## 2. 三个候选分别解决什么

### 2.1 GRAM：适应有效时利用历史，不可靠时保持鲁棒控制

[论文](https://www.merl.com/publications/docs/TR2026-057.pdf) · [官方代码](https://github.com/merlresearch/gram)

**问题。** 普通域随机化能提升鲁棒性，但可能牺牲性能；依赖历史估计动力学的策略，在训练分布外可能估计错误。GRAM把这两种需求放进同一训练框架。

**方法。** 用历史估计控制所需的环境表示，并结合不确定性处理分布外情况；基于强化学习训练。部署时主要进行历史条件化推断，不应描述为每个控制步都在线进行 PPO 更新。

**相关实验证据。** 最终论文含运行中添加负载及困难地面变化，确实比只在回合开始换参数更贴近本项目。

**代码程度。** 有训练、策略、环境和评估实现。默认 CLI 和事件配置不能直接等同论文每条突变曲线；指定时间的故障调度和恢复统计仍需核对、补充。

**主要限制。** 当前实现的任务与动作围绕普通四足关节位置控制。对 Go2-W 应增加四个轮速度通道；对 UR7e 应重建机械臂观察、目标、奖励和控制器。其“目标固定”故障与“输出力矩丢失”故障是不同实现，不能都叫断电。

**判断。** 适合首先验证核心训练方法和鲁棒/适应对照，再逐平台迁移。原任务复现与双平台移植应分开汇报。

### 2.2 ESCP：明确研究连续运行中的物理参数突变

[论文](https://cdn.aaai.org/ojs/20730/20730-13-24743-1-2-20220628.pdf) · [官方代码](https://github.com/FanmingL/ESCP)

**问题。** 条件改变后，历史信息会过时；如何让策略快速重新判断当前环境？

**方法。** SAC策略结合短时 GRU 环境表征，并用表征学习目标区分不同训练域。部署不输入真实物理参数或故障标签。训练时模拟域分组标签参与表征学习，这与部署要求已知故障不是一回事。

**代码证据。** 非平稳评估在运行中修改重力、阻尼等参数，保留身体状态与策略历史；不是通过重置机器人模拟变化。原默认训练域在单回合内固定，连续变化主要在评估时检验。

**主要限制。** 测试整机参数变化不等于已验证全部电机故障。代码较旧，适配现代接口有维护成本；没有现成 Go2-W 或 UR7e 环境及权重。

**判断。** 算法对连续观察、动作的维数没有强绑定，比强依赖固定机械结构的控制器更容易分别移植。但“参数维数可配置”只解决网络形状，动作语义、归一化、奖励和硬件控制仍需自己实现。

### 2.3 Situationally-Aware Dynamics Learning：工况识别与条件动力学

[论文](https://arxiv.org/html/2505.19574v2) · [官方代码](https://github.com/AlejandroMllo/situationally_aware_dynamics_learning)

**问题。** 一份不断混合旧数据与新数据的动力学模型，可能无法适应变化，也容易遗忘不同工况。

**方法。** 训练阶段建立不同工况的动力学表示与条件模型；测试阶段依据近期转移识别匹配工况，并用 MPPI 规划。应区分测试时工况匹配与重新更新模型参数，不宜笼统称为每步在线学习权重。它属于模型驱动控制，不是 PPO 类策略强化学习。

**公开材料。** 有数据、模型、训练与评估代码；论文包含地面和空中系统，发布可直接追踪的示例集中 QuadX。

**代码风险。** 已发现模式切换方法缺失、验证集回退和默认回合时长与风扰动发生时刻不匹配等问题。部分属于局部修复，不能据此说整个算法不存在；但也不能承诺原样运行即可复现全部实验。

**迁移难点。** Go2-W 的接触动力学和机械臂任务需建立各自状态—动作模型；直接对 16 维动作做在线规划的计算负担必须实测。它更适合作为模型适应方向的候选，而非当前最省时的 RL 主线。

## 3. 其他值得保留的方法及其正确用途

| 论文 | 公开材料与主要价值 | 为什么不是当前最优先的共同底座 |
|---|---|---|
| [TAM，CoRL 2026](https://github.com/Dongwon-Son/TAM) | 官方力矩适配训练与仿真链；历史条件化残差力矩 | 底层力矩和理想动力学合同明确；实机控制桥接未公开，轮足接触迁移较重。适配模块本身不是RL |
| [UARL，RA-L 2026](https://github.com/lakshitadodeja/uncertainty_aware_residual_rl) | 不确定性引导残差 SAC，有训练入口和公开基策略/数据链接 | 实验主要是操作任务和 sim-to-real，不是未知运行中故障；两平台都要先准备 nominal 策略 |
| [RecoveryChaining，IROS 2025](https://github.com/shivamvats/recovery-chaining) | 从失败状态学习恢复技能并接回原控制器；机械臂价值高 | 恢复对象偏任务失败、接触与物体状态，不等价于执行器动力学突变 |
| [SimDist，RSS 2026](https://github.com/CLeARoboticsLab/simdist) | 仿真预训练世界模型、真实数据适配与腿式部署链 | 真实数据适配与瞬时未知故障不同；机械臂发布范围须独立核对 |
| [FADA，CoRL 2026](https://github.com/LeCAR-Lab/FADA) | 运动意图与执行动力学解耦，少量数据适配执行器 | 主要为离线少样本适配；要求已有策略能产生可用运动，不是跌倒后即时恢复 |
| [OCCAM，CoRL 2024](https://github.com/Hersh500/occam) | 在线优化控制器参数，层级接口便于分别接入硬件 | 依赖可调低层控制器，适应时间尺度较长；不直接重建失效后的全身控制 |
| [OSCAR，ICRA 2022](https://github.com/NVlabs/oscar) | 结构化动力学与力矩控制，训练/评估资料丰富 | 机械臂优势明显；轮足浮动基座、接触和力矩接口需较大改造 |
| [GrBAL / ReBAL，ICLR 2019](https://github.com/iclavera/learning_to_adapt) | 老但直接的动态环境模型适应基线，包含不同连续控制系统 | TF1 与早期 MuJoCo 栈维护成本高；不应因为经典就假定复现更轻松 |
| [TARC，CoRL 2026](https://github.com/arnavsukhija/tarc) | PPO 同时选择动作和持续时间，公开训练、包装器及结果 | 解决控制频率分配，未解决一般故障辨识；实机部署文档仍有 TODO |

这些项目的“有训练代码”均不表示本轮已经运行成功。需要进一步验证依赖、资产和标准任务训练结果。

## 4. 新查重结果对创新选题的约束

不能直接把以下组合称为首次提出：

- 历史编码器 + 自适应策略：已有 ESCP、RMA 类与 GRAM。
- 冻结基策略 + 不确定性门控残差RL：已有 UARL。
- 变化检测 + 历史工况或模型召回：已有 MBCD、MOCA、Situationally-Aware Dynamics Learning。
- 主动采集对控制有用的数据：已有 SPI-Active、QOED 等，需要比较具体目标和实验条件。
- 按需提高控制频率：已有 TARC。

新增的 [CAPABLE 预印本](https://arxiv.org/abs/2610.11971)尤其相关：它已研究共享关节历史编码、运动学条件和残差 SAC，以适应未知受损关节。因此“跨关节共享历史特征后补偿动作”不是一个足够的新贡献。本次作者项目页尚未给出可核实的完整代码链接，不能把它列为已经认证的正式主复现底座；但**未公开代码也不影响它作为创新查重对象**。

## 5. 两个平台的输入输出怎样落地

下表说明分别建立平台合同的一种路线；是否进一步共享编码器或权重，需由具体论文及研究问题决定：

| 项目 | Go2-W | UR7e |
|---|---|---|
| 观察基础 | IMU、关节位置/速度、轮速度、目标车体运动、近期执行动作 | 6轴关节位置/速度、末端状态、目标轨迹、近期执行动作 |
| 特别要核实 | 低层控制时车体线速度来源；轮位置信息如何表示 | 力矩反馈的单位/含义；控制器是否内置重力补偿 |
| 第一版动作 | 腿12个位置目标 + 轮4个速度目标 | 6轴位置/速度目标，或经实际接口确认的关节力矩 |
| 共同研究对象 | 含底层控制器的指令—响应系统如何在扰动后恢复 | 同左，但不用假设身体运动学相同 |
| 需要分别训练 | 观察归一化、策略权重、任务奖励、故障范围 | 同左 |

若选 TAM / OSCAR 类力矩方法，必须沿其力矩合同实现，不能用 `servoJ` 位置指令替代后声称原方法已复现。若选历史条件化 RL，则可在混合位置/速度控制层建模，但必须把该闭环动力学定义清楚。

## 6. 可继续讨论的研究问题

以下是由现有材料归纳的一项可对照问题，不排除其他更有价值的方向：

> **在没有故障标签、切换时刻提示的情况下，机器人遇到运行中执行能力与接触条件变化时，如何利用有限历史，及时恢复可行运动，并避免错误适应进一步降低表现？**

可以围绕“历史的快速更新与稳定利用”“控制权限受限时的恢复目标”“执行器变化和外部接触变化的区别”继续缩小。但这仍是研究问题，不应提前包装为已确认首创的算法。已有查重表明，变化检测、残差、上下层分工、信息收益等单独概念均有大量先例。

工作量需要与本科阶段的资源匹配：优先把研究问题、对照和方法贡献做清楚，再决定模块数量和实验范围，不以跨平台数量代替创新。

## 7. 后续进入复现时的顺序

1. **原任务最小复现。** 固定官方提交与依赖，先跑主候选原生任务；记录实际训练预算和论文指标，区分核心算法复现与整篇论文复现。
2. **Go2-W 标称控制。** 在既有轮足仿真/部署工程上确认观察和16通道动作，获得无扰动下可靠基线。
3. **统一突变协议。** 在连续状态下改变执行效率、时延、负载或接触；不重置身体，不向 actor 输入故障标签。先验证每种扰动的物理实现。
4. **UR7e 对应任务。** 采用简单轨迹或位置跟踪，分别训练同算法。锁死一个关节后不能继续要求任意不可达6维末端任务，应明确可行性边界。
5. **机制研究。** 仅在基线已跑通后选择一个失败现象，设计必要修改，与原算法、普通鲁棒RL、同预算历史策略比较。
6. **硬件验证。** 仿真和实机分别报告结果，不把任务成功率、恢复时间与平均回报混成同一指标。

建议至少报告：扰动后的累计跟踪误差、恢复时间、失败率、正常工况表现，以及计算/交互预算。统计从扰动发生时开始，包含试探、切换或适应的成本。

## 8. 补充候选与复现成本

本节合并原补充审查中的版本条件及相关工作，不另设重复综述。以下定位为原审查时的判断。

### GRAM 的复现成本需要补上硬件软件兼容性

此前将 GRAM 列为现代强化学习优先候选，其方法相关性仍成立。但“论文发表于2026年”不等于代码使用2026年的软件栈。

官方提交 `ea3f26ce898d7fdae4cc51497b22e8361a1c3f02` 的 [README](https://github.com/merlresearch/gram/blob/ea3f26ce898d7fdae4cc51497b22e8361a1c3f02/README.md)要求 Isaac Lab 1.0.0、Isaac Sim 4.1.0.0、rsl_rl 2.0.0；[环境文件](https://github.com/merlresearch/gram/blob/ea3f26ce898d7fdae4cc51497b22e8361a1c3f02/environment.yaml)固定 Python 3.10、PyTorch 2.2.2、CUDA 11.8。

用户提供的 GPU 简称是 RTX PRO 5000 × 2。本轮没有连接服务器确认完整型号。**如果实际为 Blackwell 版本，不能承诺照抄这份旧环境即可使用 GPU 训练。** [PyTorch 官方2.7发布说明](https://pytorch.org/blog/pytorch-2-7/)才引入 Blackwell 与 CUDA 12.8 构建支持；[NVIDIA Blackwell兼容指南](https://docs.nvidia.com/cuda/pdf/Blackwell_Compatibility_Guide.pdf)说明旧 CUDA 应用能否兼容还取决于是否包含合适的 PTX。故不能把所有旧 CUDA 程序一概判为绝对不能运行，也不能认为容器或 Conda 可以自动解决 GPU 架构问题。

对本项目的影响：

1. 原始训练环境是否能运行，先于大规模训练预算评估。
2. 如果需要升级 Isaac Lab / PyTorch，必须把它作为显式的算法与环境移植工作。
3. 容器隔离依赖，但不更换GPU架构，也不免除主机驱动兼容性要求。
4. 本次没有安装、测试或修改服务器，不能声称已确认兼容。

因此，GRAM当前应称“方法相关性高、公开训练链明确的优先候选”，不应称“已确认在本服务器开箱运行的最低成本方案”。

### ReLCE：真实公开的残差RL参考，原实验不是中途故障

[正式论文：L4DC 2024](https://proceedings.mlr.press/v242/nakhaeinezhadfard24a.html) · [作者仓库](https://github.com/MohammadrezaNakhaei/ReLCE)

论文全名为《Residual Learning and Context Encoding for Adaptive Offline-to-Online Reinforcement Learning》。它先从离线数据训练基础策略，再用近期交互编码动力学条件，通过残差强化学习改善变化后的表现。

#### 方法与复现材料

提交 `1bfc2f9034d2f18be5250c86c463176d2dfc5c9e` 含离线训练、动力学模型、残差SAC、历史序列buffer、环境修改和在线训练入口。它并非只有方法框架或占位网页。

但 README 的残差命令写为 `train.py`，实际文件为 `train_relce.py`；依赖命令也有拼写错误。这些属于说明修复，不应扩大成“训练算法缺失”。在线训练入口需要先载入离线策略及动力学模型，因此还须准备原始离线训练阶段和数据。

#### 扰动时序的明确边界

原论文规定：每回合开始采样动力学参数，随后本回合保持不变。源码 [modify_env.py](https://github.com/MohammadrezaNakhaei/ReLCE/blob/1bfc2f9034d2f18be5250c86c463176d2dfc5c9e/utils/modify_env.py)也只在 `reset()` 修改质量与阻尼，`step()`直接转发动作。

因此可以参考其“离线基策略＋历史表征＋残差SAC”的实现，但不能称其原结果已经证明运行中突然故障恢复。若新增中途变化，还应检查序列buffer与表征一致性损失是否错误地把跨变化的数据当成同一工况。

#### 两平台的适用性

算法读取连续观察/动作维数，具备分别重训的实现基础。但没有现成Go2-W或UR7e任务；两平台需要各自的离线数据、基础策略和观察动作合同。相较不依赖预训练基策略的ESCP，前置工作更多。

定位：**值得保留的残差适应实现及创新查重对象，作为继续比较的样本。**

### DOMINO：复合动力学表征已有正式研究

[NeurIPS 2022正式论文](https://proceedings.neurips.cc/paper_files/paper/2022/hash/b0b1cfc8ede53f452cabf8b9cf4eef76-Abstract-Conference.html) · [作者名下MindSpore实现](https://github.com/YaoMarkMu/DOMINO_Mindspore)

DOMINO研究多个动力学因素同时影响运动时，如何学习解耦的context。它结合互信息目标与状态转移预测，可服务于模型驱动或模型无关控制。它对“把多个扰动因素拆开表示，再适应复合变化”的创新主张构成直接相关工作。

审查提交 `244131404622f154ab671971d215cef6c1021375`：有环境、模型训练、MPC控制器、采样器与推理入口；README要求Python3.7.5、MindSpore GPU1.8.1、CUDA11.1。不能把这个版本当成现代PyTorch训练工程。

`ant_cripple_env.py`中的损伤包括动作mask及几何修改。对真实Go2-W，必须区分改变形态、关节失去力矩和位置目标固定；不能用同一个“故障”名称直接迁移其物理含义。

定位：**复合扰动表征与解耦学习的重要先例；旧软件栈、MPC示例和原任务边界使其更适合作为对照或模块参考。**

### 新近直接相关工作：Stability-Aligned Residual Adaptation

[2026年9月修订论文](https://arxiv.org/abs/2603.07775v2)
