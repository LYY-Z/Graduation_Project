# 02 网络内部计算与长记忆

本篇解决一类贯穿学习过程的疑问：网络内部都是数字，为什么它可以利用多个时间点的信息？从最小的数组开始，依次解释token、QKV、segment、SG和实时缓存。

<a id="tensors"></a>
## 1. 网络、模型和参数分别从哪里来

PyTorch提供线性层、激活函数、张量运算和自动求导等工具。项目代码调用这些工具，把输入MLP、Transformer和Actor/Critic组合成模型。

```python
layer = nn.Linear(2, 4)
y = layer(x)
```

第一行创建层，并分配权重、偏置的存放位置；第二行用已有权重计算输出。同一个层可以处理很多次不同输入，不需要每次创建。

数学上：

\[
y_j=\sum_i W_{ji}x_i+b_j.
\]

权重初值由初始化规则给出，随后训练修改。checkpoint保存训练后这些数组等状态。网络结构由代码构造，权重由初始化或checkpoint提供，输入则由本次环境观测提供。

**模型对象不是checkpoint文件本身。** 创建对象准备计算结构，再把权重加载到相应层；配置决定维度和模块选择，权重决定这些模块具体怎样变换数字。

### 1.1 内部维度不是动作数量

例如2个输入数映射为4个特征：

```text
输入[关节角、速度]
→ 四组不同的加权计算
→ 得到4个内部特征
```

4个特征不是4个关节，也不一定分别有可命名的人类含义。把4改为64或256，作用是提供更丰富的内部表示。Microduck入口默认内部维度64；先前教学中的256不是论文统一设置。

<a id="forward"></a>
## 2. 一次网络调用的输入、内部计算和输出

论文确认的架构：

```text
观测 o_t
    ↓ 输入MLP
当前token x_t
    ↓ Transformer-XL，读取历史
当前隐藏表示 h_t
    ├─ Actor MLP：产生动作所需信息
    └─ Critic MLP：产生价值估计所需信息
```

token是某个时间位置的特征向量，不是自然语言单词，也不必是一个关节。这里通常一个时间位置对应一个观测token。

Actor先给动作分布所需参数，采集时再抽取实际动作。动作经过尺度、关节选择和底层控制，才产生身体响应。Critic预测未来回报，不直接控制关节。

形式上的历史策略可以依赖状态、动作序列。具体输入要看实现：Microduck的`observe()`包含`last_action`，因此即使独立的`embed_past_action=False`，也不能说它完全没有上一动作信息。

### 2.1 一段输入是多行观测

形状`[B,L,D_obs]`：

- B：并行序列数，Microduck默认12个环境。
- L：本次输入的时间位置数，训练通常16，逐步采集为1。
- D_obs：每个观测的数字数量。

输入MLP通常按最后一维做共享变换，输出`[B,L,d]`。时间行数不因特征映射而改变。

“同一个线性层处理每一行”，表示使用同一组W和b，可以通过一次矩阵运算处理多行。它不要求Python写16次不同的层，也不意味着输出行彼此没有时间关系。

<a id="qkv"></a>
## 3. Q、K、V为什么这样计算

当前表示和历史表示都是向量。注意力要完成两件事：给可读取位置分配权重，再组合它们提供的内容。

\[
Q=HW_Q,\qquad K=\widetilde H W_K,\qquad V=\widetilde H W_V.
\]

- H：当前段上一层的表示。
- \(\widetilde H\)：旧历史与当前段的扩展材料。
- \(W_Q,W_K,W_V\)：训练参数，分别学习查询、匹配和内容的变换。
- Q/K/V：本次输入经过参数计算出的结果，会随输入变化。

“查询、匹配、内容”是对功能的解释；实际没有人给每个位置写一条中文问题或人工标签。

### 3.1 一行矩阵乘法怎样算

教学输入\(h=[2,1]\)，假设：

\[
W_Q=\begin{bmatrix}1&0\\0&2\end{bmatrix}.
\]

则\(q=hW_Q=[2,2]\)。同一h经过另一组W_K、W_V，可以得到其他向量。相同输入通过不同权重承担不同作用，并不矛盾。

实际W不是人工填出后永远固定；训练根据最终损失反向传播来修改。

### 3.2 为什么用Q和K相乘

常见匹配分数是点积：

\[
e_{tj}=q_t\cdot k_j/\sqrt{d_k}.
\]

点积把两个向量的对应分量相乘再相加，得到一个匹配数。它是方便、可微、可并行的一种设计选择，不是唯一可能的匹配方式。

关键是W_Q、W_K会被训练调整，让对任务有用的位置组合更容易获得相应分数。不能仅凭未训练向量的某次点积，保证它真的具有“相关性”语义。

例如q=[1,0]，候选k分别为[2,0]、[0,1]，未缩放点积为2和0。第二个分量此时不影响匹配，因为q对应分量是0。

除以\(\sqrt{d_k}\)用于控制高维点积的尺度，避免softmax过度尖锐；它不是在把历史平均分成几份。

### 3.3 点积为什么能变成比例

点积先得到分数，不直接就是概率。softmax把允许位置的分数转换成非负且和为1的系数：

\[
\alpha_{tj}=\frac{e^{e_{tj}}}{\sum_{m\in\mathrm{allowed}}e^{e_{tm}}}.
\]

接着上面的二维例子，点积2和0除以\(\sqrt2\)，得到最终分数约1.414和0；softmax系数约为0.8044和0.1956。再组合对应Value：

\[
u_t=\sum_j\alpha_{tj}v_j.
\]

如果两个Value简化为10和4，组合约为\(0.8044\times10+0.1956\times4=8.8266\)。这个数字是内部特征，不是环境奖励，也不是Critic价值。

多个历史时间位置各自有K和V。当前位置的Q分别与它们匹配，产生一整行系数，再组合多个位置的V。不是把所有历史预先挤成唯一一个K。

### 3.4 权重怎样优化，改动会影响什么

损失沿“输出—隐藏表示—注意力—QKV变换”反向传播。改变W_Q/W_K会影响匹配分数及读取比例；改变W_V会影响实际读取的内容。它们共享最终任务训练信号，不需要另有人工QKV答案。

注意力系数\(\alpha_{tj}\)是本次计算结果，不是优化器直接保存的模型参数。同一层跨时间共享W，不表示所有网络层必须共用同一组W。

<a id="transformer-layer"></a>
## 4. 注意力之后为什么还有前馈网络、残差与归一化

注意力负责让位置之间交换信息。得到组合结果后，前馈网络继续对当前位置的特征做非线性变换，让已有信息形成更适合下一层或动作输出的表示。

例如，注意力可能读到“前几步目标改变”和“对应响应偏小”的线索，后续非线性网络有能力组合这些线索。具体神经元不保证可解释成固定的中文规则。

前馈网络通常是线性变换、激活、再线性变换。扩展再压缩是常见设计，提供非线性组合能力，不是机器人控制必须遵守的自然定律。

残差把当前输入与新计算结果相加，保留直接信息与梯度通路。归一化调节内部数值尺度，帮助训练稳定。各实现的层顺序、归一化和门控可能不同；不能把本地参考仓库的全部扩展说成论文明确配置。

位置编码或旋转位置机制提供顺序信息，使相同数值出现在不同时刻时能够获得不同的相对位置关系。它不向模型提供未来观测。

<a id="segment"></a>
## 5. segment是什么，为什么采集逐步输入而训练整段输入

segment是沿时间连续的一段序列，例如第1～16步。训练时真正送入网络的核心是这段观测，加上允许使用的历史缓存及相应边界信息。

保存的动作、旧概率、优势和回报目标随后用于损失。它们不自动全变成网络的观测输入。

### 5.1 采集：后续观测尚未产生

```text
已有o1 → 网络计算动作a1 → 环境执行 → 才得到o2
已有o2 → 网络计算动作a2 → 环境执行 → 才得到o3
```

不能为了先凑齐未来16步观测而等待，因为不先执行动作，后面的观测不会出现。当前实现每次送入一步，缓存供给历史；不满一段也照常输出动作。

采集时也可以设计成输入一段已经获得的历史，但不能输入尚未产生的未来。本地实现选择增量输入与缓存，避免反复重算全部历史。

### 5.2 训练：观测已经保存

交互结束后，o1～o16全部存在，可以组成数组一次输入。网络为每个位置输出动作分布与价值信息，用来求梯度，不向环境再次发送过去动作。

这也不是Diffusion Policy那样，一次规划新的未来动作序列。

### 5.3 整段一起输入，为什么能并行

某一层的输入表示在所有位置上已经准备好，因此可同时计算各行Q/K/V，进行矩阵匹配与Value组合。当前层位置3使用的，是这一层输入中位置1/2等提供的K/V，不必等位置1通过整个网络后再开始位置3。

层与层之间依次执行，同一层多个位置可以并行。

<a id="mask"></a>
## 6. 因果掩码：一起输入为什么不会偷看未来

四步教学段的读取范围：

| 当前输出 | o1 | o2 | o3 | o4 |
|---|---|---|---|---|
| 输出1 | 可读 | 屏蔽 | 屏蔽 | 屏蔽 |
| 输出2 | 可读 | 可读 | 屏蔽 | 屏蔽 |
| 输出3 | 可读 | 可读 | 可读 | 屏蔽 |
| 输出4 | 可读 | 可读 | 可读 | 可读 |

再加上允许读取的旧缓存。训练可以知道后来获得的奖励，把它作为评价过去动作的目标；但当前动作的前向计算不能读取未来观测。目标中使用未来回报，与输入中的因果约束是不同问题。

不同环境的batch行不互相读取。不同Episode之间也需要掩码隔离。论文中同一任务内多个Trial可以共享历史，不能见到“重置身体”就自动清掉所有信息。

<a id="sg"></a>
## 7. 论文公式（2）与SG：信息保留，旧计算链截断

\[
\widetilde h^{n-1}_{z+1}
=[\operatorname{SG}(h^{n-1}_z)\circ h^{n-1}_{z+1}].
\]

- z/z+1：前一段、当前段。
- n−1：用于当前层计算的上一层表示。
- \(\circ\)：沿时间维拼接，不是逐元素相加。
- SG：保留数值，但停止通过这份旧表示追溯其生成过程的梯度。

当前段Query来自当前表示，K/V由扩展材料得到。旧段表示此前已经受到更早历史影响，因而可能间接传递更早信息。

### 7.1 被截断和保留的路径

```text
当前段损失 → 当前段计算 → 当前可训练参数：保留

当前段损失 → 旧缓存 → 回到旧段生成过程：截断
```

当前读取旧表示时使用的W_K/W_V等权重，仍可获得梯度。SG不会把整个Transformer冻结。

前一段已经执行backward得到的梯度也不会因detach消失。梯度保存在参数`.grad`中，缓存是另一份数据。

### 7.2 为什么要这样设计

让旧段数值继续提供历史，控制需要保留的计算图长度和内存。代价是舍弃穿过旧表示生成链的跨段梯度，所以分段SG训练不等价于完整长序列的无限制反向传播。

共享参数仍会从每个当前段自身的损失学习。旧计算图不再追溯，不等于这些参数以后永远不能更新。

<a id="cache"></a>
## 8. segment、表示缓存、KV-cache不是同一个对象

| 名称 | 含义 |
|---|---|
| segment | 时间序列的一种分段组织方式 |
| 原始观测token | 观测编码后的当前输入 |
| 层间隐藏表示 | 已经经过部分网络计算的特征 |
| 表示缓存 | 保留旧层表示供后段计算 |
| KV-cache | 保留已经投影得到的K/V，减少重复计算 |

论文公式（2）强调隐藏表示缓存；实时推理进一步使用KV-cache。本地第三方实现的`TransformerMemory`还包含KV、记忆段、编号等结构，不应逐字段冒充论文公式。

### 8.1 为什么不保留旧segment以后每次重算

原始数据可以保留，但重复从头经过全部层会增加计算。缓存保存了某个阶段已经算出的结果，以便复用。

### 8.2 计算出KV以后，旧表示能不能删除

取决于后续计算是否仍需要它、缓存实现保留哪一级数据、是否还要反向传播或重算。不能仅凭“已经算过KV”统一删除所有旧段数据。

不再被后续逻辑引用的临时张量可以释放；仍作为历史输入的缓存要按容量策略淘汰。不是永远同时保留所有原始段、全部隐藏状态和全部KV。

### 8.3 新段会读取哪段历史

直接读取由缓存容量和掩码决定的最近材料；旧材料本身又可能包含更早信息。只说“参考上一个segment”遗漏了这种层间间接传播；说“完整读取从开始至今全部历史”又夸大了能力。

<a id="context-length"></a>
## 9. 约18秒和255步为什么不矛盾

论文给出的示例：6层，段长L=128，控制频率50Hz，最大可能历史影响896步，约17.92秒。

实时部署的KV-cache保留最近：

\[
2L-1=255\text{步},\qquad255/50=5.1\text{秒}.
\]

前者包括更深表示中的间接传播，后者描述直接保留的近期KV范围。O(NL)描述量级，不应直接拿N×L算出的数替代论文给出的最大范围。

“最大可能影响”不保证模型能精确复述18秒内的全部细节。信息可能衰减，任务也可能不需要这么长的历史。

<a id="boundaries"></a>
## 10. 边界与参数更新时序

| 事件 | 是否必然清缓存 | 是否必然更新参数 |
|---|---|---|
| 当前采集一步结束 | 否，通常追加缓存 | 否 |
| 当前segment结束 | 通常整理、截断或淘汰部分缓存 | 否 |
| 同一任务中的Trial重置 | 论文允许保留可用历史 | 否 |
| 论文Episode切换 | 应隔离其他任务信息 | 不由这个事件单独决定 |
| 完成一次`optim.step()` | 下一轮需按实现重建可用训练历史 | 是 |

Microduck训练入口的一次`ppo()`中，窗口顺序是：当前段前向→损失→backward→下一段。全部窗口结束后才更新一次参数。当前轮内参数一致，缓存数值不断变化。

下一轮`ppo()`从空缓存开始，用更新后的参数依次重建历史。不会把最后一段的缓存倒灌到新一轮第一段。

不满段的采集照常输入1步；最后一段训练可以较短。本地`forward()`还检查一次调用不能跨越当前配置的窗口边界，不能保持window16却直接塞256步。

当前Microduck入口每批采集重新创建`stateful_fwd`，因此不无限跨采集批次保留历史；这不是论文要求所有部署都这样重置。

## 11. 一个完整例子

段长取4仅作示意：

```text
采集：
o1→a1→o2→a2→o3→a3→o4→a4→o5……
每步调用网络，缓存逐步更新；每4步整理段边界。

训练：
[o1,o2,o3,o4] + 空/允许的历史
→ 四个位置的输出 → 各自损失 → backward
→ detach后的缓存
[o5,o6,o7,o8] + 上一段缓存
→ 四个位置的输出 → 各自损失 → backward
→ 全部数据处理后optim.step
```

这三个变化要分别说：环境交互改变身体状态；网络前向改变表示和缓存；优化器更新改变参数。
