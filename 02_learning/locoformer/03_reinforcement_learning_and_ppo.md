# 03 强化学习、GAE与PPO的完整计算链

本篇重点解决学习中最反复的阻塞：奖励不是正确动作标签；网络怎样根据经历调整概率；旧概率为什么固定；为什么重新前向；多条数据、多轮优化、segment和参数更新怎样连接。

阅读时始终区分三个阶段：**环境交互产生数据；前向和反向计算产生输出与梯度；优化器修改参数。**

<a id="rl-loop"></a>
## 1. 强化学习到底在做什么

一次交互是：

```text
观测及历史 → 策略输出动作分布 → 抽动作 → 环境执行
→ 新观测、奖励、结束标记 → 保存经历
```

重复多次，形成一批经历。随后利用这些经历计算训练损失、梯度并更新网络。再用更新后的策略收集新经历。

它不是每获得一个动作输出，就必须立即更新一次参数；也不是把输出先交给一个叫“强化学习”的模块变成正确动作。

PPO规定怎样利用这批交互经历训练Actor与Critic。机器人得到的训练反馈通常是奖励，没有人逐步提供“正确关节角度”。

### 1.1 Actor与Critic

Actor根据输入产生动作分布信息，采集时从中选出实际动作。Critic根据输入估计未来回报，为评价动作提供参照。

网络前部可以共享，后部有不同分支。Critic参与训练，不直接给执行器下指令。

<a id="return"></a>
## 2. 奖励、回报、价值、优势分别是什么

本文记\(r_t\)为执行\(a_t\)后得到的奖励。

| 名称 | 含义 |
|---|---|
| 奖励\(r_t\) | 环境对这一步给出的即时反馈 |
| 折扣回报\(G_t\) | 从这里开始后续奖励的折扣和 |
| 价值\(V^\pi(H_t)\) | 按当前策略行动时，对未来回报的条件期望 |
| Critic输出\(V_\phi(H_t)\) | 网络对这个期望的近似预测 |
| 优势\(A^\pi(H_t,a_t)\) | 选择这个动作相对当前策略平均表现的好坏 |
| 优势估计\(\hat A_t\) | 程序用有限经历与价值预测算出的近似值 |

H_t表示当前允许使用的观测与历史。简写成V(s_t)时，不代表策略获得全部真实物理参数。

\[
G_t=r_t+\gamma r_{t+1}+\gamma^2r_{t+2}+\cdots.
\]

奖励为正，不意味着优势必定为正：如果表现仍低于原来的预期，优势可以为负。

理论目标是最大化期望回报。PPO用有限数据构造代理目标，不直接知道所有可能未来的真实平均分，也不保证每次更新都提高实际表现。

<a id="td"></a>
## 3. 时序差分δ为什么这样写

\[
\delta_t=r_t+\gamma V_{\mathrm{old}}(H_{t+1})-V_{\mathrm{old}}(H_t).
\]

未来回报可以拆成“当前一步奖励＋下一位置以后的回报”。走完一步后，已经知道r_t，用下一位置的价值预测估计剩余部分，就得到：

\[
Y_t^{(1)}=r_t+\gamma V_{\mathrm{old}}(H_{t+1}).
\]

再减去走之前的预期V_old(H_t)，得到δ_t。

```text
走之前预计未来得2分。
走一步得到0分，新位置预计以后还能得5分。
若γ=1，新估计为0+5=5；相比原来的2，高了3。
```

因此δ=3。3是评价差异，不是额外领到3分奖励；新位置的5仍是预测，不是实际已获得的奖励。

### 3.1 “下一时刻”不是“下一轮训练”

V_old(H_t)和V_old(H_{t+1})由采集时同一个版本网络产生，只是输入时间位置不同。old与new区分参数版本，t与t+1区分交互时间。

任务真正终止时通常不再bootstrap未来价值；采集长度到达上限但任务未结束时，可以用末端Critic值估计尚未观察的未来。环境终止、时间截断、Trial边界和segment边界不能自动当作同一种事件。

### 3.2 TD目标不是确定真值

一步评价中包含网络预测，所以它有估计误差。训练依赖大量不同经历和适当的估计方法，而不是声称一次反馈就知道某个动作的真实长期价值。

<a id="gae"></a>
## 4. GAE为什么把后面的δ加进来

一步TD只用了一个实际奖励，其余依赖预测。继续交互会得到更多评价差异，GAE将其加权综合：

\[
\hat A_t=\delta_t+\gamma\lambda\delta_{t+1}
+(\gamma\lambda)^2\delta_{t+2}+\cdots.
\]

把后半部分括起来就得到递推式：

\[
\boxed{\hat A_t=\delta_t+\gamma\lambda\hat A_{t+1}}.
\]

γ对未来奖励打折；λ控制后续TD修正传播的权重，关系到偏差与方差的折中。λ并不是“每段损失占比”。

### 4.1 用同一份三步经历完整计算

以下仅为手算，取γ=λ=1，末端价值0，暂不标准化优势：

| 位置 | 奖励 | 采集时旧价值 |
|---|---:|---:|
| 1 | 0 | 2 |
| 2 | 1 | 5 |
| 3 | 3 | 1 |

\[
\delta_1=0+5-2=3,
\quad\delta_2=1+1-5=-3,
\quad\delta_3=3+0-1=2.
\]

从后往前：

\[
\hat A_3=2,\quad
\hat A_2=-3+2=-1,\quad
\hat A_1=3+(-1)=2.
\]

第1步只看一步得到δ=3，综合后面的信息后优势变成2。不是把第1步的评价永远固定为最初的δ。

<a id="value-target"></a>
## 5. 为什么回报目标是优势加旧价值

\[
\boxed{\hat R_t=\hat A_t+V_{\mathrm{old}}(H_t)}.
\]

把优势理解为对原预测的估计修正量：旧预测加修正，得到新的回报训练目标。

上述例子得到：

| 位置 | 旧价值 | 优势 | 回报目标 |
|---|---:|---:|---:|
| 1 | 2 | +2 | 4 |
| 2 | 5 | −1 | 4 |
| 3 | 1 | +2 | 3 |

为什么先减又加？展开第1步：

\[
\begin{aligned}
\hat A_1
&=(r_1+V_2-V_1)+(r_2+V_3-V_2)+(r_3-V_3)\\
&=r_1+r_2+r_3-V_1.
\end{aligned}
\]

中间价值项抵消，再加V_1就恢复累计回报。本例是4。一般γ、λ和末端bootstrap不同，目标是相应估计，不保证等于完整真实回报。

在有效非终止位置，也可整理为：

\[
\hat R_t=r_t+\gamma[(1-\lambda)V_{\mathrm{old}}(H_{t+1})+\lambda\hat R_{t+1}].
\]

λ=0退化为一步bootstrap目标；λ=1沿后续回报继续递推。

**回报目标使用未标准化优势构造。** 本地代码先`returns = gae + values`，随后才对供Actor使用的优势做标准化。不能拿标准化后的数加旧价值，声称得到同一个目标。

同一批PPO优化中，保存的奖励、旧价值及构造出的目标作为常量，不对目标的生成链反向传播。

<a id="collection"></a>
## 6. 采集旧概率与价值，为什么先不保留梯度

当前Microduck采集逻辑是：

```python
with torch.no_grad():
    action_logits, old_value = stateful_fwd(observation, ...)
    action = model.unembedder.sample(action_logits)
    old_log_prob = model.unembedder.log_prob(action_logits, action, ...)
next_observation, reward, ... = environment.step(action_for_environment)
```

采集主要需要数值，不需要为数百步交互一直保留完整反向计算图。动作采样和环境响应产生实际经历，保存旧概率作为后续参照。

机器人多关节动作是一组数，例如[a1,a2,...,aD]。策略通常给各维连续分布参数，再采样。连续值的单点概率为0，这里比较的是概率密度；密度可以大于1，对数密度也不必为负。

环境可以不可微。PPO把采集到的动作、奖励等当作数据，通过“该动作在当前策略下的密度”路径求梯度，不要求把梯度穿过真实机器人或仿真引擎。

<a id="recompute"></a>
## 7. 为什么参数没变还要重新前向

训练把保存的观测与相应历史重新输入网络：

```python
current_logits, current_value = network(saved_observation, history)
current_log_prob = log_prob(current_logits, saved_action)
```

计算的是**保存的那个动作**当前有多大密度，不需要再执行它，也不需要重新抽一个动作替代它。

第一次优化开始时，若输入、参数、历史及随机设置一致，输出数值可以与采集时相同。用户最初的判断没有错。

重新前向的直接目的，是获得本次求梯度所需的中间值与计算图。计算关系由代码已经规定，不是在“重新寻找权重关系”。如果原图完整保留且参数不变，数学上不必天然再算一次；当前实现选择采集no_grad、训练重算，以控制资源并支持多轮更新。

\(y=2w\)在w=1时值为2，但导数仍为2。输出数值没变，不意味着梯度为0。

后续轮次参数已经变了，因此当前概率、当前价值与梯度通常都需要重新计算。

<a id="ratio"></a>
## 8. 新旧概率比比较的是同一条经历

\[
\rho_t(\theta)=
\frac{\pi_\theta(a_t\mid H_t)}{\pi_{\mathrm{old}}(a_t\mid H_t)}
=\exp(\log p_{\mathrm{current},t}-\log p_{\mathrm{old},t}).
\]

分子是当前网络计算结果，可求梯度；分母是采集时保存的固定值。

旧值0.5、当前值0.55，比例1.1；当前0.7，比例1.4。比较的是同一个位置、同一个已执行动作的新旧密度，不是任意两个动作的概率相减。

第一轮开始比例可以是1，但\(p_\theta/p_{\mathrm{old}}\)对θ仍有导数，因为分母固定，分子随θ变化。它不是恒等于1的函数\(p_\theta/p_\theta\)。

若存在随机层、训练/采集模式差异或历史重建差异，首轮数值也未必逐位完全相同；不要把“初始必为1”当作所有实现的无条件保证。

<a id="clipping"></a>
## 9. PPO为什么取min，负号又做什么

单位置Actor损失：

\[
\ell_t^\pi=-\min\left(
\rho_t\hat A_t,
\operatorname{clip}(\rho_t,1-\epsilon,1+\epsilon)\hat A_t
\right).
\]

min先比较两项**希望最大化的训练目标**；外面的负号再转换成要最小化的损失。因此不是“已经选小损失后又加一个多余负号”。

未经裁剪的目标ρA：A为正时鼓励提高该动作密度；A为负时鼓励降低。取ε=0.2，四种关键情况：

| A | ρ | 原目标ρA | 裁剪目标 | min选中 | 最终损失 |
|---:|---:|---:|---:|---:|---:|
| +1 | 1.4 | 1.4 | 1.2 | 1.2 | −1.2 |
| +1 | 0.6 | 0.6 | 0.8 | 0.6 | −0.6 |
| −1 | 0.6 | −0.6 | −0.8 | −0.8 | +0.8 |
| −1 | 1.4 | −1.4 | −1.2 | −1.4 | +1.4 |

### 9.1 好动作增加太多：停止继续鼓励

A=+1、ρ=1.4，选择常数裁剪项1.2。再增加ρ，这条样本的该项不继续提供增大密度的收益。

### 9.2 好动作反而降低太多：仍然纠正

A=+1、ρ=0.6，选未裁剪的0.6，仍可通过提高ρ增大目标。若只用clip，0.6和0.7都会变成0.8，这里就失去纠正梯度。

### 9.3 坏动作已经降低太多：停止继续鼓励

A=−1、ρ=0.6，−0.8比−0.6小，选择裁剪项−0.8。注意负数的大小关系。

### 9.4 坏动作反而增加太多：仍然纠正

A=−1、ρ=1.4，选未裁剪项−1.4。降低ρ能使目标从−1.4增至−1.3，损失下降。

min实现“有利改变过大时停止进一步鼓励，不利改变时保留纠正”。只用clip会把两种方向一起截断；取max又可能继续奖励过大的有利改变。

裁剪不保证密度比硬性保持0.8～1.2；共享参数、其他样本、Critic与熵梯度仍影响输出。它也不是对关节角度或机器人运动幅度的安全限幅。

损失可以为负，零也不表示达到最优。它的用途是产生合适的梯度，不是与环境累计得分使用相同刻度。

<a id="critic"></a>
## 10. Critic怎样训练：目标固定，当前预测变化

这里必须分开：

| 数据 | 用途 |
|---|---|
| 采集时保存的旧价值 | 构造GAE和回报目标 |
| 优化时重新计算的当前价值输出 | 与固定回报目标比较，求Critic损失 |

例如旧预测2、回报目标4。更新后当前预测变成2.2，目标仍然是4，不能每轮把旧预测换成2.2，顺手改掉训练参照。

### 10.1 通用标量Critic的教学损失

常见平方误差是：

\[
\ell^V=\tfrac12(V_\phi-\hat R)^2.
\]

它让当前预测靠近回报目标，梯度由当前误差沿网络传回。这里是理解计算链的例子，不是当前仓库实际Critic损失。

### 10.2 当前代码实际使用HLGauss

Critic默认输出32个回报区间的logits。Microduck传入区间(-100,2000)。将logits转换成分布后，可读出一个标量价值，用于采集与GAE。直观上，用各区间代表值\(c_j\)进行概率加权：

\[
V_\phi(H_t)=\sum_jp_jc_j.
\]

例如，教学分布给回报2与4各0.5权重，读出值就是3。这个3是网络预测，不是程序已经看到了全部真实未来。实际区间与平滑由HLGauss配置决定。

训练则保留分布输出，调用：

```python
value_loss = self.hl_gauss_loss(
    value_logits, data.returns, reduction='none'
) * self.value_loss_weight
```

HLGauss把标量目标转成目标附近的软分布，再与预测分布比较。其核心交叉熵形式可理解为：

\[
p_j=\operatorname{softmax}(z)_j,\qquad
\ell^V=-\sum_jq_j(\hat R)\log p_j.
\]

q是由回报目标和库的区间/平滑规则生成的固定软目标，p是当前Critic预测。目标生成的具体边界与平滑参数需按使用的依赖版本核对。

对logit的典型梯度为\(p_j-q_j\)：某个区间预测概率低于目标时，梯度倾向于提高对应logit，反之降低。再沿Critic与共享主干计算各权重梯度。

这不是额外获得了“正确物理动作标签”，也不表示论文原作者明确采用了32区间HLGauss；这是本地第三方代码的选择。依赖说明见[HLGauss实现](https://github.com/lucidrains/hl-gauss-pytorch)。

<a id="batch"></a>
## 11. 多条数据怎样汇总损失

有效位置i先分别计算Actor与Critic损失，再平均：

\[
L=\frac1N\sum_{i\in\mathrm{valid}}
[\ell_i^\pi+c_V\ell_i^V-c_H\mathcal H_i].
\]

N是有效位置数，不一定是名义采集条数。H是动作分布熵，用于鼓励一定探索。

先逐位置算min与clip，再汇总。不能先把不同位置的优势和比例平均，再套一次裁剪公式。

当前代码默认连续动作按动作维度分别计算比例与裁剪，再对动作维平均，得到每个时间位置的Actor损失。这与常见教材先求整组动作联合密度比的写法有区别；不能把两者默认当成数值等价。

同一时间位置的一组关节动作共用该位置优势。环境通常没有把奖励精确分配到每个关节，学习依赖多样经历和梯度统计。

<a id="numerical"></a>
## 12. 两条数据、连续两轮：完整手算

这是教学网络，暂不做优势标准化、熵正则、梯度限幅，也使用普通梯度下降。不要将其数字当作真实Microduck训练输出。

从前面经历中选择甲位置，再加另一环境的乙位置：

| 样本 | 输入特征x | 旧动作概率 | 旧价值 | 回报目标 | 优势 |
|---|---:|---:|---:|---:|---:|
| 甲 | −1 | 0.5 | 2 | 4 | +2 |
| 乙 | +1 | 0.5 | 2 | 1 | −1 |

两个样本构成一个手算批次。Actor与Critic在这个小例子中参数独立，便于看清各自梯度；真实网络前部共享，两种损失会共同影响共享参数。

### 12.1 Critic第一轮

设\(V(x)=wx+b\)，初始w=0、b=2。两个预测都是2。

\[
L_V=\frac12\left[\frac12(2-4)^2+\frac12(2-1)^2\right]=1.25.
\]

单样本误差e=V−R，梯度为：

\[
\partial\ell/\partial w=e x,\qquad
\partial\ell/\partial b=e.
\]

甲：e=−2，对w贡献+2，对b贡献−2。乙：e=+1，对w贡献+1，对b贡献+1。

平均梯度：dw=1.5，db=−0.5。学习率0.1：

\[
w\leftarrow-0.15,\qquad b\leftarrow2.05.
\]

预测变成：甲2.2，乙1.9。两者都靠近各自目标。

### 12.2 Critic第二轮

目标仍是4和1。当前误差−1.8、+0.9，损失1.0125，平均梯度dw=1.35、db=−0.45。

再更新得到w=−0.285、b=2.095，预测甲2.38、乙1.81。

| 阶段 | 甲预测，目标4 | 乙预测，目标1 | 平均Critic损失 |
|---|---:|---:|---:|
| 更新前 | 2 | 2 | 1.25 |
| 第一轮后 | 2.2 | 1.9 | 1.0125 |
| 第二轮后 | 2.38 | 1.81 | 0.820125 |

### 12.3 Actor第一轮

令两个位置对应的已执行动作概率为：

\[
p_\theta(x)=\operatorname{sigmoid}(\theta x),\qquad\theta=0.
\]

初始概率均0.5，比例均1，未触发裁剪。样本损失为−2和+1，平均−0.5。

本段内：

\[
\ell=-\frac{p_\theta}{0.5}\hat A,
\qquad
\frac{\partial\ell}{\partial\theta}
=-\frac{\hat A}{0.5}p(1-p)x.
\]

这是链式法则：损失如何依赖概率，概率如何依赖θx，θx如何依赖θ。

甲梯度为+1，乙梯度为+0.5，平均+0.75。学习率0.1：

\[
\theta\leftarrow-0.075.
\]

于是甲动作概率变成0.518741，乙变成0.481259。正优势样本概率提高，负优势样本概率降低。

这不是先手动提高概率、再求梯度。程序先由损失算梯度，再改权重；概率变化是之后重新前向的结果。

### 12.4 Actor第二轮

分母仍为采集时保存的0.5。当前比例约1.037482和0.962518，仍在裁剪区间内。

新平均损失约−0.556224，重新计算平均梯度约+0.748946，更新θ≈−0.149895。当前概率继续改变。

| 时刻 | 当前θ | 甲动作概率 | 乙动作概率 | 两个旧概率 |
|---|---:|---:|---:|---|
| 第一轮开始 | 0 | 0.5 | 0.5 | 均0.5 |
| 第二轮开始 | −0.075 | 0.518741 | 0.481259 | 仍均0.5 |
| 第二轮更新后 | −0.149895 | 约0.5374 | 约0.4626 | 仍均0.5 |

后续若进入裁剪区域，要按当前激活分支计算梯度，不能继续无条件使用未裁剪公式。

这个例子恰好两个样本的梯度支持相容调整；复杂网络中不同样本可能冲突，所以不能保证每条数据在每次更新后都改善。

<a id="autograd"></a>
## 13. 反向传播与优化器分别做什么

```python
loss.backward()   # 计算并累积参数.grad
optim.step()      # 根据梯度和优化器状态修改参数
optim.zero_grad() # 清除已使用的梯度，不清除权重
```

backward依据前向计算关系使用链式法则，并不会自动替代step更新参数。Adam还有动量与尺度状态，其更新数值不等于手算的普通梯度下降。

每个参数有自己的梯度，最终不是拿一个平均损失数字直接加到全部权重上。损失数值为0，也可能有非零梯度；损失数值大，也不能单靠大小确定每个权重该往哪改。

共享主干收到Actor与Critic等损失的梯度之和。梯度限幅限制梯度范数，PPO裁剪改变训练目标，机器人动作限幅限制实际指令，三者用途不同。

<a id="segment-loss"></a>
## 14. 分segment计算损失，到底平均什么

当前Microduck一次采集12×256=3072个名义位置，段长16，所以通常沿时间处理16个窗口，每窗12×16=192个位置。

设有效位置总数N。每段使用：

\[
L_w=\frac1N\sum_{i\in\mathrm{segment}\ w,\ valid}\ell_i.
\]

分母是整批N，不是每段各自随意平均后直接相加。若窗口有效位置数不同，这点尤其重要。

代码执行：

```text
窗口1：前向 → L1.backward → 累积g1
窗口2：前向 → L2.backward → 累积g1+g2
……
窗口16：前向 → L16.backward → 累积所有窗口梯度
最后：梯度限幅 → Adam.step → 更新一次参数
```

整轮窗口计算期间参数不变。按SG规则处理的各窗口梯度可以相加，但它们不是不截断旧生成链的完整长序列梯度。

segment主要决定计算分块、记忆和反传边界；这次使用多少经历首先由采集批次和数据选择决定。实际损失值只有当前网络计算后才知道，配置只能规定构造方法和权重。

## 15. 从第一次采集到多轮更新的完整时间链

```text
θ0固定，12个环境各交互256步
→ 保存D：观测、动作、旧logp、旧V、奖励、done、ep_id
→ 额外计算采集末端V，处理未结束未来的bootstrap

优化第1轮：
用D中旧数值构造GAE与目标
→ cache=None，依次处理16个窗口
→ 每窗前向、损失、backward，传detach缓存
→ 所有窗口后Adam.step：θ0→θ1
→ zero_grad

优化第2轮：同一批D，重建缓存，θ1→θ2
优化第3轮：同一批D，重建缓存，θ2→θ3
优化第4轮：同一批D，重建缓存，θ3→θ4

使用θ4与环境交互，采集D2
→ D2的旧概率和旧价值来自θ4
→ 继续优化……
```

当前代码每次`ppo()`都会从同样的保存数据重算GAE；目标不因当前Critic变化而替换。优化四轮不表示与环境又交互四次，也不表示把第一轮新概率当成第二轮分母。

“PPO更新一次”容易混淆：本文用“采集一批”“优化一轮”“执行一次参数更新”分别描述。当前Microduck一轮`ppo()`对应一个Adam更新，但其他入口可能使用mini-batch，更新次数不同。

## 16. 标准解释与当前实现的边界

1. 当前gamma=.99、lambda=.95，会标准化有效位置优势，手算gamma=lambda=1不复刻其数值。
2. 当前`gae_mask=padding_mask & ~done`同时用于GAE及损失筛选，终止位置本身被排除；它的奖励仍可能通过GAE影响前面位置。不能把3072说成必定有3072份有效损失。
3. term与trunc在入口合并为done。一般算法需要区分真正终止与时间截断，复现前应检查这份实现的bootstrap语义。
4. 论文多Trial Episode边界与本地Microduck环境episode编号不同，不能自动套用同一种重置规则。
5. 当前连续动作默认逐维裁剪，Critic为HLGauss，优化器为Adam。论文没有披露这些都采用相同设置。
6. PPO也可能有KL惩罚、自适应学习率等其他实现。本手册解释当前标准clip分支，没有把所有PPO变体都混入本流程。

这些边界是代码阅读结论与待核验事项，不是本次已经修复或验证过的训练结果。
