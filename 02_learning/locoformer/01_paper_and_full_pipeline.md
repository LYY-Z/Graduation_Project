# 01 论文与完整流程

阅读目标：先把整个系统串起来，知道每个名词属于哪个阶段，再理解网络和优化细节。

<a id="overview"></a>
## 1. 整篇论文的主线

LocoFormer研究跨本体运动控制：用同一个策略控制不同腿式、轮足机器人，并在遇到身体或驱动条件变化后，利用交互历史调整控制。

整条链路包含两个过程：

```text
训练：
采样机器人及条件 → 网络选择动作 → 仿真计算身体响应与奖励
→ 保存一批经历 → 根据经历构造训练目标 → PPO求梯度并更新参数
→ 用更新后的策略继续采集

部署：
加载训练好的参数 → 读取当前观测与历史 → 输出关节目标
→ 身体执行 → 获得新观测 → 更新历史 → 下一次计算
```

部署时通常不执行PPO，不根据每一步反馈修改网络权重。策略在训练中已经学到了怎样利用历史；部署中的输入和内部缓存变化，足以使动作发生相应变化。

可以把一次控制写成：

\[
(a_t,C_{t+1})=f_\theta(o_t,C_t).
\]

这里，\(\theta\)是训练参数，\(C_t\)是运行中的历史缓存。固定\(\theta\)，并不要求\(C_t\)或\(a_t\)固定。

### 1.1 与Diffusion Policy的联系和区别

| 项目 | Diffusion Policy原论文主线 | LocoFormer主线 |
|---|---|---|
| 学习信号 | 专家演示中的动作 | 环境交互产生的奖励 |
| 主要训练方式 | 行为克隆，预测动作噪声 | 强化学习，PPO Actor–Critic |
| 输出组织 | 生成一段动作计划，执行前段 | 根据当前观测与长历史选择当前动作 |
| 重点记忆机制 | 观察窗口与条件编码 | Transformer-XL段间记忆、跨Trial经历 |
| 运行中的随机性 | 扩散采样等 | 动作分布采样等 |

不能把LocoFormer的segment理解为Diffusion Policy生成的未来动作块。这里的segment主要沿已经出现的观测时间序列分块。

<a id="robustness"></a>
## 3. 鲁棒性与适应性为什么都需要

### 3.1 初始鲁棒性从哪里来

训练中让策略遇到不同结构、质量、惯量和控制条件，并用奖励鼓励稳定跟踪指令。不同条件共同影响梯度，策略可能学到在一定变化下仍能工作的控制规律。

“训练见过很多变化”增加泛化机会，不等于覆盖所有身体、所有故障，更不保证任意新条件安全成功。

### 3.2 适应性增加了什么

例如，某条腿运动幅度变小。当前瞬时姿态可能只显示身体偏斜，短时间内不容易区分：是接触扰动、动作暂时滞后，还是驱动能力持续下降。

连续交互提供了“发出怎样的控制，身体如何响应”的证据。网络利用这些信息改变后续控制，就是这里强调的适应。

它可以形成身体相关的内部表示，不必显式输出“质量3.2kg”或“左膝失效”这样的标签。实验中的表示分簇，也不能直接证明精确物理参数辨识。

### 3.3 两者不是单向因果

初始策略可能已经足够鲁棒，不需要先发生明显适应；适应也可能提升随后运行的鲁棒表现。论文把广泛任务训练与长历史利用结合起来，不能把所有鲁棒性都归因于部署适应。

<a id="concepts"></a>
## 4. 先统一名词与时间尺度

| 对象 | 具体是什么 | 不应混成什么 |
|---|---|---|
| 任务/MDP \(\mathcal M\) | 一组机器人结构、动力学、控制及环境规则 | 一次网络调用 |
| 时间步 \(t\) | 观测、动作、环境响应的一次交互位置 | 一次参数更新 |
| 轨迹 | 按时间排列的观测/状态、动作、奖励等记录 | 网络一次凭空生成的真实未来 |
| Trial | 从初始状态开始的一次物理或仿真运行 | 固定16步的计算段 |
| 论文Episode | 同一任务内多个Trial组成的一组经历 | 必然等于某个Gym环境的episode |
| segment | 沿时间切分、供网络计算和记忆管理的一段序列 | 环境重置标记 |
| 采集批次D | 在一段交互期间保存的一批数据 | 单个segment |
| 一轮优化 | 用选定数据前向、求梯度并按实现进行更新 | 再次执行过去的动作 |
| 参数\(\theta\) | 训练学到的权重与偏置 | 当前观测、缓存、动作 |

例如，一个Trial可以持续数百步，跨过多个segment；一个segment也可能跨物理Trial边界。是否允许读取边界之前的历史，取决于Episode组织与注意力掩码。

这里“同一任务”不表示每一瞬间的身体状态不变。身体状态本来就要随动作变化；任务规则也可能包含扰动。

<a id="sampling"></a>
## 5. 论文公式（1）：为什么写三次采样

原文目标可概括为：

\[
J(\theta)=\mathbb E_{\mathcal M,k,E}
\left[\sum_{i=1}^{k}\sum_t
\gamma^{H_{i-1}+t}R_{\mathcal M}(s_t,a_t)\right].
\]

\(H_{i-1}\)是此前Trial的累计长度；折扣指数沿整组经历推进。目标是最大化期望回报。

### 5.1 抽任务 \(\mathcal M\sim\rho_{\mathcal M}\)

先决定这次让策略面对什么身体和控制条件。\(\rho_{\mathcal M}\)是选择这些任务的规则，不自动意味着所有条件等概率。

它决定哪些条件更常贡献训练经历，进而更常影响参数更新。任务生成参数与网络权重是两类不同参数。

### 5.2 抽Trial数量 \(k\sim\rho_K\)

形式定义取\(\rho_K=\operatorname{Uniform}(1,\ldots,K)\)。例如K=3时，可以抽到1、2或3次Trial。

这个抽样让策略经历不同长度的交互组织。它不是从网络已有输出中挑一个最好动作。

### 5.3 运行策略产生 \(E_{\mathcal M,k}\sim\pi_\theta\)

在已选任务中，让策略和环境真正交互：策略选择动作，环境产生新状态、奖励和结束信息。初始状态或动作采样等会使同一配置下的经历不同，因此整组经历可视为随机过程的样本。

这个“\(\sim\)”概括策略驱动的轨迹分布，网络并没有一次性输出全部未来真实状态。

### 5.4 期望与PPO怎样连接

期望表示对任务、交互随机性等因素的理论平均。程序无法知道全部可能未来，所以用有限采样的经历构造PPO代理目标，近似推动策略改善。

损失最小化与回报最大化之间通过目标设计连接。不能说强化学习在“降低回报期望”，也不能把PPO损失数值直接当真实期望回报。

<a id="protocol"></a>
## 6. 实际训练为何改用适应时间预算

原文指出长Trial使直接抽次数不够方便，因此实际训练采样：

\[
u\sim\operatorname{Uniform}(0,U).
\]

预算u内允许进行若干Trial，然后运行最终Trial。

```text
选定同一个任务
    ↓
适应预算内：Trial1、Trial2……按运行情况发生
    ↓
最终Trial：利用此前交互历史继续控制
```

不是每个Trial前各自再放一段适应时间。形式公式抽次数与实际协议抽时间预算，是论文先定义问题、再调整实现的两个层次。

“最终Trial”是时间组织中的最后一段运行，不是挑选此前得分最高的一次。它既可以出现在训练任务构造中，也可以用于测试协议。

原文目标累计整组经历回报；时间预算实现没有公开全部奖励与损失掩码。因此，不能补写成“适应窗口完全不训练，只训练最终Trial”。

### 6.1 为什么训练先短后长

这是整个训练过程的课程安排：先采用较短Trial与较小U，随后延长。前期让适应相关的经历较集中地出现，后期准备较长时间控制。

它不是每个Episode内部都先运行短任务，再现场切换到长任务。

<a id="training-deployment"></a>
## 7. 训练、推理和部署的完整时间链

### 7.1 单步交互

```text
环境提供观测
→ 输入MLP生成token
→ Transformer-XL结合缓存
→ Actor产生动作分布信息
→ 抽取动作并转换为关节目标
→ 底层控制器和身体执行
→ 环境返回新观测、奖励与结束标记
```

这只是一次交互步，不是一次完整训练。单步前向改变内部表示；只有后续优化器更新才改变参数。

目标角度不保证立刻等于实际角度。执行器需要时间响应，实际运动还受到惯量、负载、接触和控制增益等影响。仿真负责计算这些响应。

### 7.2 一次采集—优化循环

```text
固定θ_old采集一批经历
→ 计算优势和回报目标
→ 当前网络重新前向
→ 算Actor、Critic等损失
→ 反向传播，优化器修改θ
→ 同批可再优化若干轮
→ 用更新后的策略采集新数据
```

03给出完整数值计算，04给出当前Microduck入口的12×256、16步分段与4轮更新时序。

### 7.3 部署适应与zero/few-shot

部署固定已训练参数，持续积累可用历史。Zero-shot表示没有额外的预评估适应预算，不表示当前Trial运行中没有历史。

Few-shot先允许额外交互，再计最终Trial的表现。论文仿真比较使用5秒预评估交互；不能把5秒写成所有真实机器人统一配置。

如果给zero-shot增加不计分的预运行，再保留历史开始计分，实际上改变了评估协议。运行多少次、保留何种历史、从何时计分，都需要明确。

## 8. 仿真实验：数字代表什么

Table 1在10种未见机器人上评估，每种1,000个随机化环境，包含5种双足、3种四足、2种轮足。

指标是朝随机目标方向的平均位移，归一化到[0,1]。它不是任务成功率，也不是以米计的绝对位移。

| 方法 | 平均归一化位移 |
|---|---:|
| LocoFormer zero-shot | 0.96 |
| LocoFormer few-shot | 0.98 |
| GRU | 0.37 |
| Conditioning | 0.78 |
| Expert | 0.99 |

GRU采用相同训练设置，主要比较记忆架构。Conditioning具有运动学特权信息，但上下文64步，同时改变了输入和历史条件，不能当成仅改变一个因素的消融。Expert在目标平台直接训练，提供专用策略参照，不是所有任务的数学上界。

Spot的均值在zero/few-shot下均为1.00。平均提升不意味着每个平台严格提升，更不保证每次运行都改善。

### 8.1 Figure 4(a)：适应时间

随机化强度加倍，在四类程序化机器人上改变适应预算，之后评估最长6秒运行的平均存活时间，每个设置50,000个Episode。总体上更多交互改善存活，但曲线有波动和饱和。

不能把图中的适应预算直接理解为每个Trial都要等待的固定时长。

### 8.2 Figure 4(b)：表示分化

四种人形变体、4,096次zero-shot运行，观察第二层平均表示随时间变化。约5秒后形成身体相关簇，支持网络内部表示利用了身体相关交互信息。

原文未完整说明可视化投影方法，不补写PCA或t-SNE。表示分化不等同于显式、精确辨识物理参数。

## 9. 实机结果及证据强度

同一模型部署到G1、H1、Go2、Go2-W，包含后腿双足模式，不先针对目标平台微调或重训。

Figure 5展示关节/腿锁定、跨Trial保留失败经历、轮部驱动变化、负载改变、高跷和截短腿部等情况。

跨Trial示例在后续尝试中利用此前缓存，第3次Trial展示稳定行走。它说明“失败经历可以成为信息”，不表示所有故障都在3次内恢复。

原文把轮控制增益置零的情况称为锁轮。增益置零不自动等同机械刹车锁死，复述时使用“轮部驱动条件改变”更准确。

部分恢复时长在正文与图注之间存在口径差异，因此不应给整篇论文编造统一恢复秒数。实机案例主要展示能力，尚不能替代故障类型覆盖、恢复时间分布与成功率统计。

<a id="limits"></a>
## 10. 特色、局限与后续研究问题

这篇论文把三个条件连接起来：

1. **任务多样性**：让策略接触不同身体和动力学。
2. **长历史与跨Trial组织**：让响应、失败和重试成为后续控制依据。
3. **奖励驱动训练**：使利用这些信息的行为有机会获得长期回报收益。

仅有大模型不自动产生适应；仅加缓存也不自动学会使用历史。训练任务必须提供有用的变化和交互机会。

与单平台RL相比，作者扩大身体与动力学范围；与显式身体条件输入方法相比，强调从交互构造表示；与部署微调相比，强调固定参数的上下文适应。

附录C提到100k机器人和相对专用策略的大计算需求。不同训练资源、平台及“每机器人摊销”口径不能直接等价为复现所需天数。

可检验的后续问题包括：匹配数据和计算预算后比较长/短上下文；单独控制跨Trial缓存保留；量化故障恢复时间与失败率；检验历史长度、任务覆盖与泛化的相互作用。这些是分析提出的研究设计，不是原文已经完成的全部消融。
