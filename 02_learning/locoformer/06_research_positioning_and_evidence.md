# 06 研究定位、跨本体接口与实验依据

本篇补充论文汇报中必须回答的问题：研究对象是什么，已有工作做到了什么，LocoFormer 的贡献是什么，不同机器人怎样共享输入输出，实验支持哪些结论，以及目前能够复现到什么程度。

核对日期：2026-11-02。论文细节以[本地 arXiv v1 全文](../../01_papers/locoformer/paper.pdf)为依据，发表信息核对[CoRL/PMLR 页面](https://proceedings.mlr.press/v305/liu25a.html)。公开资源核对作者项目页与第三方仓库。本文没有执行训练、仿真或硬件控制。

## 1. 汇报需要先建立研究问题

算法流程解释“程序怎样工作”；研究汇报还必须解释“为什么值得做、与谁不同、证据有多充分”。建议采用下面的论证顺序：

```text
现实问题和研究范围
→ 已有方法与尚未解决的困难
→ 本文的研究假设与贡献
→ 输入输出接口及完整方法
→ 评测任务、基线和指标
→ 结果、结论边界与局限
→ 公开资源和复现计划
```

对于 LocoFormer，可以先用一句话确定问题：

> 如何让同一个运动控制策略迁移到训练中未出现的腿式、轮足机器人，并在身体或驱动条件变化时，通过交互历史调整控制，而不依赖部署时重新训练策略？

这里同时包含跨本体泛化和运行中的适应。它不是只研究某一台机器人的走路，也不是研究图像生成、机械臂操作或任意类型机器人控制。

## 2. 先区分几个汇报术语

| 术语 | 含义 | 本文中的例子 |
|---|---|---|
| Problem | 要解决的研究问题 | 未见身体的运动控制和身体条件变化后的适应 |
| Method | 解决问题的具体机制 | 统一关节空间、多样化任务训练、跨 Trial 长历史和 PPO |
| Contribution | 相比已有研究增加了什么 | 将这些设计用于大规模跨本体运动控制，并给出相应评估 |
| Benchmark | 一套评测任务、环境、协议和指标 | 十种未见机器人及随机化环境构成的仿真评测设置 |
| Baseline | 在相同评测中作为对照的方法 | GRU、Conditioning、目标平台 Expert Policy |
| Metric | 怎样量化表现 | 归一化朝目标位移、平均存活时间 |
| Ablation | 控制其他因素，改变某一设计以分析其作用 | 比较是否跨 Trial 保留历史的实验设计 |
| Related work | 与问题或技术有关的既有研究 | RMA、GenLoco、URMA、Body Transformer、RL² 等 |

Benchmark 不等于一个固定离线数据集，在线仿真评测也可以构成 benchmark。应将本文设置称为“论文构建的评测设置”，不能在未核实公开资产和协议时称为完整开放标准基准。

“basemark、baselink”在论文比较语境中很可能指 benchmark、baseline。如果确实是机器人软件中的 `base_link`，它表示机身基坐标系，与基线方法是不同概念。

## 3. 本文属于哪一类方法

需要按不同维度分类，不能把 PPO、Transformer 和跨本体控制当成同一层级的并列类别。

| 分类维度 | LocoFormer 的位置 |
|---|---|
| 研究任务 | 跨本体腿式与轮足运动控制 |
| 学习方式 | 在物理仿真中通过奖励进行强化学习，使用 PPO 优化 |
| 策略结构 | 观测 MLP、Transformer-XL 主干、Actor/Critic 分支 |
| 适应机制 | 基于历史的隐式适应、固定权重的上下文适应 |
| 跨本体接口 | 统一关节空间，并提取当前机器人对应的动作分量 |
| 部署方式 | 网络参数固定，观测、缓存、内部表示和动作随交互变化 |

从功能上可以将其放在记忆型元强化学习或上下文强化学习的研究脉络中，但不应把它讲成 MAML 式部署梯度微调。PPO 是训练阶段改变权重的算法；部署适应主要发生在固定权重的前向计算中。

与先前学习的 Diffusion Policy 对照：后者主线是从专家演示学习动作生成；LocoFormer 的学习信号来自仿真交互和奖励。两者都称为 policy，但研究问题、训练信号和动作生成机制不同。

## 4. 不同关节数量怎样适配

### 4.1 接口适配和控制适应是两个问题

接口适配回答：

- 这台机器人有哪些关节？
- 传感器数据对应网络输入的哪些位置？
- 网络输出对应哪些电机？
- 关节顺序、正方向、单位和动作尺度怎样对应？

控制适应回答：

- 发出目标后，实际响应是否符合预期？
- 负载、接触或驱动能力变化后，下一步应怎样调整？

两者不能互相替代。网络可以通过历史调整控制，但软件仍然需要明确的数据与执行接口。

### 4.2 论文明确给出的方案

§2.1 的 Unified Observation, Action and Reward Space 说明：构造覆盖多种机器人关节的统一关节空间，统一组织观察和动作；策略输出统一空间中的目标关节位置，再提取具体机器人对应的关节分量。

可以将逻辑写成：

```text
机器人 r 的实际传感器数据
→ 按接口规则映射到统一观察格式
→ 共享策略结合历史计算
→ 输出统一关节空间中的目标
→ 提取机器人 r 对应的动作分量
→ 控制器与执行器
```

以下是解释接口逻辑的示意记号，不是作者额外给出的模型公式：

\[
\widetilde o_t=g_r(o_t),\qquad
\widetilde a_t\sim\pi_\theta(\cdot\mid\widetilde o_{\le t},\text{history}),\qquad
a_t=P_r\widetilde a_t.
\]

其中 \(g_r\) 代表机器人相关的输入映射，\(P_r\) 代表输出选择。完整控制实现可能还需要动作缩放、偏置和约束，不能仅靠选择数组下标替代所有执行处理。

### 4.3 一个仅用于理解的例子

假设统一空间暂设 16 个关节槽位，机器人 A 有 12 个关节，机器人 B 有 16 个关节。这些数字仅用于举例，不是论文公开的槽位数。

机器人 A 把自己的关节数据写入规定的 12 个槽位；策略输出 16 个目标，A 只提取属于自己的 12 个。B 则按自己的映射组织输入并取出相应目标。

不是让 12 个数直接进入一个只接受 16 个数的线性层，也不是所有机器人都随意取前 N 个输出。槽位的对应关系必须有明确规则。

### 4.4 论文未完整披露的实现细节

已核对的正文和附录没有给出可直接复现的完整接口规格，包括：

1. 统一关节空间的确切大小与完整槽位表；
2. 每种机器人关节如何对应槽位；
3. 不存在的关节采用什么填充值，是否另设有效位掩码；
4. 完整观察字段、归一化和坐标约定；
5. 目标关节位置的缩放、偏置、限位和完整低层增益配置。

零填充和有效位掩码是可考虑的工程选择，但不能说成已经确认的作者实现。实际复现时必须把这些选择记录为自行补充的设计。

因此，严谨的答复是：

> 论文在方法层面以统一关节空间处理不同关节数量；但完整映射与缺失关节编码未公开到可直接照搬的程度。复现需要补齐接口规格并检验其影响。

## 5. 网络怎样知道是哪一种机器人

### 5.1 不一定需要输出机器人型号

控制所需的信息不必表现为“这是 G1、那是 Go2”的类别标签。策略可以根据当前关节状态和过去动作产生的响应，形成对当前控制条件有用的内部表示，再选择动作。

例如，同样改变关节目标，如果关节转动不足、身体姿态持续偏移，历史就提供了驱动或负载条件的线索。策略不必先把负载精确估计成某个公斤数，才能调整动作。

刚开始运行时历史较少，策略首先依赖训练获得的通用控制规律和当前观察。交互增多后，历史才提供更多依据。因此不保证任意新身体第一次动作就稳定。

### 5.2 “不提供精确形态”不等于“没有接口信息”

至少需要区分三种信息：

| 信息 | 作用 |
|---|---|
| 接口信息 | 关节数量、输入输出对应关系、方向和单位，用于连接设备与策略 |
| 精确形态/动力学描述 | 关节轴位置、肢体几何、质量、惯量等，可作为显式条件或模型 |
| 交互证据 | 发过什么动作、身体实际怎样响应，供策略在运行中调整 |

论文强调减少对精确运动学信息的依赖，并利用交互适应。不能因此声称软件完全不知道关节接口，也不能断言输入模式完全不提供任何身体线索。

### 5.3 证据支持到什么程度

Figure 4(b) 显示，不同身体的网络特征随着交互逐渐分开。这支持特征包含身体相关信息，但不能直接证明：

- 网络精确恢复了质量、惯量或完整骨架；
- 它有一个准确的机器人型号分类器；
- 任何未知机器人都能被识别并安全控制。

### 5.4 第三方代码中的 ID 不能当成论文结论

当前本地仓库来自 [lucidrains/locoformer](https://github.com/lucidrains/locoformer)，作者元数据为 Phil Wang，是第三方实现。

README 示例中：

```python
dim_state = [32, 16]       # 两种观察向量的维度，不是两种关节数量
state_id = 0              # 选择对应的输入 MLP
selector_index = 0        # 选择对应的动作输出分量
```

本地 `StateEmbedder` 在 `locoformer.py:1179` 为不同观察维度创建输入 MLP，并在 `:1208` 按 `state_id` 选择。ID 在此是程序路由信息，不能直接等同于给 Transformer 拼接了一个机器人类别 token；也不能借此证明原论文使用相同 ID 方案。

对应代码：[StateEmbedder](../../03_code/locoformer/locoformer/locoformer.py:1153)。

## 6. 已有研究怎样分类、比较

### 6.1 分类应有多个维度

可以分别问：

1. 面向单个身体，还是多个身体？
2. 是否显式输入身体结构或物理参数？
3. 用短历史估计隐变量，还是用长历史直接支持决策？
4. 部署时改变网络参数，还是只改变内部状态？
5. 使用什么训练方式和网络结构？

这些是交叉维度，下面的研究路线不是互不重叠的完整分类。

### 6.2 代表性研究路线

| 路线与代表 | 核心做法 | 优点 | 与本文的差异或比较边界 |
|---|---|---|---|
| 单平台专用运动策略 | 针对特定机器人训练、随机化和调参 | 对目标平台能取得较高性能，接口和约束清楚 | 迁移到不同拓扑通常需要额外适配；不是所有专用策略都没有适应能力 |
| 历史驱动的隐变量适应：RMA | 基础策略与适应模块结合，利用历史估计控制所需的环境隐变量 | 已展示快速、固定权重的在线适应 | 原工作主要验证特定四足平台，不等同于广泛跨形态控制 |
| 显式描述驱动的跨本体策略：URMA | 编码关节/足部观察与描述，使用共享控制器及形态相关解码 | 明确处理不同关节数量，结构信息有助于迁移 | 需要描述信息；不能把它简化成必须具备完整精确动力学模型 |
| 身体结构作为网络先验：Body Transformer | 将传感器和执行器组织为身体图，用掩码注意力利用结构 | 通过结构先验改善策略学习 | 身体图是输入先验；重点不是跨失败 Trial 的长时适应 |
| 程序化身体随机化：GenLoco | 在随机生成的多种四足身体上训练共享策略 | 证明了身体多样性可支持向未见机器人迁移 | 原工作主要研究相近四足形态；LocoFormer 进一步覆盖腿式/轮足、双足/四足与长历史适应 |
| 跨尝试记忆：RL²、AdA | 跨任务训练，通过运行中的记忆利用少量新交互 | 为固定权重的快速适应提供先例 | 并非专门解决本文的多身体高频运动控制系统 |

原始资料：[RMA](https://arxiv.org/abs/2107.04034)、[URMA](https://arxiv.org/html/2409.06366v4)、[Body Transformer](https://arxiv.org/abs/2408.06316)、[GenLoco](https://arxiv.org/abs/2209.05309)、[RL²](https://arxiv.org/abs/1611.02779)、[AdA](https://arxiv.org/abs/2301.07608)。各路线局限应理解为研究范围和所需信息的差别，不应在没有统一评测时直接排出优劣名次。

已有工作意味着：不能说 LocoFormer 首次提出跨机器人策略，首次提出根据历史适应，或首次提出跨尝试保留记忆。

## 7. Contribution 和 Method 怎样分别回答

### 7.1 贡献：增加了什么

结合摘要、方法和实验，可以归纳为三项；这是汇报中的归纳，不是声称作者逐字列出了三条：

1. **跨本体训练方案。** 将多种程序化身体与强动力学随机化结合，在宽任务分布上训练共享运动策略。
2. **面向高频控制的长历史适应。** 用 Transformer-XL 和跨 Trial 保留的经历，支持固定权重的运行中调整。
3. **相应的实验验证。** 在十种未见仿真机器人与多种实机变化上，展示迁移、额外交互收益和跨尝试改善。

前两项是方法设计，第三项是实验性贡献。论文价值在于这套组合解决的研究问题及其效果，不在于重新发明 PPO、Transformer-XL、注意力或 KV cache。

### 7.2 方法：具体怎样实现

| 部分 | 设计 | 解决的困难 |
|---|---|---|
| 输入输出接口 | 统一关节空间与机器人相关分量提取 | 不同关节数量和排列无法直接共享固定格式网络 |
| 训练任务 | 程序化双足、四足、轮式变体与强随机化 | 训练分布过窄，迁移后条件变化大 |
| 交互组织 | 同一任务可多次 Trial，身体可重置而历史保留 | 单次尝试可能来不及获得足够控制证据 |
| 记忆网络 | 观测 MLP、Transformer-XL、因果注意力、段间缓存与 SG | 长历史读取与训练计算成本 |
| 参数学习 | 以整组经历的回报目标组织训练，使用 PPO | 让利用历史的行为获得训练收益 |
| 训练课程 | 先短 Trial/小适应预算，再延长 | 逐步获得适应及持续控制能力 |
| 部署 | 固定权重，逐步更新历史，KV cache 加速 | 将已训练的历史使用能力用于实时控制 |

§2.1 给出形式化多 Trial 目标，并在实际训练中改为采样适应时间预算。原文未公开这个实现的全部损失掩码，不能补写成只训练最终 Trial。

## 8. Benchmark、Baseline 与指标必须一起解释

### 8.1 Benchmark：在哪里、按什么规则测试

Table 1 是十种训练中未出现的机器人：五种双足、三种四足、两种轮足；每种使用 1,000 个随机化仿真环境，并包含粗糙地形。

- Zero-shot：没有额外预评估交互预算，开始计分后仍会积累历史。
- Few-shot：先给 5 秒额外交互，再进行评估，后续可用此前经历。

因此两者的可用交互预算不同。Few-shot 得分更高可以支持交互有帮助，但不是严格相同预算下免费获得的提升。

训练覆盖很多程序化身体，与评估使用十种具体未见身体，是不同的数据划分。不能把约十万训练身体写成十万真实机器人，也不能把评测中的同名目标机器人纳入训练后仍称为该项零样本迁移。

### 8.2 Baseline：Table 1 实际比较了谁

| 对照方法 | 设置 | 平均得分 | 能说明什么，以及不能说明什么 |
|---|---|---:|---|
| LocoFormer zero-shot | 无额外预评估交互 | 0.96 | 检验直接迁移表现 |
| LocoFormer few-shot | 先交互 5 秒 | 0.98 | 检验额外交互后的表现；不是相同预算比较 |
| GRU | 论文称相同训练设置，换用 GRU 记忆 | 0.37 | 支持记忆架构影响表现；不自动证明参数量、全部计算条件完全匹配 |
| Conditioning | Transformer，提供特权运动学信息，历史为 64 步 | 0.78 | 同时改变输入和历史长度，不能只归因于其中一个因素 |
| Expert Policy | 在目标本体上直接训练 | 0.99 | 目标平台专用参照；不是未见本体泛化方法，也不是数学性能上界 |

论文没有在 Table 1 中逐个重跑 RMA、GenLoco、URMA、Body Transformer 的完整原始方法。因此应区分“相关工作中的方法对比”和“统一实验协议下的定量比较”。Conditioning 基线也不能未经实现核对就称为完整复现的 URMA。

### 8.3 Metric：0.96 代表什么

Table 1 使用朝随机目标方向的归一化位移，数值归一化到 [0,1]。0.96 不是 96% 成功率，也不是 0.96 米，更不等于速度误差。

结果的两个常见表述需要核对：

- 总均值从 0.96 到 0.98：提高 0.02 个归一化得分单位，相对约 2.1%。
- TRON1 从 0.87 到 0.96：提高 0.09，相对约 10.3%；论文所述约 10% 改善对应这个平台，而非全部机器人平均提升 10%。

对归一化分数使用相对提升时应同时保留绝对差值，避免夸大解读。已核对文本没有完整给出可直接实现的归一化细节；表中 ± 的统计含义也应进一步核对，不能自行标成 95% 置信区间。

### 8.4 其他证据分别回答什么问题

| 实验 | 衡量或展示的内容 | 结论边界 |
|---|---|---|
| Figure 4(a) | 在更强随机化下，增加适应时间，比较随后最多 6 秒的平均存活时间 | 总体收益不等于每个点严格单调，更不等于持续运行无限稳定 |
| Figure 4(b) | 不同身体的网络特征随交互逐渐分开 | 支持身体相关表示，不是精确参数辨识或机器人分类准确率 |
| Figure 5 实机案例 | G1、H1、Go2、Go2-W 及驱动/结构/负载变化下的行为 | 案例展示不等于全面故障恢复统计 |
| Figure 8 | 仿真 TRON1 跨 Trial 改善 | 不应与实机第三次 Trial 稳定的案例混为同一个实验 |

恢复时间、故障失败率、能耗和实时延迟都是后续值得系统报告的指标，但不能冒充本文已经提供的完整数据。

## 9. 优点、局限与尚未证实的内容

### 9.1 有依据的优点

- 同一个策略在所测多种身体上取得较好的迁移表现，减少每台机器人从头训练的需求。
- 利用交互历史调整动作，部署适应不必依靠现场反向传播。
- 保留失败 Trial 的经历，使后续尝试仍能利用先前信息。
- 基于已有可扩展网络和训练算法，不依赖一套新的复杂显式动力学辨识器。

### 9.2 论文承认的限制

§6 明确指出训练计算需求高，且程序化任务空间需要人工设计、覆盖不穷尽。Appendix A 也列出未被生成规则准确包含的真实结构差异。

作者[项目页的失败案例](https://generalist-locomotion.github.io/)进一步说明：某些情况下，突发变化发生后适应来不及完成，机器人仍会失败；训练中身体与特定物理属性在每个 Episode 内保持固定，是作者给出的部分解释。

### 9.3 从证据范围进一步得到的判断

- 十种未见仿真身体和若干实机案例，不能推出任意关节拓扑、任意传感接口都可直接使用。
- 固定权重不表示不需要关节映射、归一化、执行接口和控制配置。
- 跨 Trial 适应允许身体重置，不能将其表述成机器人摔倒后会自主起身。
- 长历史与大规模训练共同出现，现有结果尚不能完全分离所有收益来源。
- 部署初期缺少历史、变化过快或超出训练覆盖时，仍可能失败。

前一节已经区分了论文实际做过的实验与仍需补充的对照，不能笼统地说它“完全没有消融”。

### 9.4 怎样设计更严谨的后续验证

最直接的对照包括保留/清空跨 Trial 历史，以及不同历史范围的比较。需要明确：

1. 训练和测试的身体、随机种子及条件；
2. 模型参数量、训练交互量、优化次数和计算预算；
3. 哪些时间用于适应、哪些时间计分；
4. 物理重置是否一致，网络权重和缓存分别何时重置；
5. 稳定恢复的判定标准、失败时间上限和重复次数。

历史变长会改变计算量，不能轻易声称数据量、更新数、总计算量、运行时间全部完全固定。可以分别报告等数据/更新预算与等计算预算的结果，并说明取舍。

当前本地代码快照为 `79ce9d72d1137015e0212284f06656c83bb414e7`。Microduck 默认单平台环境、输入编码选择、动作处理、缓存边界及训练损失均需与论文分别核对。它含有论文之后的扩展，不能把所有代码功能归于原论文。

应将三种目标分开：

1. **模块复现**：网络、缓存、因果掩码和 PPO 能运行；
2. **机制复现**：在自行声明的训练设置下，验证历史与跨 Trial 经验是否产生适应收益；
3. **结果复现**：按作者设置和预算重现 Table 1、仿真适应曲线及实机结果。

完成第一种不自动等于完成第三种。第三方 Microduck 能训练走路，也不等于已经复现十万程序化身体训练出的跨本体模型。

> LocoFormer 研究未见腿式、轮足机器人的共享运动控制与在线适应。它用统一关节空间连接不同机器人，在大量程序化身体与强随机化条件下，通过 PPO 训练带有 Transformer-XL 长记忆的策略。同一任务中的历史可以跨 Trial 保留；部署时权重固定，策略利用新交互调整动作。论文在十种未见仿真机器人和多种实机变化中提供了支持证据，但统一接口的完整规格、作者训练代码与权重仍未确认公开，实验也不能证明任意机器人或任意故障都能适应。

## 12. 教师追问时的简答

**问：不同关节数量怎么处理？**

答：论文采用统一关节空间，先组织成统一输入，策略输出统一关节目标，再取出当前机器人的分量。完整槽位、缺失关节编码和映射表没有充分披露，需要明确作为复现缺口。

**问：网络怎么知道机器人型号？**

答：不必先做型号分类才能控制。它利用当前状态和动作响应形成有用表示；软件仍要提供正确接口映射。原文的身体相关特征可视化不等于精确物理参数辨识。

**问：主要 contribution 是什么？**

答：将大规模多身体训练与跨 Trial 长历史适应结合，用于高频跨本体运动控制，并以未见身体迁移与实机变化实验验证。PPO 和 Transformer-XL 本身不是新发明。

**问：属于哪类方法？**

答：基于 PPO 的跨本体强化学习策略，使用 Transformer-XL 和历史驱动的固定权重上下文适应。

**问：benchmark 和 baseline 是什么？**

答：前者是测试任务、环境和规则，后者是参与对照的方法。本文主要仿真评测是十种未见机器人；直接基线为 GRU、Conditioning 和目标平台 Expert。

**问：0.96 是成功率吗？**

答：不是，是归一化朝目标位移。最终解释还要结合平台、随机化环境、交互预算和统计口径。

**问：能直接用当前代码复现原文吗？**

答：当前代码是第三方实现，可支持模块学习和自行定义的机制实验；没有确认作者完整配置与权重，不能承诺直接复现 Table 1 和全部实机结果。
