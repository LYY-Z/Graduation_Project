# 最小复现与排障

## 0. 不要从真实机器人开始

真实机器人涉及相机标定、控制频率、限位、碰撞、安全中间层和硬件急停。论文的真实系统也有专门中层控制器。初学第一目标应是：在低维或仿真 Push-T 上，看懂一个 batch、跑通一次训练/评估、生成可视化 rollout。

## 1. 建议的三阶目标

### 阶段 A：官方 Colab（最小风险）

打开官方 README 提供的 **state** Colab。依次完成：运行全部单元格；记录数据中 `obs`、`action` shape；找到加噪与 MSE；找到采样循环；保存一次 rollout 图/视频。达标条件是能口述“哪一格是训练、哪一格是推理”。

### 阶段 B：本地仿真 Push-T

确认 CUDA/GPU、Python、PyTorch 版本与官方仓库当前 README 兼容后，再按 README 建环境和获取数据。首次只用仓库已有配置训练/评估；不要一上来改模型、数据、horizon 三项。达标条件是：能复现实验命令、找到输出日志/checkpoint、对比闭环指标。

### 阶段 C：修改一个受控变量

只选一项改动，例如 $T_a$、推理步数、是否图像观测或 CNN/Transformer。保持随机种子、数据切分、评估 rollout 数不变。记录：改什么、为何、训练损失、成功率、视频行为、是否因延迟/抖动失败。

## 2. 每次运行前的检查表

- 数据是否为演示 episode，而不是把动作错当观测？
- `To/Ta/Tp` 是否清楚并在配置、dataset、policy 三处一致？
- normalizer 是从训练集拟合、并用于验证/推理的吗？
- 图像颜色通道、尺寸、裁剪和相机顺序是否一致？
- 用的是训练时的 scheduler 还是推理时的 scheduler？推理步数是多少？
- 评价的是闭环 rollout 成功率/覆盖率，还是仅训练 MSE？

## 3. 必须保存的实验记录


## 4. 何时再碰真实机器人

只有在仿真中能稳定复现、能解释失败、并有导师/实验室批准的硬件安全流程时，才考虑真实部署。策略模型不应直接绕过实验室既有的安全控制、速度/力矩限制与紧急停止规范。

## 5. 常见症状到检查点

| 症状 | 先检查什么 | 为什么 |
|---|---|---|
| loss 不下降或出现 NaN | 学习率、归一化、数据范围、噪声日程 | 扩散训练对数值尺度敏感 |
| loss 下降但 rollout 失败 | 闭环评估、动作坐标系、延迟、执行切片 | 离线噪声 MSE 不等于控制成功 |
| 动作只抖不前进 | \(T_a,T_p\)、推理步数、观察与动作对齐 | 计划可能不连贯或条件错位 |
| 图像模型失败而低维成功 | 相机顺序、裁剪/颜色、视觉 encoder 是否训练 | 视觉输入的预处理常是差异来源 |
| 结果无法复现 | 随机种子、配置、数据版本、checkpoint | 需要能比较“唯一改变的变量” |
