# 第 12 节：其他模块、基线、脚本与测试

## 本节要回答的问题

官方仓库不只有主线 Diffusion Policy。哪些目录对理解视觉扩散训练最重要？其他 policy、脚本、测试和通用工具分别是什么？需要一次全部学会吗？

结论先说：不需要。按“当前主线能跑通并解释”的目标，先掌握前 11 节；其余模块按问题查阅。

## 1. 仓库分区地图

| 区域 | 职责 | 什么时候读 |
|---|---|---|
| policy/ | 策略类：输入观测、算训练 loss、做动作预测 | 学习方法主线、追踪输入输出 |
| workspace/ | 实验生命周期：建数据、训练、验证、保存 | 理解训练脚本如何编排任务 |
| dataset/ 与 common/replay_buffer.py | 数据读取、切分、采样、归一化 | batch 内容或时间窗口不对时 |
| model/ | U-Net、视觉编码器、扩散层等网络组件 | 追踪策略内部的具体网络 |
| env_runner/ | 把策略放进模拟环境评估 | rollout 指标或视频有问题时 |
| real_world/ | 相机、机器人状态、控制器和真机流程 | 阅读真机路径时 |
| gym_util/、common/ | 环境包装、通用数据/时间/配置工具 | 被主线调用到时再追 |
| scripts/ | 数据转换、指标处理、辅助命令 | 需要准备数据或查看某种指标时 |
| tests/ | 针对关键工具和接口的自动检查 | 修改代码后或想确认一个工具契约时 |

## 2. 主线以外的策略是什么

仓库可能包含：

- 低维状态 Diffusion Policy：不以图像为主输入，用位置/状态向量作为条件。
- Hybrid Diffusion Policy：图像与低维状态一起提供条件。
- Transformer diffusion：用 Transformer 结构预测动作噪声，和 U-Net 是不同网络实现。
- 视频策略：处理/预测视频或相关序列。
- BET、IBC/DFO、Robomimic 等基线：与扩散策略进行比较的其他策略实现或复用接口。

它们共享部分概念（观测、动作序列、训练 Workspace、评估），但算法目标、网络和配置不能互相替换。论文聚焦的模型才是首次读代码的中心。

## 3. common/ 为什么看起来到处都被调用

通用模块通常提供很多策略都要用的基础功能，比如：

- ReplayBuffer：统一按 episode 存放演示；
- Normalizer：保存数值缩放规则；
- 采样器、时间戳、队列和进程管理；
- checkpoint、日志或环境包装辅助函数。

把这些抽成共享模块，策略代码就不必重复实现。读代码时先确认调用者需要它完成什么，再只追那个函数，不用一上来把 common/ 全部读完。

## 4. 脚本与测试的边界

scripts/ 中常有数据转换、运行统计、图像/视频处理等一次性或辅助程序。它们不是主训练算法，除非你要处理对应数据格式。

tests/ 通过小输入检查工具行为，例如 episode 边界、采样窗口、相机接口、时间戳或控制器接口。测试不是训练数据，也不会自动证明策略会完成任务；它们主要检查代码组件的约定没有被破坏。

例如 replay buffer 的测试能帮助确认切片是否越过 episode，但不能替代 Push-T rollout 成功率。

## 5. 遇到不懂的模块，使用“调用者优先”读法

1. 先从你正在读的主线代码找到调用位置。
2. 看传进去的参数和期待返回值。
3. 打开被调用函数，只看与这次调用有关的分支。
4. 用输入 shape、类型和语义写一句话总结。
5. 回到调用者，确认结果怎样被使用。

这通常比从一个庞大工具文件的第一行开始读更有效。
