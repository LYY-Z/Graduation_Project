# 第 13 节：端到端复习图与自测

## 目标：能够讲清楚一次训练和一次闭环推理

本节把前 12 节压缩成两条可复述的数据流。重点不是背文件名，而是每个阶段输入什么、输出什么、由谁负责。

## 1. 训练全流程

~~~text
train.py
  │  Hydra 读取 YAML，创建指定 Workspace
  ↓
Workspace.run()
  ├─ 依据任务配置创建 Dataset / DataLoader
  ├─ Dataset 从 ReplayBuffer 取 episode 时间窗口
  ├─ batch 整理成 image、state、action 等张量并归一化
  ├─ Policy 把观测编码为条件特征
  ├─ 对演示动作序列加随机高斯噪声，并抽取扩散步
  ├─ Conditional U-Net 根据“带噪动作 + 观测条件 + 扩散步”预测噪声
  ├─ MSE 衡量预测噪声与实际注入噪声的差距
  ├─ backward + optimizer 更新在线模型，EMA 平滑模型参数
  ├─ 周期性计算验证 loss、在模拟环境 rollout
  └─ 记录日志并保存 checkpoint
~~~

每个模块的角色：

- YAML 选择对象与数值参数；
- Workspace 管理实验；
- Dataset 决定样本片段；
- Policy 决定方法输入输出；
- Model 负责神经网络的可学习计算；
- optimizer 负责参数更新；
- runner 测策略在环境中的闭环表现。

## 2. 推理与环境交互全流程

~~~text
环境 / 真实传感器提供最新观测 O_t
  ↓
Policy 对图像和状态做训练时一致的预处理/归一化
  ↓
视觉编码器和状态分支得到条件特征
  ↓
从随机动作计划开始，scheduler 循环多次调用去噪网络
  ↓
得到一段动作计划，反归一化并选取要执行的前段
  ↓
环境 / 控制器执行动作并产生新状态
  ↓
重新观测，再规划；直到 episode 终止
~~~

“随机动作计划”是采样开始时的一组噪声数字，不是机器人先随机乱动；采样过程在模型内部完成，模型输出后才把动作交给环境/控制器。

## 3. 最重要的区别卡片

| 容易混淆的东西 | 正确区分 |
|---|---|
| 训练 loss vs 任务成功率 | 前者是噪声预测误差，后者是闭环执行结果 |
| 扩散步 k vs 环境时刻 t | k 是模型内部去噪；t 是真实/模拟交互时间 |
| Policy vs U-Net | Policy 管理输入、条件、采样与输出；U-Net 是其中一种去噪网络 |
| scheduler vs 网络 | scheduler 按公式加噪/更新样本；网络预测噪声 |
| 计划 horizon vs 实际执行步数 | 计划长度与本轮执行长度可以不同 |
| 在线模型 vs EMA 模型 | 在线模型实时训练；EMA 是参数历史平滑副本 |
| 模拟评估 vs 真机评估 | 前者在可重置环境中运行；后者连接真实设备且有硬件风险 |
| image vs hybrid 配置 | 要查实际观测键和 shape，不可只按名字推断 |

## 5. 自测题

先尝试自己回答，再看简答要点。

1. train.py、Workspace、Policy、U-Net 各自承担什么角色？
2. Dataset 输出的一条样本为什么常包含一段时间，而不是一个单独状态/动作？
3. 训练时网络看到的动作是什么状态？监督目标是什么？
4. 观测图像为什么不是和动作一起被加噪？
5. MSE 降低为什么不保证 rollout 成功？
6. EMA 对什么做平滑？评估为什么可能选 EMA 模型？
7. 一次推理中，去噪网络循环与环境交互循环有什么区别？
8. 为什么策略只执行动作计划的一部分，然后重新观察？
9. eval.py 与 train.py 有什么区别？
10. 真机 observation 与训练配置不一致可能导致什么问题？

### 简答要点

1. 入口解析配置；Workspace 编排实验；Policy 组织观测条件、训练损失和动作采样；U-Net 是被 Policy 调用的去噪网络。
2. 方法预测动作轨迹，用一段时间上下文表达动作间的协调关系。
3. 动作演示被加噪；目标是网络恢复前向过程实际加入的噪声。
4. 论文把观测作为条件，把动作序列作为生成对象；观测提供“当前发生什么”的信息。
5. loss 只测训练目标，不直接测机器人与环境组成的闭环系统。
6. EMA 平滑模型参数；它常有较稳定的泛化表现，但应遵照具体 Workspace 和评估配置。
7. 去噪循环是模型内部生成计划；环境循环是真实执行、重新观测和规划。
8. 新观测能纠正模型预测与现实之间的偏差。
9. train 学参数并保存；eval 加载既有参数并测表现。
10. 可能 shape/字段不匹配，也可能单位或语义不一致而产生错误控制。

## 6. 推荐的复习方法

1. 从本目录 [学习路线](README.md) 看完整 13 节结构。
2. 不看答案画出训练数据流和推理闭环。
3. 从每个表格的问题定位到实际仓库文件，确认一处代码证据。
4. 若卡在扩散数学，回到 [DDPM 基础](../../01_foundations/02_ddpm_from_intuition_to_formula.md)；若卡在论文方法，回到 [论文学习地图](../../README.md)。
5. 用自己的话讲一次“演示数据如何变成可执行动作”，而不是逐字背公式。

完成这套学习后，合理的目标是能读懂视觉扩散策略的主训练和推理路径、辨认主要配置与数据形状，并能继续独立查阅扩展模块；这不等于已经掌握仓库所有策略，也不等于可以不经安全准备运行真机代码。
