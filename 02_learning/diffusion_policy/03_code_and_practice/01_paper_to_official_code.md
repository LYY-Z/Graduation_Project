# 论文到官方代码：符号、张量与数据流

> 目标：先在低维仿真任务中读懂并跑通完整数据流，再接触真实机器人。不要一上来就把模型接到机械臂上。

## 1. 复现前最重要的认识

论文公式中的一个“样本”，在代码里不是一张猫图，而是一段动作张量：

\[
A_t^0 \in \mathbb R^{B\times T_p\times D_a}
\]

其中：

- \(B\)：一个训练批次里有多少段示范；
- \(T_p\)：每段要预测多少个未来动作；
- \(D_a\)：每个动作有多少维，例如 \((x,y,z,\text{旋转},\text{夹爪})\)。

模型从来不是“看一张图，直接输出机械臂命令”这么简单。完整链条是：

\[
\text{演示数据}
\rightarrow
\text{切时间窗口}
\rightarrow
\text{归一化}
\rightarrow
\text{加噪动作序列}
\rightarrow
\text{预测噪声}
\rightarrow
\text{采样动作序列}
\rightarrow
\text{只执行前 }T_a\text{ 步}
\]

如果其中任一环节的单位、形状、时间对齐错误，损失下降也不代表机器人会成功。

---

## 2. 推荐的最小复现顺序

按下面顺序做，失败时定位最容易。

1. **只读论文的低维任务配置。** 不用相机，只用环境给出的状态向量。
2. **检查数据集。** 打印一个样本的键、形状、最小值和最大值。
3. **跑通一次训练前向。** 确认网络输出的噪声张量与目标噪声同形状。
4. **让训练损失正常下降。** 这只是必要条件，不是成功条件。
5. **在仿真中滚动执行。** 录制轨迹或视频，检查真正的任务成功率。
6. **再换成图像输入。** 先检查相机帧、裁剪、颜色通道、时间对齐。
7. **最后才考虑真实机器人。** 先使用速度/位置限幅和安全空间测试。

低维任务通常比视觉任务更适合第一轮学习，因为它把问题缩小到“动作扩散与控制循环”，而不是同时调试相机和视觉网络。

## 3. 一条训练数据在代码中怎样流动

假设数据集中保存了轨迹：

\[
(o_0,a_0),(o_1,a_1),\ldots,(o_L,a_L)
\]

在真实时刻 \(t\)，数据加载器通常取：

\[
O_t=(o_{t-T_o+1},\ldots,o_t)
\]

作为观察窗口，取：

\[
A_t^0=(a_t,a_{t+1},\ldots,a_{t+T_p-1})
\]

作为监督的干净动作序列。

### 3.1 训练伪代码

```text
for batch in dataloader:
    obs = 取最近 To 帧观察                    # [B, To, ...]
    action_clean = 取未来 Tp 个专家动作        # [B, Tp, Da]

    obs = normalizer.normalize(obs)
    action_clean = normalizer.normalize(action_clean)

    k = 为批次中每个样本随机抽扩散步           # [B]
    eps = 与 action_clean 同形状的标准高斯噪声
    action_noisy = scheduler.add_noise(action_clean, eps, k)

    eps_pred = model(obs, action_noisy, k)     # [B, Tp, Da]
    loss = mean((eps_pred - eps) ** 2)

    optimizer.zero_grad()
    loss.backward()
    optimizer.step()
    ema.update(model)                          # 如果工程使用 EMA
```

这段代码对应论文的核心训练目标：

\[
\mathcal L(\theta)=
\mathbb E\left[
\left\|\epsilon-epsilon_\theta(O_t,A_t^k,k)\right\|^2
\right]
\]

关键核对项：

- `eps` 是你刚刚抽出的、已知答案的噪声；
- `eps_pred` 必须同形状；
- `k` 对每个样本可不同，网络必须知道它；
- 训练时的 `action_clean` 必须是专家动作，不能误用环境未来状态；
- 所有归一化统计量都只能从训练集计算。

### 3.2 一条样本的形状例子

若批大小 \(B=32\)，观察历史 \(T_o=2\)，预测长度 \(T_p=16\)，动作维度 \(D_a=7\)，那么：

| 张量 | 可能形状 | 解释 |
|---|---|---|
| `obs`（低维） | `[32, 2, Do]` | 两帧状态观察 |
| `action_clean` | `[32, 16, 7]` | 16 步专家动作序列 |
| `eps` | `[32, 16, 7]` | 人工加入的高斯噪声 |
| `action_noisy` | `[32, 16, 7]` | 带噪动作序列 |
| `k` | `[32]` | 每个样本的扩散时刻 |
| `eps_pred` | `[32, 16, 7]` | 模型预测噪声 |

视觉输入可能为 `[32, 2, 3, H, W]`；先由视觉编码器变成特征，再与动作去噪网络结合。图像和动作的维度不同没有问题，因为模型负责把观察变成条件信息；但噪声预测的输出必须与动作张量同形状。

## 4. 推理和机器人控制循环

推理时没有专家动作，因此从纯噪声动作块开始。

```text
while 任务尚未结束:
    obs = 读取最近 To 帧真实观察
    obs = normalizer.normalize(obs)

    action = 标准高斯噪声                    # [1, Tp, Da]
    for k = K, K-1, ..., 1:
        eps_pred = ema_model(obs, action, k)
        action = scheduler.step(eps_pred, k, action)

    action = normalizer.unnormalize(action)
    execute(action[0 : Ta])
```

这里最容易误解的点是：

- 内层 `k`：扩散模型在计算机内部做的去噪步骤；
- 外层 `while`：机器人在真实世界不断“观察—规划—执行—再观察”的控制循环；
- `action[0:Ta]`：只发送新计划开头的 \(T_a\) 个动作，不发送完整 \(T_p\) 个动作。

因此，机器人**不会**执行 \(K\) 次随机动作。\(K\) 次操作发生在内存中的动作张量上，直到它被去噪成一段可执行的计划。

## 5. 归一化：最容易被忽略、也最容易毁掉训练的部分

不同动作维度的单位可能不同：位置用米、角度用弧度、夹爪用 0 到 1。若不处理，数值大的维度会主导 MSE。

论文的实践包含逐维 min-max 归一化到大约 \([-1,1]\)；低方差维度则应避免被非常小的范围放大。部署时必须使用训练时保存下来的同一组统计量反归一化。

你要明确记录：

1. 每个观察和动作字段的原始单位；
2. 训练集计算出的 `min/max` 或 `mean/std`；
3. 旋转表示是什么（欧拉角、轴角、四元数、6D rotation 等）；
4. 推理时是否用了同一坐标系和同一统计量；
5. 动作发给控制器前是否做了限幅。

不能使用测试轨迹来计算归一化统计量，否则会发生数据泄漏。

## 6. 从论文概念到典型代码模块

不同版本仓库的文件名可能变化，但职责通常如下。

| 论文概念 | 代码中应寻找的职责 | 要检查什么 |
|---|---|---|
| \(O_t\) | dataset / observation encoder | 时间窗口、相机顺序、数据增强 |
| \(A_t^0\) | action horizon slicing | 是否取的是未来专家动作 |
| 加噪公式 | scheduler 的 `add_noise` | 噪声和动作形状、`k` 是否正确 |
| \(\epsilon_\theta\) | temporal CNN / Transformer policy | 输入条件、时间嵌入、输出维度 |
| MSE 损失 | training workspace / loss function | 是否对噪声而不是干净动作算损失 |
| 反向采样 | scheduler 的 `step` | 推理步数、随机性、时间顺序 |
| 滚动时域 | environment runner / real robot runner | 只执行 \(T_a\)，重新观测的时机 |
| EMA | model averaging / checkpoint | 评估到底使用在线模型还是 EMA 模型 |

读代码的顺序建议是：`配置文件 → 数据集 → policy.forward → loss → scheduler → runner/eval`。先画数据流，不要一开始钻进网络中每一层卷积。

## 7. 第一轮复现应记录什么

每次实验至少记录以下信息，否则以后无法比较：

| 类别 | 必须记录 |
|---|---|
| 数据 | 任务名、示范数量、训练/验证划分、状态或图像、动作单位 |
| 时间参数 | \(T_o,T_p,T_a\)、控制频率、扩散训练步数和推理步数 |
| 模型 | CNN/Transformer、视觉编码器、参数量、是否 EMA |
| 优化 | batch size、学习率、随机种子、训练步数 |
| 结果 | 训练损失、验证损失、成功率、失败视频、推理耗时 |

训练损失低但成功率低时，不要直接加训。先看一条 rollout 视频：它是观察错位、动作单位错、坐标系错、控制延迟，还是策略本身不够好？

## 8. 常见故障的“症状 → 首查项”

| 症状 | 优先检查 |
|---|---|
| 一开始 loss 为 NaN | 数据是否有 NaN/Inf、归一化分母是否接近 0、学习率是否过大 |
| `eps_pred` 形状不匹配 | 动作维度、horizon、batch/time 维是否交换 |
| loss 下降但动作像随机 | 采样器时间顺序、推理是否加载了训练权重/EMA、是否反归一化 |
| 机器人动作幅度异常大 | 单位、min-max 统计量、坐标系、限幅 |
| 图像模型失败而低维模型正常 | 相机时间同步、RGB/BGR、裁剪、相机外参、视觉编码器训练 |
| 只在训练集演示附近有效 | 示范覆盖不足、没有恢复数据、测试状态分布不同 |
| 控制有明显滞后 | 推理耗时、队列堆积、\(T_a\) 和控制频率、观测时间戳 |

## 10. 最终自测：能否说“已经学会这篇论文”

请脱离笔记回答；不会的题目回到对应章节补上。

1. 这篇论文是强化学习吗？它训练信号来自哪里？
2. \(A_t^0\)、\(A_t^k\)、\(O_t\)、\(k\) 分别是什么？
3. 为什么多模态动作会让普通 MSE 回归出现平均动作？
4. 训练时网络为什么预测人工加入的 \(\epsilon\)，而不是直接预测一个动作？
5. 推理时为什么从高斯噪声动作块开始？
6. `eps_pred` 和 `eps` 在代码中必须具有怎样的形状关系？
7. \(T_p\) 和 \(T_a\) 的区别是什么？为什么不执行整个 \(T_p\)？
8. `k` 和真实机器人时间 \(t\) 为什么不能混为一谈？
9. 为什么低训练损失不足以证明策略可用？
10. 为什么归一化统计量必须保存并用于部署？
11. CNN 与 Transformer 各适合什么情形？
12. DDIM 类采样器主要想解决什么工程问题？
13. 论文的“46.9% 相对提升”能否直接承诺给你的任务？为什么？
14. 若策略在真实机器人上动作爆冲，你的前三个检查是什么？
15. 用 5 句话说出论文完整的训练和执行流程。

### 参考答案骨架

1. 主要是模仿学习；从专家示范动作监督学习，不依赖奖励在线探索。
2. 分别是干净专家动作块、该动作块第 \(k\) 级噪声版本、最近观察窗口、扩散内部时间步。
3. 因为损失倾向条件均值，而均值可能不属于任何一种可行策略。
4. 加入的噪声已知，目标稳定；预测噪声可用于逐步恢复条件动作分布。
5. 前向训练把数据连到已知高斯先验，反向网络学习从该先验采样。
6. 完全同形状，通常都是 `[B,Tp,Da]`。
7. \(T_p\) 是计划长度，\(T_a\) 是本轮实际执行长度；只执行开头以获得闭环纠错。
8. \(k\) 是计算中的去噪索引，\(t\) 是现实世界控制时刻。
9. 离线误差不能发现闭环分布漂移、坐标系错配和控制延迟。
10. 否则推理数值尺度与训练不一致，动作含义被改变。

完成后，你已经具备阅读论文、解释核心公式、浏览实现并启动低维复现的知识基础。真实机器人部署仍需要在你的硬件、控制器和安全规范下单独验证。

## 9. 论文符号与官方仓库命名

| 论文概念 | 常见官方代码名 | 典型张量形状 | 作用 |
|---|---|---|---|
| 观察历史 \(T_o\) | n_obs_steps | \(B,T_o,D_o\) 或图像 batch | 策略可看多少历史 |
| 动作执行长度 \(T_a\) | n_action_steps | 动作时间维的前段 | 每轮真正发给环境多少步 |
| 预测时域 \(T_p\) | horizon | \(B,T_p,D_a\) | 完整未来动作计划长度 |
| 干净计划 \(A_t^0\) | action | \(B,T_p,D_a\) | 数据集示范或生成结果 |
| 带噪计划 \(A_t^k\) | noisy_action | \(B,T_p,D_a\) | 网络当前去噪对象 |
| 扩散步 \(k\) | timesteps | \(B\) 或 \(B,1\) | 告诉网络当前噪声等级 |
| 条件 \(O_t\) | obs / global_cond | 依任务而定 | 图像和本体状态特征 |
| 噪声预测器 | ConditionalUnet1D / transformer | 输出同 \(A_t^k\) | 预测已注入的噪声 |

官方仓库的数据流应按下列顺序追踪，而不要先钻入每一层卷积：

\[
\text{dataset window}
\rightarrow\text{normalizer}
\rightarrow\text{visual/state encoder}
\rightarrow\text{noise scheduler add\_noise}
\rightarrow\epsilon_\theta
\rightarrow\text{scheduler step}
\rightarrow\text{action slice}
\rightarrow\text{environment rollout}.
\]

读代码时每到一层先写下形状。若形状从 \(B,T_p,D_a\) 变成其他形式，先问“哪一维是 batch、时间、动作维或特征维”，再判断实现是否正确。
