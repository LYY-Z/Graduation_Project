# 01　先看懂工程，再看懂 Python

[教材目录](README.md) · 下一章：[硬件和观察](02_hardware_and_observations.md)

本章的目标是让你能沿着代码读下去。不是把一本 Python 教科书塞进工程说明，而是先解释这份工程实际出现的语法，再指出它在部署中为什么有用。代码片段分为“来自本工程的简化片段”和“纯教学例子”；简化片段帮助理解，完整边界条件仍以链接中的实际文件为准。

## 1. 从文件夹到程序，中间发生了什么

你双击一张图片，系统会选择图片查看器。Python 源文件 `.py` 则需要 Python 解释器读取并执行。“解释器”就是执行这门语言的程序；`python` 是终端中找到它的常见名字。同一台服务器可以安装多个 Python，分别拥有不同版本和第三方库，所以“系统里装过 Python”并不能保证当前命令用了正确的那个。

“项目”是整个文件夹，包含代码、配置、模型、说明、测试和运行记录。“包”是可被 Python 导入的一组模块，本工程包名为 `dp_ur7e`。“模块”通常就是一个 `.py` 文件，例如 `geometry.py`。项目目录名可以是 `diffusion_policy_ur7e`，包名仍是 `dp_ur7e`，两者不必一致。

```text
diffusion_policy_ur7e/   项目根目录
├─ pyproject.toml                  包名、依赖与安装信息
├─ config.example.yaml             可公开的配置模板
├─ config.yaml                     本机配置；由模板复制，默认不提交
├─ src/dp_ur7e/                    Python 能导入的适配包
├─ third_party/diffusion_policy/   固定版本的原论文实现
├─ third_party/ur_rtde_guarded/source/  私有控制库源码
├─ .runtime/                       当前帧、控制后端等运行材料
├─ models/                         权重、官方配置和来源清单
├─ tests/                          不连接硬件的自动检查
└─ runs/                           每次运行留下的独立记录
```

隐藏目录名 `.runtime` 开头的点，在 Linux 通常表示默认不显示，并不赋予它特别的安全能力。“根目录”是这份项目最外层目录；“当前工作目录”是终端现在所在的目录，二者可以不同。“绝对路径”从盘符或 `/` 起写完整位置，“相对路径”从某个约定起点寻找文件。`config.py` 会明确把配置中的工程内路径解析为完整路径，而不是在每个模块里猜当前目录。

### 为什么使用 `src/` 布局

真实包放在 `src/dp_ur7e`，可以减少“碰巧在项目根目录所以 import 成功”的混乱。安装为可编辑包时，Python 知道到哪里找源代码，修改源文件通常不必重新复制一遍包。系统 ROS Python 未安装这个包时，可以在专用桥接终端显式设置 `PYTHONPATH` 指向 `src`。这两种办法是告诉解释器“模块在哪里”，不是安装 ROS 或下载模型。

不要通过反复复制 `.py` 文件来修复 `ModuleNotFoundError`。先看究竟用了哪个解释器、包是否安装、导入路径是否正确。缺少 `rclpy` 多半发生在 ROS 环境，缺少 `torch` 多半发生在模型环境；把它们同时塞进所有环境未必解决冲突。

## 2. 终端命令如何到达主流程

统一命令形式为：

```text
python -m dp_ur7e inspect --config config.yaml
```

逐项理解：`python` 选择解释器；`-m` 要求按模块或包执行；`dp_ur7e` 是包；`inspect` 是交给本工程解析的子命令；`--config` 是参数名，后面的 `config.yaml` 是参数值。空格用于分开参数，文件路径含空格时要加引号。

[__main__.py](../../../03_code/diffusion_policy_ur7e/src/dp_ur7e/__main__.py) 是包以 `-m` 运行时的入口，职责很小：转交给 [cli.py](../../../03_code/diffusion_policy_ur7e/src/dp_ur7e/cli.py) 的 `main()`。`cli` 是 command-line interface，即命令行接口；它处理“用户选择了什么”，[pipeline.py](../../../03_code/diffusion_policy_ur7e/src/dp_ur7e/pipeline.py) 处理“选中的流程应该按什么顺序完成”。

```python
from .cli import main

if __name__ == "__main__":
    main()
```

第一行导入函数，不等于调用函数。前面的点表示同一个包内部的相对导入。`if` 是条件，冒号表示后面开始缩进代码块。`__name__` 在直接执行时具有特殊值 `"__main__"`，满足条件才调用 `main()`。括号 `()` 表示函数调用；仅写 `main` 则是在指向这个函数本身。

`__init__.py` 用于包初始化和标识。这里应该保持普通、轻量，不在导入时接相机、加载模型或发送指令。于是读取帮助、做配置检查时，不会因为“导入一个文件”就悄悄启动设备。

## 3. 变量、类型和单位先分开

变量是给一个值取名字。例如：

```python
max_step_m = 0.001
max_commands = 3
execute = False
mode = "preview"
```

它们依次是浮点数、整数、布尔值和字符串。布尔值只有 `True`、`False` 两种，Python 大小写敏感。`"False"` 带引号，是一段非空文字，不能当作布尔假值使用。因此配置解析器会认真检查类型，避免把拼写相似的文字当成真实开关。

`max_step_m` 里的 `_m` 是作者添加的单位提示，Python 本身不知道米。`0.001` 表示 1 mm，是因为代码约定这项用米；把它改成 `1` 不是“更清楚地写 1 mm”，而是写了 1 m。`_s` 常表示秒，`_rad` 表示弧度，`_m_s` 表示米每秒，`_m_s2` 表示米每秒平方。

`None` 表示没有值或尚未创建。例如 `control = None` 表示当前还没有控制客户端。它不是数字零，也不是字符串 `"None"`。预演模式保留 `None`，正好让代码明确区分“只有数值候选”和“已有发送通道”。

### 列表、元组和字典

```python
pose = [0.25, 0.42, 0.70, 0.0, 3.14, 0.0]
image_shape = (96, 96, 3)
observation = {"image": image_array, "agent_pos": position_array}
```

列表用方括号 `[]` 表示一组有次序的元素；元组常用圆括号 `()` 表示固定组合；字典用大括号 `{}` 把名字映射到值。`pose[0]` 取第一个数，Python 从 0 编号。`observation["image"]` 用字符串键寻找图像数组；这不是按第几个元素查找。

配置也是嵌套字典：`cfg["paths"]["frame_store"]` 先找到 `paths` 这一组，再找到其中的 `frame_store`。这里的方括号接连出现，是连续查找，不是矩阵乘法。

`cfg` 是 configuration 的常见缩写，不是 Python 关键字。`obs` 常缩写 observation；`q` 在机器人代码中常表示关节角；`p` 常表示位置；这些名字要结合上下文和单位阅读，不能仅凭字母判断。

## 4. NumPy 数组和 shape：代码里的数据容器

NumPy 是处理多维数字数组的库，通常写为 `import numpy as np`。数组与普通列表的差别在于它明确记录形状和数值类型，并能批量计算。

```python
import numpy as np

v = np.asarray([3.0, 4.0], dtype=np.float64)
length = np.linalg.norm(v)
```

`np.asarray` 将输入转换为数组；`dtype` 表示每个元素怎样存储；`float64` 是 64 位浮点数。`norm` 在这里计算欧氏长度，结果为 5。实际限幅中把 `[3,4] mm` 缩到长度 1 mm，就得到 `[0.6,0.8] mm`。不能把“向量每项小于 1 mm”和“总长度小于 1 mm”混为一谈。

`shape` 是数组每个轴的长度。例如 `(2,3)` 表示两行三列，包含六个数。`(6,)` 表示一个长度六的一维数组，末尾逗号是 Python 表示单元素元组的语法。它与 `(1,6)` 不同：后者额外有一个长度一的轴。

```python
np.asarray(value, dtype=np.float64)
np.all(np.isfinite(result))
result.copy()
```

这三行的意思分别是“转成指定类型的数组”“每一项都必须是有限数”“给出独立副本”。有限数不包括 `NaN` 和正负无穷；这些值进入运动几何后，普通比较可能产生难以察觉的结果，所以输入先被拒绝。

`copy()` 也有实际意义：如果历史记录和正在更新的缓冲区指向同一块数组，后来修改缓冲区可能把过去的样本一起改掉。副本让已经接收的样本保持独立。它消耗少量内存，却使“记录是什么”更明确。

## 5. 函数：把一项输入变成一项输出

```python
def metres_to_mm(distance_m):
    return distance_m * 1000

result = metres_to_mm(0.001)
```

`def` 定义函数，`distance_m` 是参数，缩进中的 `return` 返回结果。定义函数时不会执行内部计算；最后一行调用函数后 `result` 才变为 `1.0`。如果没有 `return`，函数默认返回 `None`。

在 [geometry.py](../../../03_code/diffusion_policy_ur7e/src/dp_ur7e/geometry.py) 中，`finite_vector(value, size, name)` 把“检查向量形状、检查有限性、复制”集中成一件事。不同模块复用这个函数，比每处各写一套稍有差异的检查更容易审查。

```python
def propose(self, desired_base_xyz, actual, *, source_age_s):
    ...
```

这里 `*` 后面的 `source_age_s` 要用名字传入，例如 `source_age_s=0.8`。代码阅读时能立即看出 0.8 是观察年龄，而不是位移或速度。`...` 在本章示例中表示省略正文，不是建议替换真实实现。

类型标注如 `size: int`、`-> np.ndarray` 是给读者和工具的提示，不会自动替代运行检查。即使写了 `size: int`，仍应在关键入口验证真实数据。

### import 与延迟导入

`from .geometry import finite_vector` 表示从同包的 geometry 模块取出这个名字。导入一次后，其他代码可以直接调用它。在本工程里，`torch`、ROS 和控制模块的一些导入放在具体函数里：只有确实选择相应模式，才依赖那套环境或加载原生模块。这叫延迟导入。

延迟导入帮助实现明确边界：`--help` 不需要 GPU，`inspect` 不需要相机，纯限幅测试不需要 RTDE。它不代表函数执行时可以缺少依赖；只是把需要发生的时刻放在正确的位置。

## 6. 类、实例和 self：让数据与操作待在一起

“类”定义一种对象有哪些数据和操作；“实例”是按这份定义创建的一个具体对象。你可以把 `ActionGuard` 理解为“本次运行的数字守卫”：它不仅知道限制，还记住已经消耗多少路径、上一条增量和起始姿态。

```python
guard = ActionGuard(initial_pose, limits)
target = guard.propose(desired, actual, source_age_s=0.8)
```

第一行创建实例，变量 `guard` 指向它；第二行调用这个实例的方法。方法是放在类中的函数。`self` 指向当前这个实例，因此 `self.path_m` 是这一轮守卫自己的累计路径。如果同时创建另一个守卫，两者记录的预算可以不同。

`__init__` 在实例创建时初始化数据，例如把 `commands` 设为 0。它不等于整个项目的入口。`self.commands += 1` 表示在旧值上增加一；它改变的是对象内部状态。

这也是为什么 `propose` 与 `commit` 必须区分：提出候选不应马上消耗执行预算；最终通过发送前检查、承诺一条命令时才更新状态。预演只计算候选，不能假装真的已经移动到了候选点。

### dataclass 是减少重复书写的工具

```python
@dataclass(frozen=True)
class CameraFrame:
    rgb: np.ndarray
    sequence: int
    host_monotonic_s: float
```

`@dataclass` 根据字段自动生成常用初始化等代码。`frozen=True` 禁止简单地重新赋值字段，使一帧记录更接近固定的数据快照。它不能神奇地冻结 NumPy 数组内部每个元素，因此读写处的副本和纪律依然重要。

`@classmethod` 表示方法绑定在类上，常用于 `ReceiveOnlyRobot.connect(...)` 这样的工厂入口：先按配置建立连接，再返回一个可读取的实例。普通 `robot.read()` 则是在这个已存在的连接对象上工作。

## 7. 条件、循环与缩进怎样控制执行

```python
if execute and not site_ready:
    raise ValueError("live execution requires explicit site readiness")
```

`and` 表示两个条件同时成立，`not` 取反，`raise` 抛出异常。意思是“若要求真实执行但没有现场确认，就停止这条路径”。异常不是只打印一条提醒；它会跳出当前正常流程，除非外层明确捕获。

```python
for index in range(3):
    print(index)
```

输出是 0、1、2。`range(3)` 不包含 3。真实执行里的循环上限不等于运动完成条数，因为候选可能被拒绝或小于死区，程序要分别记录“第几轮候选”和“几条目标完成”。

`while` 在条件成立时重复。看真实循环时先找四件事：结束条件、等待间隔、超时、错误出口。没有这些约束的无限重试可能持续用旧数据。本项目对等观察、等 ready、等到位分别设置了明确期限。

列表推导式如 `[image_tensor(f.rgb) for f in selected_frames]` 表示对每帧调用一次转换函数，再把结果放进列表。它的紧凑写法不改变每一步的物理含义。

## 8. with、try/finally 和清理为什么很重要

```python
with SensorSession(cfg) as sensors:
    observation, evidence = sensors.observation()
```

`with` 使用“上下文管理器”：进入代码块前调用对象的 `__enter__`，离开时调用 `__exit__`。`SensorSession` 进入时建立只读状态连接和采集线程；离开时设置停止信号、等待自己启动的线程、关闭自己的连接。即使代码块抛错，也有机会走清理过程。

```python
try:
    run_work()
finally:
    writer.close()
```

`finally` 的意思是只要 Python 仍在执行异常展开，无论正常还是报错，都执行关闭动作。它不保证断电、操作系统强杀或网络故障后的物理设备状态。不能把“有 finally”理解成机器人必然已停稳。

`except ValueError as exc` 捕获某类错误，名字 `exc` 保存该异常。“等待历史不足”可以短时间重试；“控制器时钟倒退”“TCP 不符”则不应无限重试掩盖。看代码时要检查捕获范围，不能只看有无 `except`。

`raise RuntimeError(...) from exc` 把上层解释与原错误连起来，错误链能回答“什么阶段失败”以及“最初原因是什么”。清理过程中若又失败，应记录清理失败，同时保留原来的主要异常，这比只剩一句 `close failed` 更可诊断。

## 9. 线程和进程：同时工作不等于无顺序

“进程”是独立运行的程序，有自己的解释器和内存；桥接程序和推理程序是两个进程。“线程”在同一个进程内共享内存；传感器会话的状态采集、相机帧读取分别在后台线程工作，主线程负责组织和推理。

为什么需要采集线程？假如一次推理耗时约 0.60 s，若主线程推理时完全不采集，结束后就只有推理前的旧样本。后台采集让主线程忙时仍积累新输入，下一轮可以重新观察。

`threading.Lock` 保护共享队列的一段操作，避免一边复制队列，一边另一线程恰好清空或修改。`threading.Event` 是共享停止信号；一个线程发现致命错误，可以设置它，让其他采集循环退出。`join(timeout=...)` 等待线程结束并设置等待上限。

“有线程”不等于“已实现硬实时”。普通操作系统调度、文件读写、Python 执行和 GPU 计算都存在抖动。程序必须检查样本时间，而不是仅相信请求频率。

## 10. 参数、权重、配置三个词怎么区分

这三个词在不同上下文中容易混用。

| 名称 | 在这里具体是什么 | 举例 | 改动意味着什么 |
|---|---|---|---|
| 函数参数 | 调用函数时传入的输入 | `source_age_s=0.8` | 这一次计算使用不同输入 |
| 模型权重 | 训练获得、决定网络计算的数值张量 | EMA 下的视觉网络和 Transformer 权重 | 更换模型，或需要新的训练/微调依据 |
| 模型结构配置 | 决定构造什么网络、维度和采样器 | `horizon=10`、策略类 | 必须与权重结构相容 |
| 部署配置 | 设备、路径、采集时序和环境选项 | topic、机器人 IP、帧路径 | 改变外部接线和运行条件 |
| 运动限制 | 此阶段允许的执行边界 | `max_step_m=0.001` | 改变受限行为；不能随意放宽 |

修改 YAML 中的相机话题不会训练网络；给 checkpoint 改名不会改变权重；把 `n_action_steps` 写成 3 也不代表已有模型突然只预测三步。本工程最多三条真实命令，是执行层的预算，和模型返回八步是不同层。

## 常见问题

**为什么不把全部代码写在一个文件？** 一次看似少跳转，长期却很难判断哪个函数会连接设备、哪里只是数学计算。12 个业务文件对应清晰职责，既能从主流程看全局，也能独立检查数值部分。

**读代码必须从第一行一直读到底吗？** 不需要。先找函数入口和调用，记录输入、输出、可能的副作用；不懂某个辅助函数时再跳过去。对部署代码，“哪里连接、哪里发送、哪里落盘、哪里清理”通常比语法细节更先决定理解。

**`pip install` 和 `import` 是一回事吗？** 安装把包放进环境并登记信息；导入是某个解释器运行时加载模块。装在 Python A，不代表 Python B 能导入。

**没有写控制代码的文件也可能产生副作用吗？** 可以，比如写日志、开线程、读文件。这里把真实控制创建集中到控制边界，并让纯计算函数尽量只返回数字，阅读时仍应查看实际调用。

## 练习与答案

1. `pose[2]` 与 `q_rad[2]` 都是第三项，它们物理意义相同吗？
2. `guard.propose(...)` 返回目标后，为什么不能立即把它记成“运动完成”？
3. `np.zeros((1,2,2))` 有几个数字？每个轴怎样解释？
4. 某机器装了 ROS，运行模型 Python 却提示没有 `rclpy`，应首先做什么？
5. 阅读某个会话类，想知道异常时是否关闭连接，应找哪两个方法？

答案：

1. 不同。`pose[2]` 是 TCP 的 z，单位米；`q_rad[2]` 是第三个关节的角度，单位弧度。相同索引不代表相同物理量。
2. 候选还没有经历最终检查、下发确认和实际反馈，更不代表到位；提出、承诺发送和确认完成分别属于不同阶段。
3. 四个数。对本项目 `agent_pos` 来说，1 是一个窗口，前一个 2 是两帧时间，后一个 2 是 X/Y 两维位置。
4. 先检查当前解释器及命令属于哪个流程。桥接使用系统 ROS Python，模型使用隔离环境；不应首先把 ROS 强装进模型环境。
5. 找 `__enter__` 与 `__exit__`，并继续看资源创建失败时是否也进入清理，以及清理是否只处理自己拥有的资源。
