# Go2-W / UR7e：文献迁移的输入输出审查

> 阶段记录（2026-11-22）：以下论文、分类和建议反映当时已查到的资料，不是最终候选或后续检索边界。可随新文献和核验结果替换、修正。

本文件核对公开接口，不代表已经连接或验证当前实验设备。作者代码中的配置与硬件实测必须分开。

## 1. 两个平台共享什么，不能共享什么

可以共享算法框架、训练程序设计、故障定义原则和评估协议。任务环境、状态估计、动作语义、控制频率和训练权重通常需要分别建立。将数组补齐到相同长度只解决张量形状，不能统一物理意义。

| 对象 | Go2-W | UR7e |
|---|---|---|
| 结构 | 浮动机体，12个腿部关节与4个驱动轮，接触模式随运动变化 | 固定基座，6个串联关节，任务可引入夹爪及物体接触 |
| 常见本体观测 | 关节q/dq，IMU；基座线速度需要估计来源 | 关节q/dq，TCP位姿；反馈力矩和TCP wrench须区分 |
| 常见动作 | 腿部位置目标+轮速，或经核对的低层力矩接口 | 关节位置/速度目标、末端增量或经版本核对的力矩接口 |
| 环境相关观测 | 地形、接触、里程计；原算法需要哪些就必须提供哪些 | 目标/物体状态、视觉、接触；不能默认为已有真值 |
| 严重故障的影响 | 可用支撑和轮腿分工可能发生变化 | 可达空间、姿态/轨迹约束与剩余自由度可能变化 |

## 2. 官方 Go2-W 示例的直接证据

来源：[Unitree SDK2 Go2-W stand example](https://github.com/unitreerobotics/unitree_sdk2/blob/main/example/go2w/go2w_stand_example.cpp)。

- 发布`rt/lowcmd`，订阅`rt/lowstate`；示例循环间隔0.002s。
- 示例对motor_cmd[0:12]发送腿部位置目标，并设置kp/kd。
- 对motor_cmd[12:16]发送轮速目标，kp=0、kd非零。
- 同一条MotorCmd包含q、dq、kp、kd、tau字段，但不是任意组合都等价。
- 示例中的500Hz不是所有论文都必须或能够采用的策略频率，也不保证Python端到端实时性。

来源：[Unitree MuJoCo README](https://github.com/unitreerobotics/unitree_mujoco/blob/main/readme.md)。

官方明确：真实机关闭内置运动控制服务后，SportModeState不可读；仿真保留该消息用于分析。因此仿真能直接读到的位置/速度，不可默认为自定义低层实机控制仍可获取。IMU提供角速度与加速度，不能未经估计直接替代基座线速度。

## 3. UR7e 的力矩接口不是笛卡尔 force mode

来源：[UR ROS2 Force and Torque Control](https://docs.universal-robots.com/Universal_Robots_ROS2_Documentation/rolling/doc/ur_robot_driver/ur_robot_driver/doc/usage/force_torque_control.html)。

- 官方区分关节力矩控制与笛卡尔force mode，TCP的6维wrench不能当6个关节力矩使用。
- forward_effort_controller使用direct_torque；官方文档列出PolyScope5>=5.25.1或X>=10.12.1。
- 文档说明机器人自动补偿重力，目标力矩不应重复包含重力补偿。这意味着论文中的“总关节力矩”需要明确转换为接口期望的命令。
- 实际关节力矩反馈与旧驱动用电流填充effort不同。文档对actual_current_as_torque给出>=5.23.0/10.11.0条件。
- 本轮未读取当前机械臂版本，故不能由文档推断当前设备已满足接口条件。

## 4. 五种“故障”不能混称

| 软件操作 | 对应含义 | 不能推断的含义 |
|---|---|---|
| tau乘以h | 模拟施加力矩权限下降，须位于正确执行层 | 不自动覆盖位置伺服器内部补偿 |
| q_des=q0+h*a | 缩小位置目标相对默认姿态的偏移 | h=0不是断电，PD仍可能把关节拉回q0 |
| 固定q_des且维持PD | 主动保持角度的近似锁定，能力受增益/饱和影响 | 不是无限刚度机械锁死 |
| kp=kd=tau=0 | 在该模型下撤去主动控制 | 不代表轮子锁止，可能自由滑行 |
| 改摩擦或外加力 | 接触环境变化或外力 | 不是执行器能力变化 |

## 5. 各候选都必须补齐的合同

1. 部署输入的每个量如何测量/估计、参考坐标系、单位、时间戳与历史窗口。
2. actor、critic和辅助监督分别使用什么，部署是否剔除故障真值。
3. 策略输出经哪种缩放、基准姿态、PD/IK/OSC或力矩转换后执行。
4. 底层闭环与策略的频率、延迟、动作保持方式。
5. 故障实际注入哪一层，变化发生在reset还是episode中途。
6. 基础控制器是否仍有能力完成任务；无法完成原任务时是否调整目标或切换技能。

由接口可实现性推导出的迁移判断，必须标为工程评估。只有经过对应仿真、实机以及配对评价后，才能称已验证迁移。
